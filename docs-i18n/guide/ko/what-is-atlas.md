# Ontology Atlas란?

Ontology Atlas는 코드베이스가 무엇을 만들고 왜 그렇게 만들었는지를 지도로
남겨 두는 오픈 소스 앱이에요. 이 지도가 바로 온톨로지예요. 이름이 붙은 개념들과
그 개념들을 잇는 관계를 모은 것이고, 관계마다 유형이 정해져 있어요. 지도는
저장소 안에 마크다운 파일로 저장돼요. 사람은 이 파일들을 화면에서 지도로 보고,
Claude Code, Codex, Cursor, Antigravity 같은 코딩 에이전트는 MCP(Model Context
Protocol)로 같은 파일을 읽고 고쳐요.

이 가이드에서는 이게 무슨 뜻인지, 어떻게 시작하는지, 에이전트가 코드를 바꾸는
동안 지도를 어떻게 실제와 맞게 유지하는지 설명해요.

## 어떤 문제를 푸나요

코딩 에이전트는 팀이 읽는 속도보다 빠르게 코드를 바꿔요. 에이전트에게 몇 주쯤
일을 맡기다 보면 간단한 질문에도 답하기 어려워져요. 이 파일은 제품의 어느 부분을
위한 걸까? 이 파일에 무엇이 의존할까? 지난 변경은 어디를 건드렸을까? 에이전트가
자기 작업을 요약해 줘도 그건 에이전트의 주장일 뿐, 따로 확인한 증거가 아니에요.

Atlas는 이런 질문의 답을 코드 옆에 둬요.

- **각 부분이 무엇을 위한 것인지.** "주문" 같은 도메인, "장바구니 체크아웃"
  같은 역량, 그리고 그 역량을 구현하는 요소예요.
- **어디에 있는지.** 개념마다 그 개념을 구현하는 소스 경로를 적어 둘 수 있어요.
- **무엇이 무엇에 의존하는지.** 관계를 파일에 적어 두고, 필요하면 이유도 한 줄
  붙여요.
- **아직 아무도 모르는 것.** 빠진 관계는 "안전"이 아니라 "알 수 없음"으로
  보여요.

## 화면에서 보이는 것

개념 하나는 마크다운 파일 하나예요. 파일 맨 위 몇 줄을 frontmatter라고 하는데,
여기 적힌 `kind`, `title`, 관계로 지도에 점이 하나 찍히고 관계는 선으로 그려져요.
개념을 고르면 그 개념이 의존하는 개념과 그 개념을 쓰는 개념에 불이 들어오고,
패널에 하나하나 이름이 나와요.

지도는 같은 개념을 다섯 가지 보기로 보여 줘요. **평면**, **육각**, **도메인
구조**, **3D**, **뉴런**이에요. 앱에는 같은 폴더를 읽는 다른 화면도 있어요.
**자료실**(원본 문서와 위키 문서), **기획**, **프로젝트**, **하네스**(에이전트가
저장소에서 읽는 파일과 에이전트 작업을 검사하는 장치), **변경**, **Git** 등이에요.

## 누가 쓰나요

- **사람**: 시스템을 이해하고, 개념의 근거를 확인하고, 에이전트가 쓴 내용을
  고치거나 거절할 때 써요. 모든 변경이 마크다운 diff라서 코드처럼 Git에서
  리뷰하면 돼요.
- **코딩 에이전트**: 작업을 시작하기 전에는 그 작업이 건드리는 개념, 코드 경로,
  아직 풀리지 않은 질문을 읽고, 코드를 바꾼 뒤에는 지도 업데이트를 제안할 때
  써요. Atlas MCP 서버는 에이전트가 내 컴퓨터에서 직접 띄우기 때문에 앱을 켜 둘
  필요가 없어요.

## 어디서 돌아가나요

- **macOS 앱**(Apple Silicon): 서명과 공증을 마쳤고, MCP 서버가 앱 안에 들어
  있어요.
- **Windows x64 베타**: 서명되지 않은 베타예요. 폴더와 MCP 기능은 macOS 앱과
  같아요.
- **브라우저**: Chrome이나 Edge에서 디스크의 폴더를 열어 지도를 볼 수 있어요.
  다만 에이전트 등록과 에이전트 대화는 안 되고, API 키도 저장하지 않아요. 폴더
  없이 열면 샘플 지도를 보여 줘요.
- **Linux**: 브라우저를 쓰거나, 소스 체크아웃에서 MCP 서버를 실행하세요
  ([코딩 에이전트 연결하기](/guide/connect-agent)).

계정도, Atlas 서버도, 텔레메트리도 없어요. 폴더는 내 디스크에 평범한
마크다운으로 남아요([데이터·개인정보·안전](/guide/trust)).

## 도움이 될 때와 아닐 때

코드베이스가 너무 커서 머릿속에 다 담기지 않을 때, 에이전트 세션마다 같은 배경
설명을 붙여 넣고 있을 때, 변경을 받아들이기 전에 그 변경이 어디에 영향을 줄지
봐야 할 때 도움이 돼요.

파일 몇 개짜리 프로젝트이거나 코드 구조만 알면 될 때는 얻을 게 별로 없어요.
그런 건 검색과 언어 서버가 더 빨리 답해요. 지도의 선은 누군가 적어 둔 관계일
뿐, 런타임 동작을 증명하지 않아요. 그리고 Atlas는 아직 초기 단계예요. 자체
벤치마크에서도 Atlas를 쓰면 에이전트가 더 나은 답을 낸다는 걸 아직 보여 주지
못했어요
([측정 현황](https://github.com/wlsdks/ontology-atlas/blob/main/docs/benchmark/README.md#current-measurement-status)).
