# 코드가 바뀔 때 지도 최신으로 유지하기

이 장에서는 나와 코딩 에이전트가 계속 코드를 바꾸는 동안 코드베이스 온톨로지를
사실대로 유지하는 법을 다뤄요. 변경 뒤 지도 동기화하기, 안전하게 이름 바꾸기,
중복 개념 피하기, 근거가 낡은 개념 찾기, 바뀐 내용을 검토하고 커밋하기예요.

## 코드를 바꾼 뒤 동기화하기

변경을 마쳤으면 그 변경을 한 에이전트에게 같은 세션에서 지도도 업데이트하라고
요청하세요. 기준은 이래요.

- **동기화**: 도메인, 역량, 요소, 또는 그 사이의 관계를 더하거나 없애거나 이름을
  바꾸는 변경.
- **건너뛰기**: 오타, 주석, 한 줄짜리 스타일 변경, lint 설정, 의미가 바뀌지 않는
  테스트 픽스처.

에이전트는 `get_concept`으로 영향받는 개념을 읽고, `patch_concept`,
`add_concepts`, `add_relations`로 고친 뒤 `validate_vault`를 실행해요. 코드
이름을 바꿨다고 개념 이름까지 바꿀 필요는 없어요. 의미가 바뀐 건지 파일만 바뀐
건지 판단하세요. 파일만 옮겨졌다면 개념의 `path`만 고치면 돼요.

`init`은 Claude Code와 Codex용 시작 스킬 세 개를 설치해요. `atlas-review`는
깨지거나 끊어진 곳을 알려 주고, `atlas-grow`는 다음에 더할 것을 제안하고,
`atlas-absorb`는 메모나 명세에서 개념을 뽑아내요. 셋 다 내가 고르기 전에는
아무것도 쓰지 않아요.

## 낡은 것 찾기

데스크톱 앱에서는 지도가 근거가 낡았을 수 있는 개념을 표시해요. 개념이 인용한
파일이 개념 문서의 마지막 변경보다 나중에 커밋됐다면 그 개념은 **오래됨**이에요.
지도의 각 보기는 오래된 개념을 호박색이나 금색으로 표시하고, 범례에서 그 표시를
설명해요. 폴더의 Git 기록이 필요하기 때문에, 웹사이트나 Git이 없는 폴더에서는
오래됨 표시가 나오지 않아요.

터미널에서는 `health`가 전체 점검을 실행해요. 개념이 인용한 소스 경로가 아직
있는지도 확인해요.

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs health ./atlas
```

`validate`는 마크다운과 참조만 확인하고, 코드는 보지 않아요. 그래서 인용된
파일을 지운 리팩터링은 `validate`를 통과하고도 `health`에서 실패할 수 있어요.

앱의 **변경** 화면은 내가 고른 코드 저장소의 Git 기록을 읽어요. 기간 안에 머지된
내용을 요약하고, 변경마다 그 변경이 건드린 코드 경로를 가진 **영향받는 개념**을
보여 줘요. 바쁜 한 주가 지나면 여기부터 보세요.

커밋하기 전에 `preflight --staged`를 실행하면 스테이징한 파일을 그 파일을
인용하는 개념과 짝지어, 무엇에 영향을 주는지 출력해요. 커밋을 막는 일은 없고,
맞는 개념이 없으면 아무것도 출력하지 않아요.

## 중복 피하기

지도가 망가지는 가장 흔한 경우는 같은 개념을 두 이름으로 두 번 쓰는 거예요.
더하기 전에 확인하세요.

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs similar "order acceptance" ./atlas
```

점수가 높으면 새로 만들지 말고 기존 개념을 고치세요. 에이전트도 같은 보호를
받아요. 제목이 비슷한 개념이 이미 있으면 `add_concept`이 경고를 돌려줘요. 이미
두 개념으로 갈라졌다면 합치세요. 합치기는 모든 참조를 남는 개념으로 옮겨요.

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs merge capabilities/checkout capabilities/order-acceptance --vault ./atlas
```

## 참조를 깨지 않고 이름 바꾸기

개념 이름을 손으로 바꾸면 참조를 놓쳐요. `rename`은 파일을 옮기고, 관계 메모를
포함해 그 개념을 가리키는 모든 개념을 다시 써요.

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs backlinks capabilities/checkout --vault ./atlas
node ~/tools/ontology-atlas/cli/src/index.mjs rename capabilities/checkout capabilities/order-acceptance --vault ./atlas
```

slug는 바뀌지만 개념의 `uid`는 그대로라서, 에이전트와 내보낸 파일도 여전히 그
개념을 알아봐요. `rename`, `merge`, `delete`는 기본으로 미리 보기만 해요.
적용하려면 `--confirm`을 붙이세요. `delete`는 다른 개념이 아직 그 개념을
가리키고 있으면 거부해요. 에이전트는 짝이 되는 MCP 도구 `rename_concept`,
`merge_concepts`, `delete_concept`를 쓰고, 이 도구들도 똑같이 먼저 미리
보여 줘요.

## 지도에서 검토 결과 보기

앱에서 개념을 고르고 **온톨로지 검토**를 여세요. **AI에게 검토 요청**을 누르면
에이전트가 지도를 점검하고, 답이 **검토 결과** 아래에 발견 하나당 한 줄씩
나와요. 지도는 발견이 가리키는 개념을 표시해요. 발견마다 **고치게 하기**,
**나중에 보기**, **기각** 중 하나를 고르세요. 발견은 에이전트의 추측이에요.
검토가 스스로 지도를 고치는 일은 없어요.

## 동시에 편집할 때

나, 동료, 에이전트가 같은 파일을 편집할 수 있어요. Atlas는 조용히 덮어쓰는 일이
없어요.

- MCP 쓰기 도구는 쓰기 전에 디스크에서 파일을 다시 읽고, 에이전트가 읽은 뒤에
  바뀐 파일은 덮어쓰지 않아요. 에이전트는 다시 읽고 재시도해야 해요.
- 앱이 제안된 변경을 방금 바뀐 문서에 적용하려 할 때는 아무것도 쓰지 않고 그
  사실을 알려 줘요.

## 바뀐 내용 커밋하기

온톨로지 폴더는 Git에 있는 평범한 파일이라서, 개념 변경을 코드와 같은 풀
리퀘스트에서 리뷰해요. 앱의 **Git** 화면은 커밋하지 않은 변경을 문서별로 보여
주고 바뀐 줄을 표시해요. 변경 수가 적힌 **커밋** 버튼으로 기록하면 돼요. 여기서
문서 하나를 이전 버전으로 되돌릴 수도 있어요. 터미널에서는 `snapshot`이
온톨로지 폴더만, 바뀐 내용 요약과 함께 커밋해요.

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs snapshot ./atlas --dry-run
```

여기서 쓴 명령은 모두 [CLI 장](/guide/cli)에 정리돼 있어요. 개념과 관계의 모양은
[개념 사이의 관계](/guide/relations)에서 다뤄요.
