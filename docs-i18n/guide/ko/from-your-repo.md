# 내 코드로 첫 지도 만들기

이 장에서는 내 저장소의 첫 코드베이스 온톨로지를 만들어요. 코드가 구현하는
도메인, 역량, 요소, 그리고 그 사이의 관계를 담은 지도예요. Claude Code나 Codex
같은 코딩 에이전트가 MCP로 코드를 읽고 지도를 제안하면, 내가 검토해서 승인한
것만 저장돼요.

## 누가 무엇을 하나요

Atlas가 혼자서 코드의 의미를 알아내 주지는 않아요. 에이전트가 코드를 읽고
근거와 함께 개념과 관계를 제안한 다음, 내가 받아들인 것만 온톨로지 폴더에
마크다운으로 써요. 코드는 읽기만 하고 절대 바꾸지 않아요.

저장소를 스캔한 결과는 근거일 뿐 정답이 아니에요. `analyze_repo_structure`,
`infer_imports`는 아무것도 쓰지 않아요. 폴더 이름이나 import
한 줄은 에이전트가 관찰한 사실일 뿐, 그것만으로 도메인이나 역량이나 의존이
되지는 않아요.

## 앱에서 시작하기

데스크톱 앱에는 시작하는 방법이 세 가지 있어요.

**코드로 온톨로지 만들기.** 시작 카드에서 이 버튼을 누르면 코드 폴더를 고르라고
해요. Atlas는 코드 폴더 안에 만들 `atlas` 폴더의 경로를 보여 주고(이미 있으면 그
폴더를 그대로 써요), 내가 **만들기**를 누를 때까지 기다려요. 그다음 코딩
에이전트와 대화가 열리고, 에이전트가 코드를 읽어 첫 지도를 한 번에 만들어요.
쓰기마다 내 승인을 받아요. **자동 승인**을 켜 두더라도 코드 폴더를 연결하기 전과
지도를 마무리하기 전에는 물어봐요.

**시작하기.** 아직 지도가 없는 폴더를 열면 지도 위 카드가 몇 단계를 안내해요.
코드 폴더라면 첫 단계는 **코드를 읽고 지도 초안 만들기**예요. 앱에 코딩
에이전트가 준비돼 있으면 **에이전트에게 요청**을 눌러 지도 옆 에이전트 대화에
요청을 넣을 수 있고, **보내기**는 내가 직접 눌러요. 에이전트가 준비돼 있지
않으면 **프롬프트 복사**로 같은 요청을 복사해서 터미널에서 쓰는 에이전트에 붙여
넣으면 돼요. 다음 단계에서는 에이전트를 연결하고, 시작 문서를 만들거나 직접
써 나가요.

**로컬 모델로 코드에서 만들기.** macOS 앱에서는 지도 옆 에이전트 패널에 **코드에서
만들기**가 있어요. 먼저 **에이전트** › **모델**에서 Ollama, LM Studio, llama.cpp
같은 로컬 모델을 설정해 두세요. 코드 폴더를 고르면 미리 보기에 코드 폴더, 검토한
변경을 저장할 위치, 모델, 모델 주소, 대상 파일 수가 나와요. **실행**을 누르면
코드 일부를 그 로컬 주소로만 보내요. 결과로 문서 변경안 목록이 나오면, 원하는
것만 골라서 적용하세요.

## 에이전트에게 무엇을 요청할까요

첫 지도는 작게 시작하세요. 이해하고 싶은 동작 하나를 골라 그것만 요청하면
돼요. 예를 들면 이렇게요.

```text
이 저장소의 첫 Atlas 지도를 만들어 줘. [주문 접수처럼 동작 하나]에
집중해 줘.

먼저 connection_info를 호출해서 온톨로지 폴더와 코드 저장소를 확인해 줘.
중복을 만들지 않도록 list_concepts 집계와 이미 있는 개념을 읽어 줘. 시작 파일은
사실이 아니라 예시로 다뤄 줘.

진입점, 조건, 실패 경로를 읽어 줘. 쓰기 전에 작은 묶음을 먼저 제안해 줘.
개념마다 정의 문장, 포함하는 것과 제외하는 것, 구현 파일, 확인하지 못한
점을 적어 줘. 관계마다 왜 성립하는지 적어 줘.

내가 묶음을 고치거나 승인할 수 있게 멈춰 줘. 그다음 내가 승인한 것만
쓰고 validate_vault를 실행해 줘.
```

처음에는 개념 몇 개면 충분해요. 다른 질문에 답해야 할 때가 오면 그때 더하세요.

## 저장 전에 검토하기

좋은 제안은 주장 하나하나를 따로 짚어 반박할 수 있어요. 개념과 관계를 하나씩
확인하세요.

- **이름이 하는 일을 말해요.** 폴더나 라이브러리 이름만으로는 동료에게 전하는
  정보가 너무 적어요.
- **본문에 필요한 부분이 다 있어요.** 정의 문장, `## Includes`, `## Excludes`,
  `## Uncertainty`요. 하나라도 빠지면 `validate_vault`가 경고해요.
- **근거가 파일을 가리켜요.** 역량이나 요소에는 코드를 가리키는 `path`가 있어요.
  경로가 있다고 설명까지 맞는 건 아니니, 직접 읽어 보세요.
- **관계가 성립해요.** 관계의 대상을 없애도 그 역량이 여전히 동작할지 따져
  보세요. import 하나만으로는 의존이라고 할 수 없어요.

실제로 읽어 본 묶음만 승인하고, 그다음 묶음을 요청하세요. 지도의 모양이 자리를
잡으면 에이전트가 `connect_project_source`로 프로젝트를 코드 폴더에 연결하고,
`finalize_project_meaning`으로 결과를 기록할 수 있어요. 쓰기에 성공했다고 그
의미까지 받아들여진 건 아니에요. 커밋하기 전에 diff를 읽으세요.

## CLAUDE.md와 AGENTS.md 활용하기

에이전트 지침 파일에는 코드베이스 설명이 이미 들어 있는 경우가 많아요.
에이전트에게 그중 한 파일에 MCP 도구 `absorb_document`를 실행해 달라고 하세요.
기본으로는 계획만 돌려줘요. `confirm: true`를 주면 정책과 규칙 섹션을 `document`
개념으로 저장하고, 원본 파일을 `.pre-absorb.bak`으로 백업한 다음, 원본을 다른
곳을 가리키는 짧은 파일로 다시 써요. 개념으로 옮기지 않은 섹션은 이 파일에 그대로
남아요. 아키텍처 섹션은 제안만 하고 자동으로 쓰지 않아요.

폴더에 아직 지도에 오르지 않은 마크다운 문서가 있다면, **시작하기** 카드에 **내
문서로 지도 만들기** 단계가 추가돼요.
