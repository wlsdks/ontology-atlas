# 내 코드로 첫 지도 만들기

이 장에서는 내 저장소의 첫 코드베이스 온톨로지를 만들어요. 코드가 구현하는
도메인, 역량, 요소와 그 사이의 관계예요. Claude Code나 Codex 같은 코딩 에이전트가
MCP로 코드를 읽고 지도를 제안해요. 내가 검토하고, 승인한 것만 저장돼요.

## 누가 무엇을 하나요

Atlas가 혼자서 코드를 의미로 바꿔 주지는 않아요. 에이전트가 코드를 읽고, 근거와
함께 개념과 관계를 제안하고, 내가 받아들인 것을 온톨로지 폴더에 마크다운으로
써요. 코드는 읽기만 하고 절대 바꾸지 않아요.

저장소 스캔 결과는 근거이지 정답이 아니에요. `analyze_repo_structure`,
`index_project`, `infer_imports`는 아무것도 쓰지 않아요. 폴더 이름이나 import
한 줄은 에이전트가 관찰한 사실일 뿐이에요. 그것만으로는 아직 도메인도, 역량도,
의존도 아니에요.

## 앱에서 시작하기

데스크톱 앱에는 시작하는 방법이 세 가지 있어요.

**코드로 온톨로지 만들기.** 시작 카드에서 이 버튼을 누르면 코드 폴더를 고르라고
해요. Atlas는 그 코드 폴더 안에 만들 `atlas` 폴더의 경로를 보여 주거나 이미 있는
폴더를 다시 쓰고, 내가 **만들기**를 누를 때까지 기다려요. 그다음 코딩 에이전트와
대화를 열고, 에이전트가 코드를 읽고 한 번에 첫 지도를 써요. 쓰기마다 내 승인을
물어봐요. **자동 승인**을 켜도 에이전트는 코드 폴더를 연결하기 전과 지도를
마무리하기 전에는 물어봐요.

**시작하기.** 아직 지도가 없는 폴더를 열면, 지도 위 카드가 몇 단계를 안내해요.
코드 폴더라면 첫 단계는 **코드를 읽고 지도 초안 만들기**예요. 앱에 코딩
에이전트가 준비돼 있으면 **에이전트에게 요청**이 지도 옆 에이전트 대화에 요청을
넣어 주고, **보내기**는 내가 직접 눌러요. 그렇지 않으면 **프롬프트 복사**가 같은
요청을 복사해 줘서, 터미널에서 쓰는 에이전트에 붙여 넣을 수 있어요. 그다음
단계에서는 에이전트를 연결하고, 시작 문서를 만들거나 직접 시작해요.

**로컬 모델로 코드에서 만들기.** macOS 앱에서는 지도 옆 에이전트 패널에 **코드에서
만들기**가 있어요. **에이전트** › **모델**에서 Ollama, LM Studio, llama.cpp 같은
로컬 모델을 설정해 둬야 해요. 코드 폴더를 고르면 미리 보기가 코드 폴더, 검토한
변경을 저장할 위치, 모델, 모델 주소, 대상 파일 수를 보여 줘요. **실행**은 코드
일부를 그 로컬 주소로만 보내요. 결과는 제안된 문서 변경 목록이에요. 원하는 것만
골라서 적용하세요.

## 터미널에서 시작하기

Atlas 소스 체크아웃이 있다면([CLI와 MCP의 관계](/guide/cli) 참고), 내 저장소에서
이렇게 실행해요.

```bash
cd /path/to/your/repo
node ~/tools/ontology-atlas/cli/src/index.mjs init ./atlas
node ~/tools/ontology-atlas/cli/src/index.mjs bootstrap . --vault ./atlas
```

`init`은 시작 파일 5개가 든 `atlas` 폴더, 에이전트 설정 `.mcp.json`과
`.codex/config.toml`, 그리고 Claude Code와 Codex용 시작 스킬 세 개
(`atlas-review`, `atlas-grow`, `atlas-absorb`)를 만들어요. 시작 파일은 모양을
보여 주는 예시일 뿐, 내 제품을 분석한 결과가 아니에요.

`bootstrap`은 저장소를 스캔하고 검토 계획을 출력해요. 아무것도 쓰지 않고, 아직
승인이 필요하다는 뜻으로 종료 코드 3을 내요. 저장소에서 에이전트를 다시 시작하고
거기서 이어 가세요.

## 에이전트에게 무엇을 요청할까요

첫 지도는 작게 시작하세요. 이해하고 싶은 동작 하나를 골라서 그것만 요청해요.
예를 들면 이렇게요.

```text
이 저장소의 첫 Atlas 지도를 만들어 줘. [주문 접수처럼 동작 하나]에
집중해 줘.

먼저 connection_info를 호출해서 온톨로지 폴더와 코드 저장소를 확인해 줘.
중복을 만들지 않도록 list_kinds와 이미 있는 개념을 읽어 줘. 시작 파일은
사실이 아니라 예시로 다뤄 줘.

진입점, 조건, 실패 경로를 읽어 줘. 쓰기 전에 작은 묶음을 먼저 제안해 줘.
개념마다 정의 문장, 포함하는 것과 제외하는 것, 구현 파일, 확인하지 못한
점을 적어 줘. 관계마다 왜 성립하는지 적어 줘.

내가 묶음을 고치거나 승인할 수 있게 멈춰 줘. 그다음 내가 승인한 것만
쓰고 validate_vault를 실행해 줘.
```

첫 회차에는 개념 몇 개면 충분해요. 다른 질문에 답이 필요해지면 그때 더하세요.

## 저장 전에 검토하기

좋은 제안은 특정 주장 하나에 반대할 수 있게 해 줘요. 개념과 관계를 하나씩
확인하세요.

- **이름이 하는 일을 말해요.** 폴더나 라이브러리 이름만으로는 동료에게 알려
  주는 게 너무 적어요.
- **본문에 필요한 부분이 다 있어요.** 정의 문장, `## Includes`, `## Excludes`,
  `## Uncertainty`요. 하나라도 빠지면 `validate`가 경고해요.
- **근거가 파일을 가리켜요.** 역량이나 요소에는 코드를 가리키는 `path`가 있어요.
  경로가 존재한다고 설명이 맞다는 증거는 아니니, 직접 읽어 보세요.
- **관계가 성립해요.** 대상을 없애도 그 역량이 여전히 동작하는지 물어보세요.
  import 하나만으로는 의존이 증명되지 않아요.

실제로 읽은 묶음만 승인하고, 다음 묶음을 요청하세요. 지도의 모양이 자리를 잡으면,
에이전트가 `connect_project_source`로 프로젝트를 코드 폴더에 연결하고
`finalize_project_meaning`으로 결과를 기록할 수 있어요. 쓰기에 성공했다고 의미를
받아들인 건 아니에요. 커밋하기 전에 diff를 읽으세요.

## CLAUDE.md와 AGENTS.md 활용하기

에이전트 지침 파일에는 이미 코드베이스 설명이 들어 있는 경우가 많아요.
`absorb`는 그 내용을 개념으로 바꿔요.

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs absorb CLAUDE.md AGENTS.md --vault ./atlas
```

기본으로는 계획만 출력해요. `--write`를 붙이면 정책과 규칙 섹션을 `document`
개념으로 저장하고, 원본 파일을 `.pre-absorb.bak`으로 백업한 뒤, 원본을 흡수하지
않은 섹션만 남긴 짧은 안내로 다시 써요. 아키텍처 섹션은 제안만 하고, 절대
자동으로 쓰지 않아요. 에이전트는 MCP 도구 `absorb_document`로 같은 일을 할 수
있어요.

`init`은 내 `CLAUDE.md`나 `AGENTS.md`에 붙여 넣을 짧은 문단도 출력해요. 앞으로의
에이전트 세션에 온톨로지가 있다는 것과 언제 읽어야 하는지를 알려 주는
문단이에요. Atlas가 이 파일들을 대신 고치지는 않아요.

폴더에 아직 지도에 없는 마크다운 문서가 있다면, **시작하기** 카드에 **내 문서로
지도 만들기** 단계가 더해져요.
