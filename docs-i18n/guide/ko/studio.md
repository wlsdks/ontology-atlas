# 개념과 관계 편집하기

이 장에서는 온톨로지를 바꾸는 법을 다뤄요. 지도에서 관계나 개념 글 고치기, 개념 만들기, Claude Code나 Codex 같은 코딩 에이전트가 제안한 변경 검토하기, 그리고 디스크의 파일이 먼저 바뀌었을 때 일어나는 일이에요. 어느 길로 가든 도착점은 같아요. 온톨로지 폴더의 마크다운 파일이에요. 언제든 내 편집기에서 그 파일을 직접 고쳐도 돼요.

따로 있는 편집 화면은 없어요. 예전 Studio 주소(`/ontology/studio`, `/ontology/edit`)는 같은 개념을 고른 채로 지도로 넘겨 줄 뿐이에요.

## 지도에서 관계 고치기

1. 지도에서 개념을 골라요.
2. 개념 패널에서 **관계 편집**을 눌러요. 도메인이라면 **편집**을 열고 **관계 편집**을 골라요.
3. 패널이 같은 자리에서 관계 편집기로 바뀌어요. **관계 종류**를 골라요. **상위 개념**, **의존함**, **포함함**, **관련됨** 중 하나예요.
4. **이어질 개념**을 골라요. 폴더에 이미 문서가 있는 개념만 고를 수 있어서, 관계가 항상 제대로 이어져요.
5. **이 관계의 이유**를 채워요. **의존함**에는 꼭 필요하고, 다른 종류에는 권장해요.
6. 지도가 두 개념 사이에 그리는 점선 미리 보기를 확인해요. 아무것도 쓰기 전에 방향을 보여 줘요.
7. **변경안 보기**를 눌러요. frontmatter에서 바뀔 부분만, 이유까지 포함해 보여 줘요.
8. **확인하고 쓰기**를 누르면 파일에 써요. **다시 고치기**를 누르면 돌아가요.

관계를 지우려면 편집기에서 그 관계를 열고 **이 관계 끊기**를 고르세요. 같은 검토를 거쳐요. 기존 관계의 대상을 바꾸면 예전 대상과 그 이유를 쓰기 한 번으로 바꿔요.

편집기는 한 번에 관계 하나만 다뤄서, 옆에서 지도가 계속 보여요. 각 종류의 뜻과 어떤 frontmatter 키를 쓰는지는 [개념 사이의 관계](/guide/relations)에서 설명해요.

## 개념 글 고치기

개념 패널에서 **자세히 보기**를 눌러 전체 보기를 열고 **본문 편집**을 누르세요. 정의, 개념이 포함하는 것과 제외하는 것, 불확실한 것을 쓰고 **저장**하면 돼요. 다른 언어의 이름(`display_<locale>`)과 다른 frontmatter 필드는 파일에서 직접 고칠 수 있어요.

## 개념 만들기

**개념 추가**는 세 가지 방법으로 열어요. 지도의 빈 곳을 오른쪽 클릭하거나, 빈 지도에서 **개념 만들기**를 누르거나, 도메인에서 **편집**을 열고 **연결된 개념 만들기**를 고르세요.

이름을 화면 언어로 입력하고(두 번째 언어는 선택), **종류**를 고르고, 필요하면 **도메인**도 골라요. **만들기**는 아직 쓰지 않아요. 쓰게 될 slug, `uid`, 이름, 도메인, 작성자를 검토 화면으로 보여 줘요. **확인하고 저장**을 누르면 `.md` 파일이 만들어지고, **다시 고치기**를 누르면 입력한 값을 그대로 둔 채 양식으로 돌아가요. 종류를 정할 때는 [개념 고르기](/guide/what-becomes-a-node)가 도움이 돼요.

## 에이전트에게 변경 제안받기

### 데스크톱 앱에서

개념 패널의 **묻기**를 누르면 지도 옆에 코딩 에이전트와의 대화가 열리고, 그 개념에 대한 질문이 보낼 준비가 된 채로 들어가 있어요. 에이전트는 Atlas MCP 서버를 통해 일해요.

- 온톨로지 읽기(`list_concepts`, `get_concept`, `find_path` 같은 읽기 도구)는 대화를 멈추지 않아요.
- 쓰기(`add_concept`, `add_relation`, `patch_concept` 같은 쓰기 도구)는 모두 **변경안을 확인해 주세요**라는 카드에서 대화를 멈춰요. 카드에는 무엇이 만들어지거나 바뀌는지, 관계라면 그 이유까지 나와요.
- **이번만 허용**은 그 쓰기 하나를 실행해요. **거절**은 아무것도 쓰지 않아요. **거절 후 수정**은 거절하고, 내가 보낼 수 있도록 수정 요청 초안을 써 줘요.
- 쓰기 여러 개를 묶은 경우에는 항목별로 보여 주고, 내 답이 묶음 전체에 적용돼요.
- 쓰기 도구에는 **이 도구를 이번 대화 내내 허용**이 절대 나오지 않아요.

대화의 **작업 방식**을 **자동 승인**으로 바꾸면, 이 폴더 안의 파일 수정과 개념·관계의 생성이나 변경은 묻지 않고 진행돼요. 삭제, 커밋, 셸 명령, 폴더 밖의 일은 여전히 물어봐요. 끌 때까지 이 폴더에서 계속 켜져 있어요. 개인정보 설정의 **허용 목록**에 **대화 자동 승인**으로 나오고, **허용 취소**로 끌 수 있어요.

### 터미널 에이전트에서

Claude Code, Codex, Cursor가 Atlas MCP 서버를 직접 쓸 때는 에이전트 자체의 권한 확인이 무엇을 실행할지 정해요. 이름 바꾸기, 합치기, 삭제, 관계 제거 도구는 기본으로 미리 보기만 하고, `confirm: true`일 때만 써요. 어느 쪽이든 결과는 평범한 파일 변경이에요. 지도는 몇 초 안에 이를 반영하고, 에이전트가 만든 개념에는 `created_by: "agent:<name>"`이 붙고, 변경은 `git diff`에 남아 리뷰하거나 되돌릴 수 있어요.

파일이 써졌다고 그 의미가 받아들여진 건 아니에요. 사람만 결정해야 하는 개념에는 에이전트가 `review_state: human_decides`를 표시할 수 있어요. 문서 보기에서 **직접 결정**을 누르면 그 표시가 지워지고, **확인 완료**를 누르면 사람이 개념을 읽었고 의미가 맞다는 기록이 남아요. 그 뒤에 파일이 바뀌면 개념 패널이 알려 줘요.

## 파일이 먼저 바뀌었을 때

지도가 파일을 쓰기 전에, Atlas는 내가 연 뒤로 파일이 바뀌지 않았는지 확인해요. 내가 연 뒤에 다른 편집기, 동료, 에이전트가 같은 파일을 바꿨다면 아무것도 덮어쓰지 않아요.

- 관계 편집기는 "쓰지 못했어요. 파일이 바뀌었는지 확인하고 다시 시도하세요."라고 알려 줘요.
- 본문 편집은 내가 쓴 글을 지키고, 다른 곳에서 파일이 먼저 바뀌었다고 알려 줘요. 다시 저장하면 내 글로 바꿔요.
- MCP 쓰기 도구는 `expected_mtime`을 받고, 값이 맞지 않으면 덮어쓰지 않고 실패해요.

이 화면들 뒤에는 초안 저장소도 검토 대기열도 없어요. 제안은 내가 확인할 때까지 화면에만 있고, 한 번 쓰이면 마크다운 파일이 유일한 버전이에요.

다음: 코드가 바뀌는 동안 [지도를 최신으로 유지하기](/guide/growing-vault).
