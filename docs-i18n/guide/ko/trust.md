# 데이터·개인정보·안전

이 장에서는 Ontology Atlas를 쓸 때 데이터가 어디에 있는지, 무엇이 언제 컴퓨터
밖으로 나갈 수 있는지, MCP로 연결한 코딩 에이전트는 어디에 해당하는지, 그리고
내려받은 앱이 우리가 빌드한 그 앱인지 확인하는 방법을 설명해요. 여기 적은
내용은 모두 공개된 소스 코드에서 확인할 수 있어요.

## 짧게 정리하면

- 온톨로지는 내가 고른 폴더 안의 평범한 마크다운이에요. Atlas는 이걸 업로드하지
  않아요.
- Atlas에는 백엔드 서버도, 계정도, 텔레메트리도 없어요.
- 앱은 아래에 적은 경로로만 인터넷에 연결하고, 그중 대부분은 내가 무언가를
  눌렀을 때만 동작해요.
- 연결한 코딩 에이전트는 Atlas와 별개의 프로그램이에요. 에이전트는 내
  프롬프트와 자기가 읽은 내용을 자기 모델 제공자에게 보낼 수 있고, Atlas는 그
  트래픽을 보거나 기록할 수 없어요.

## 내 컴퓨터에 남는 것

- **온톨로지 폴더.** 마크다운 파일이 유일한 원본이에요. 앱을 지워도 폴더는
  남고, 어떤 편집기나 스크립트로든 계속 읽을 수 있어요.
- **폴더 안의 `.ontology-atlas/`.** 폴더 설정과 아래에서 설명할 전송 기록이
  들어 있어요. 기본으로 Git에 포함되지 않아요.
- **앱의 검색 색인.** 앱에서는 기본으로 켜져 있어요. 폴더의 파일로 만들어 컴퓨터의
  캐시 폴더에 두고, 어디로도 보내지 않아요. 설정의 **개인정보·데이터** › **이
  컴퓨터에 저장된 것**에서 끄거나 지울 수 있어요.
- **모델 제공자 API 키**(앱 전용). macOS 키체인 같은 운영체제의 자격 증명
  저장소에 보관해요. 폴더에 쓰이거나 웹 페이지에 남는 일은 없어요.
- **작은 환경설정.** 최근 폴더 목록 같은 것들이에요. 앱이 각 폴더의 경로를 자기
  저장소에 보관해서 다음에 다시 열 수 있게 해요. 지워도 폴더에는 아무 영향이 없어요.

Atlas는 내가 고른 폴더만 읽어요. 폴더를 읽을 때도 `.env`, `.git/`처럼 점으로
시작하는 파일과 폴더는 건너뛰어요.

## 컴퓨터 밖으로 나갈 수 있는 것

밖으로 나가는 모든 경로는 앱 설정의 **개인정보·데이터** › **외부 전송**에서 볼
수 있어요. 목록은 이래요.

| 경로 | 언제 | 보내는 곳 | 폴더 내용 포함? |
|---|---|---|---|
| 업데이트 확인 | 자동, 끌 수 있음 | ontologyatlas.com | 아니요 |
| 업데이트 받기 | 내가 누를 때 | github.com | 아니요 |
| 모델 제공자 | 내가 누를 때 | Anthropic, OpenAI, Google API | 내가 보내는 것 |
| 로컬 모델 서버 | 내가 누를 때 | 내가 입력한 주소 | 내가 보내는 것 |
| 외부 모델 검토 | 내가 누를 때 | api.typesafe.ai | 내가 보내는 것 |
| 코딩 에이전트 설치 | 내가 누를 때 | nodejs.org, npm 레지스트리 | 아니요 |
| ACP 어댑터 패키지 | 내가 누를 때 | npm 레지스트리, PyPI | 아니요 |
| GitHub PR 설명 조회 | 내가 누를 때 | api.github.com | 아니요 |
| Git 푸시·풀·페치 | 내가 누를 때 | 내 Git 원격 저장소 | 내가 보내는 것 |
| 폴더에 추가한 MCP 서버 | 에이전트가 쓸 때 | 각 서버의 주소 | 에이전트가 보냄 |
| 코딩 에이전트 | 에이전트가 일할 때 | 에이전트의 제공자 | Atlas는 볼 수 없음 |

Atlas가 직접 하는 모델 호출은 로컬 모델 서버 호출까지 모두 폴더의
`.ontology-atlas/llm-audit.jsonl`에 기록돼요. 자동 업데이트 확인은 설정 ›
**정보** › **업데이트 자동 확인**에서 켜고 꺼요.

웹사이트(ontologyatlas.com)는 자체 파일만 불러오고 내 컴퓨터의 폴더는 열지
않아요. 폴더는 앱에서 읽고, 절대 업로드하지 않아요.

## 코딩 에이전트와 MCP

Atlas MCP 서버는 계속 떠 있는 서비스가 아니에요. 코딩 에이전트가 필요할 때 내
컴퓨터에서 띄우고, 표준 입출력(stdio)으로 통신하고, 세션이 끝나면 함께 멈춰요. 네트워크
포트를 열지 않고, 네트워크 요청도 하지 않아요.

에이전트 자체는 이야기가 달라요. Claude Code, Codex, Cursor 같은 에이전트는 내
프롬프트와 자기가 읽은 파일을 자기 모델 제공자에게 보내요. 그 트래픽은
에이전트가 책임지는 영역이고, 에이전트 자체 설정을 따르며, Atlas 기록에는 남지
않아요.

쓰기를 누가 승인하는지는 에이전트가 어디서 돌아가는지에 따라 달라요.

- **앱의 에이전트 대화에서는** 파일 수정과 Atlas 쓰기마다 내가 **이번만 허용**이나
  **거절**을 누를 때까지 기다려요. 그 폴더에 **자동 승인**을 켜면 기다리지 않아요.
  셸 명령, 삭제, 폴더 밖 경로는 항상 물어봐요. 연결한 코드 폴더의 파일 읽기만은 예외예요.
- **MCP로 연결한 에이전트**가 자기 터미널이나 편집기에서 돌아갈 때는 Atlas가
  아니라 그 도구의 권한 규칙에 따라 써요.

어느 쪽이든 변경은 폴더 안의 마크다운 diff라서, Git에서 리뷰하거나 되돌릴 수
있어요.

## 내려받은 앱 확인하기

- **macOS**: 앱은 Apple Developer ID로 서명했고 Apple의 공증을 받았어요. 릴리스
  과정에서 공개 전에 서명된 디스크 이미지와 설치된 앱을 검증하고, 검증에 실패한
  빌드는 릴리스하지 않아요. 앱 안 업데이트도 서명돼 있어요.
- **Windows x64 베타**: 설치 프로그램에 서명이 없어서 SmartScreen이 '알 수 없는
  게시자' 경고를 띄울 수 있고, 회사에서 관리하는 컴퓨터에서는 막힐 수도 있어요.
  릴리스 전에 빌드를 Microsoft Defender로 검사하고, 사일런트 설치와 실행까지
  시험해 봐요.
- **Linux와 Intel Mac**: 앱이 없어요. 샘플 지도를 보거나, 소스에서 MCP 서버를
  실행하세요([코딩 에이전트 연결하기](/guide/connect-agent)).

[릴리스 페이지](https://github.com/wlsdks/ontology-atlas/releases)의 설치 파일(`.dmg`, `.exe`)과
MCP 번들(`.mcpb`) 옆에는 `.sha256` 파일이 있어요. 내려받은 파일의 체크섬과 비교해 보세요.

macOS에서는 이렇게 확인해요.

```sh
shasum -a 256 <file>
```

Windows PowerShell에서는 이렇게 해요.

```powershell
Get-FileHash <file> -Algorithm SHA256
```
