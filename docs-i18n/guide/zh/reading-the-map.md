# 读懂地图

地图是 Atlas 根据你本体文件夹中的 Markdown 文件绘制出的知识图谱。本章说明每种标记的含义、指向一个概念时哪些内容会亮起、概念面板显示什么，以及 Atlas 怎样标出“写下之后代码又变了”的概念。地图上的一切都来自这些文件。

## 静止时的地图

默认视图是 **平面**，一张按领域分组的力导向图。视图选择器还提供 **六边形**、**3D** 和 **神经**；本章介绍的是 **平面**。

- **项目** 是位于中心的一个圆盘；在没有选中任何内容时，它是唯一带颜色的标记。
- **领域** 是一片片柔和的光晕，每个领域有一个圆盘、一个加粗的大号名称，以及一行统计成员数量的说明，例如“12 项能力 · 30 个元素”。
- **能力** 是环绕在所属领域周围的较小圆盘。元素越多，圆盘就稍大一些。
- **元素** 是环绕在所属能力周围的小点。
- 不属于任何领域的概念聚在一起，下方有一行说明，例如“3 个概念不属于任何领域”。
- 领域之间淡淡的弧线表示两个领域的概念之间有多少条 `depends_on` 关系。静止时只画出关系最多的几对。

颜色只用在需要注意的地方：你正指向哪个领域，一条关系朝哪个方向。布局只取决于文件夹的内容和窗口大小，所以同一个文件夹每次都会画出同样的图，你可以记住每样东西在哪里。

## 名称与缩放

名称从不互相重叠，放不下的名称就不显示。领域名称总是会画出来，能力名称在空间允许时陆续加上（连接最多的优先），元素名称则要放大到各个小点彼此分开后才会出现。选中的概念总会显示名称。

看不到名称，并不代表没有这个概念。可以放大、指向它所属的领域，或者用 `⌘K` 搜索。

## 指向与选中

把指针停在一个概念上，稍等片刻，地图就会点亮与它相连的内容，并让其余部分暗下去。快速划过则不会点亮任何东西。

- **领域**：点亮它的成员，以及它所依赖的领域和依赖它的领域。
- **能力**：点亮它所属的领域和它的元素，以及与它相连的每个概念：它依赖的、依赖它的、与它相关的，还有它所归属的上位概念。
- **元素**：点亮它所属的能力、该能力所属的领域，以及它自身每条关系另一端的概念。

关系类型要看每条线的形状，而不只是颜色：

| 线条 | 含义 |
|---|---|
| 实心渐细线，在选中的概念一端较宽，指向另一个概念 | **依赖**：选中的概念需要它 |
| 同样的渐细线，暖色，在另一个概念一端较宽 | **被依赖**：另一个概念需要选中的概念 |
| 点状细线 | **相关**：双方互不需要 |
| 指向更上位概念的双细线 | **上位概念**（`is_a`） |

底部的图例会标出屏幕上出现的线条种类，按 `?` 可以列出所有快捷键。

点击即可选中。镜头会把选中的概念和点亮的相邻概念收进画面，同时有一小束光沿每条线跑一次，从被需要的一方流向需要它的一方。开启“减少动态效果”后，光不会流动。按 `Esc` 取消选中并让镜头复位，方向键可以在概念之间逐个移动。

## 概念面板

选中一个概念后，地图右侧边缘会打开一个紧凑的面板：

- **标题栏**：类型、直接所属（能力所属的领域、元素所属的能力），以及最近一次改动，例如“3 天前改动”。
- **定义**：只显示三行，点击可以阅读全文。
- **需要人来处理的一行**，只在符合条件时出现：文档标记为需要由人来决定、有人确认之后文档又改过，或者某些关系没有写理由。
- **依赖** 和 **被依赖**：地图上画出的关系，每个概念一行。**无理由** 标出没有记录理由的关系。指向某一行即可阅读它的理由。
- 统计其余关系的一行，例如 **其他关系 2 · 实现元素 1**。

面板底部显示 slug 和以下操作：

- **询问**（仅限桌面应用）：打开智能体对话，并附上一个关于该概念的问题，由你按下发送。
- **编辑关系**：在领域上，它位于 **编辑** 菜单中，菜单里还有 **新建关联概念**。
- **更多操作**。
- **详情**：打开一个居中的对话框，里面有完整正文、所有关系、代码位置，以及一段可以复制给智能体的提示词。

编辑方法见 [编辑概念和关系](/guide/studio)。

右键点击一个概念，可以选择 **文档**、**编辑关系**、**复制提示词**、**路径** 和 **详情**。选择 **路径** 之后，再选中第二个概念，地图就会一跳一跳地点亮两者之间的最短路径。如果一个概念包含其他概念，**更多操作** › **只看内部** 会把地图收窄到它的内部；**完整地图** 则回到整张地图。

地址栏会记下选中的概念、视图、路径和收窄后的范围，所以用同一个链接就能重新打开同样的画面。

## 过时与未知的依据

在桌面应用中，如果本体文件夹位于某个 Git 仓库内，Atlas 会把每个概念的文档与它在 `path` 中引用的代码文件做比较。

- **过时**：文档写好之后，它引用的文件又改过。圆盘上会多一个琥珀色的小点，领域说明里也会计入，例如“2 项过时”。
- **未知**：概念没有引用任何文件，或者 Atlas 无法判断文件是什么时候改的。圆盘显示为虚线空心轮廓。
- 如果什么都无法检查，例如没有 Git 历史的文件夹，项目下方会显示一行 **依据未检查**。

这些标记不是评分。它们告诉你，在相信文字之前，应该先去读哪里的代码。

## 审阅结果

**更多操作** › **本体审阅** 会打开一个面板，里面有 **职责与连接**、**审阅结果** 和 **对话** 三部分。在连接了智能体的桌面应用中，**请 AI 审阅** 会让智能体质疑范围内概念的含义。它提出的问题保存在本体文件夹的 `.ontology-atlas/analyses` 下，并列在 **审阅结果** 中。

**让它修正** 把一个问题交给智能体；它提出的任何文件改动仍要等你批准。**稍后再看** 和 **忽略** 会记录你的判断。正如面板上所写：“这些是 AI 的推测，是否成立由你判断。”
