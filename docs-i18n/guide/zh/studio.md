# 编辑概念和关系

本章介绍如何修改本体：在地图上编辑一条关系或一个概念的文字、创建概念、让 Claude Code 或 Codex 等编码智能体提出改动供你审查，以及磁盘上的文件已在别处改过时会怎样。无论走哪条路，改的都是同一处：你本体文件夹中的 Markdown 文件。你也随时可以在自己的编辑器里直接编辑这些文件。

没有单独的编辑器界面。旧的 Studio 地址（`/ontology/studio` 和 `/ontology/edit`）只会重定向到地图，并选中同一个概念。

## 在地图上编辑关系

1. 在地图上选中一个概念。
2. 在概念面板中按下 **编辑关系**。如果是领域，打开 **编辑** 并选择 **编辑关系**。
3. 面板会在原位变成关系编辑器。选择一个 **关系类型**：**上位概念**、**依赖**、**包含** 或 **相关**。
4. 选择 **关联的概念**。只能选择文件夹中已经有文档的概念，因此这条关系总能解析。
5. 填写 **为什么存在这条关系**。对 **依赖** 来说这是必填项，对其他类型则建议填写。
6. 看一下地图在两个概念之间画出的虚线预览：写入任何内容之前，它就会显示关系的方向。
7. 按下 **复核改动**。你只会看到 frontmatter 中将要变化的部分，包括理由。
8. 按下 **确认并写入** 写入文件，或按 **继续编辑** 返回。

要删除一条关系，在编辑器中打开它并选择 **移除这条关系**；它会经过同样的复核。修改已有关系的目标时，旧目标和它的理由会在同一次写入中一起替换。

编辑器一次只处理一条关系，所以地图始终显示在它旁边。每种类型的含义以及它写入哪个 frontmatter 键，见 [关系](/guide/relations)。

## 编辑概念的文字

在概念面板中按下 **详情** 打开完整视图，然后按 **编辑正文**。写下定义、这个概念包含和不包含什么，以及哪些内容尚不确定，然后按 **保存**。其他语言的名称（`display_<locale>`）和其他 frontmatter 字段可以直接在文件中编辑。

## 创建概念

有三种方式打开 **添加概念**：右键点击地图上的空白处；在空地图上按下 **创建概念**；或者在领域上打开 **编辑** 并选择 **新建关联概念**。

用界面语言输入名称（第二种语言可选），选择 **类型**，并可选择一个 **领域**。按下 **创建** 后还不会写入，而是先显示复核内容，列出将要写入的 slug、`uid`、名称、领域和作者。**确认并保存** 会创建 `.md` 文件；**继续编辑** 则返回表单，你填写的内容保持不变。决定类型时可以参考 [选择概念](/guide/what-becomes-a-node)。

## 让智能体提出改动

### 在桌面应用中

概念面板中的 **询问** 会在地图旁边打开和编码智能体的对话，并预先填好一个关于该概念的问题，可以直接发送。智能体通过 Atlas MCP 服务器工作。

- 读取本体（`list_concepts`、`get_concept`、`find_path` 及其他读取工具）不会打断对话。
- 每一次写入（`add_concept`、`add_relation`、`patch_concept` 及其他写入工具）都会让对话暂停在一张标题为 **审阅提议的更改** 的卡片上。卡片显示将要创建或修改的内容；如果是关系，还会显示理由。
- **仅允许一次** 执行这一次写入。**拒绝** 不写入任何内容。**拒绝并修改** 会拒绝这次写入，并起草一条修正请求，供你发送。
- 一批写入会逐项显示，你的回答适用于整批。
- 写入工具从不提供 **本次对话中一直允许此工具** 选项。

如果你把对话的 **模式** 设为 **自动批准**，此文件夹中的文件编辑，以及概念和关系的新增或修改，都会直接执行而不再询问。删除、提交、Shell 命令以及对文件夹以外的任何修改仍会询问。这个设置会对该文件夹一直生效，直到你关闭它。隐私设置中的 **允许列表** 会把它显示为 **对话自动批准**，并提供 **撤销**。

### 从终端里的智能体

当 Claude Code、Codex 或 Cursor 直接使用 Atlas MCP 服务器时，由智能体自己的权限提示决定什么可以执行。重命名、合并、删除或移除关系的工具默认只做预览，只有带上 `confirm: true` 时才会写入。无论哪种方式，结果都是普通的文件改动：地图会在几秒钟内反映这些改动，智能体创建的概念会带有 `created_by: "agent:<name>"`，改动也会出现在 `git diff` 中，供你审查或撤销。

写入成功不等于含义被接受。当某个概念只应由人来定夺时，智能体可以把它标记为 `review_state: human_decides`。在文档视图中，**标记为已决定** 会清除这个标记，**标记为已确认** 则记录已有人读过这个概念并确认含义正确。如果此后文件又发生了变化，概念面板会提示你。

## 文件已在别处改过时

地图写入文件之前，Atlas 会检查该文件在你打开之后有没有变过。如果在你打开之后，另一个编辑器、同事或智能体改了同一个文件，Atlas 不会覆盖任何内容：

- 关系编辑器会提示：“无法写入。请检查文件是否已变化，然后重试。”
- 编辑正文时，你写的文字会保留下来，同时提示你文件已经在别处改过；再保存一次，就会用你的文字替换它。
- MCP 写入工具接受 `expected_mtime`，不一致时会直接失败，而不是覆盖。

这些界面背后没有草稿存储，也没有审阅队列。提议在你确认之前只存在于屏幕上；一旦写入，Markdown 文件就是唯一的版本。
