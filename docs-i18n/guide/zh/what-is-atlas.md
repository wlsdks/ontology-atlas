# 什么是 Ontology Atlas？

Ontology Atlas 是一款开源应用，用来维护一张地图，记录你的代码库构建了什么、为什么这样构建。这张地图就是一个本体（ontology）：一组有名字的概念，加上概念之间带类型的关系，以 Markdown 文件的形式保存在你的仓库里。你在屏幕上把它当作地图来阅读，Claude Code、Codex、Cursor、Antigravity 等编码智能体则通过 MCP 读取和更新同一批文件。

本指南介绍这意味着什么、如何开始，以及在智能体不断修改代码的同时，如何让地图始终保持真实。

## 它解决什么问题

编码智能体改代码的速度，比团队读代码的速度快得多。把工作交给智能体几周之后，一些简单的问题就很难回答了：这个文件服务于产品的哪一部分？谁依赖它？上一次改动碰到了什么？智能体对自己工作的总结只是一种说法，并不是独立的证据。

Atlas 把这些答案放在代码旁边：

- **每个部分用来做什么。** 例如“订单”这样的领域、“结算购物车”这样的能力，以及实现它们的具体元素。
- **它在哪里。** 一个概念可以写明实现它的源码路径。
- **谁依赖谁。** 关系被明确写下来；在需要的地方，每条关系都附有一句理由。
- **哪些还没人知道。** 缺失的关系显示为“未知”，绝不会显示为“安全”。

## 你会看到什么

一个概念就是一个 Markdown 文件。文件顶部那几行 frontmatter（它的 `kind`、`title` 和关系）会变成地图上的一个点，关系则变成连线。选中一个概念，地图会点亮它所依赖的概念和使用它的概念，并在面板中列出每一个的名字。

同一批概念在地图上有多种视图：**平面**、**六边形**、**领域结构**、**3D** 和 **神经**。应用里还有其他读取同一文件夹的界面，包括 **资料库**（源文档和 Wiki 页面）、**规划**、**项目**、**Harness**（智能体会读取你仓库中的哪些内容，以及由什么来检查它的工作）、**变更** 和 **Git**。

## 谁在用它

- **你**：用来理解系统、核对一个概念背后的依据，并修正或驳回智能体写下的内容。每一处改动都是一份 Markdown diff，你可以像审查代码一样在 Git 里审查它。
- **你的编码智能体**：在开始任务之前，读取该任务涉及的概念、代码路径和未决问题；修改代码之后，再提出相应的更新。Atlas MCP 服务器由智能体在你的电脑上启动，你不需要一直开着应用。

## 在哪里运行

- **macOS 应用**（Apple Silicon）：已签名并经过公证，MCP 服务器内置在应用中。
- **Windows x64 测试版**：未签名，文件夹和 MCP 功能与 macOS 版相同。
- **浏览器**：Chrome 或 Edge 可以打开你磁盘上的文件夹并显示地图。浏览器无法注册智能体，没有智能体对话，也不保存 API 密钥。没有打开文件夹时，它会显示一张示例地图。
- **Linux**：使用浏览器版，或者从源码检出目录运行 CLI 和 MCP 服务器（[CLI](/guide/cli)）。

没有账号，没有 Atlas 服务器，也没有遥测。你的文件夹始终是你磁盘上的普通 Markdown（[数据、隐私与安全](/guide/trust)）。

## 什么时候有用，什么时候用处不大

当代码库大到装不进脑子里、你每次开智能体会话都要贴一遍同样的背景，或者你需要在接受一次改动之前看清它可能影响什么时，它会很有帮助。

对只有几个文件的项目，或者你只需要了解代码结构时，它的帮助不大：搜索和语言服务器能更快给出答案。地图上的一条线是声明出来的关系，并不能证明运行时的行为。而且 Atlas 还处于早期阶段：它自己的基准测试尚未证明智能体借助它能给出更好的回答（[测量情况](https://github.com/wlsdks/ontology-atlas/blob/main/docs/benchmark/README.md#current-measurement-status)）。
