# コードの変更に合わせてマップを最新に保つ

この章では、あなたとコーディングエージェントがコードを変え続ける中で、コードベースのオントロジーを正しく保つ方法を説明します。変更後のマップの同期、安全な名前の変更、重複した概念の防止、根拠が古くなった概念の発見、そして変更内容のレビューとコミットです。

## コードを変更したら同期する

コードを変更したら、その変更を行ったエージェントに、同じセッションの中でマップも更新するよう頼みます。判断の基準は次のとおりです。

- **同期する**: ドメイン、ケイパビリティ、要素、またはそれらの間の関係を追加、削除、名前変更したとき。
- **スキップする**: 誤字、コメント、1行のスタイル変更、lintの設定、意味を変えないテストフィクスチャ。

エージェントは、影響を受ける概念を`get_concept`で読み、`patch_concept`、`add_concepts`、`add_relations`で変更し、`validate_vault`を実行します。コードの名前を変えても、概念の名前まで変える必要はありません。意味が変わったのか、ファイルが変わっただけなのかを判断してください。ファイルが移動しただけなら、概念の`path`を更新します。

Atlasが作るオントロジーフォルダには、Claude CodeとCodex向けの3つのスタータースキルが入っています。`atlas-review`は壊れているものやつながっていないものを報告し、`atlas-grow`は次に追加するものを提案し、`atlas-absorb`はメモや仕様書から概念を抜き出します。どれも、あなたが選ぶまでは書き込みません。

## 古くなったものを見つける

デスクトップアプリでは、根拠が古くなっているかもしれない概念がマップ上で示されます。概念が**古い**とされるのは、その概念が参照しているファイルが、その概念自身の文書が最後に変更されたあとにコミットされた場合です。どのマップビューでも、古い概念は琥珀色または金色で示され、凡例にその印の名前が表示されます。これにはフォルダのGit履歴が必要なので、Webサイトや、Gitのないフォルダでは古い印は表示されません。

エージェントの`validate_vault`はMarkdownとその参照をチェックし、`pathDrift`の一覧で、概念が参照しているのにもう存在しないソースパスを示します。1つずつ`patch_concept`で直します。

アプリの**変更**画面は、あなたが選んだコードリポジトリのGit履歴を読みます。ある期間にマージされた内容を要約し、変更ごとに、そのコードパスに触れた**影響を受ける概念**を一覧表示します。忙しい1週間のあとは、まずここを見ましょう。

## 重複を避ける

マップが崩れていくいちばんよくある原因は、同じ概念が別々の名前で2回書かれることです。エージェントは概念を追加する前に、`query_ontology`の`similar_nodes`で、提案したタイトルと重なる概念がないかを確かめられます。重なる概念があれば、新しく作らずに既存の概念を更新します。似たタイトルの概念がすでにあると、`add_concept`も警告を返します。すでに2つの概念に分かれてしまっている場合は、`merge_concepts`でマージします。マージすると、すべての参照が残す側の概念に移ります。

## 参照を壊さずに名前を変える

概念の名前を手で変えると、参照を取りこぼします。エージェントはまず`find_backlinks`で参照を確かめ、次に`rename_concept`がファイルを移動して、その概念を指しているすべての概念を、関係のメモも含めて書き換えます。

スラッグは変わりますが、概念の`uid`は変わらないので、エージェントやエクスポートは引き続き同じ概念として認識します。`rename_concept`、`merge_concepts`、`delete_concept`は最初にプレビューし、確認を受けてから適用します。`delete_concept`は、ほかの概念がまだ削除対象を指している間は実行を拒否します。

## マップ上で指摘をレビューする

アプリで概念を選び、**オントロジーのレビュー**（**その他の操作**の中）を開きます。**AIにレビューを依頼**を押すとエージェントがマップをチェックし、その答えが**レビュー結果**の下に、指摘1件につき1行で表示されます。マップは、指摘の対象となっている概念に印を付けます。指摘ごとに、**修正を依頼**、**後で見る**、**却下**のいずれかを選びます。指摘はエージェントの推測にすぎません。レビューの機能がマップを勝手に編集することはありません。

## 同時に編集されたとき

あなたとチームメイトとエージェントが、同じファイルを編集することがあります。Atlasが書き込むときに、ほかの変更を黙って上書きすることはありません。

- エージェントが読んだときの`expected_mtime`を渡した場合、MCPの書き込みツールはその後に変更されたファイルの上書きを拒否します。エージェントは読み直してから再試行する必要があります。渡さなければ、そのまま書き込まれます。
- アプリが提案された変更を、直前に変更された文書に適用しようとした場合は、何も書き込まず、そのことを伝えます。

## 変更をコミットする

オントロジーフォルダはGitで管理される普通のファイルなので、概念の変更はコードと同じプルリクエストでレビューできます。アプリの**Git**画面には未コミットの変更が文書ごとに一覧表示され、変更された行に印が付きます。変更の数が表示された**コミット**ボタンを押すと、それらが記録されます。同じ画面で、1つの文書を以前のバージョンに戻すこともできます。エージェントの`git_snapshot`はオントロジーフォルダだけをコミットし、デフォルトでは何をコミットするかをプレビューするだけです。

概念と関係の形については[概念どうしの関係](/guide/relations)で説明しています。
