# MCPでコーディングエージェントを接続

この章では、Claude Code、Codex、Cursor、Antigravityなどのコーディングエージェントを、MCP（Model Context Protocol）を通じてオントロジーフォルダに接続します。接続すると、エージェントはコードを変更する前にコードベースのオントロジーを読めるようになり、マップに表示されるのと同じMarkdownファイルに新しい概念や関係を記録できるようになります。

## エージェントはフォルダに接続する

エージェントは、セッションで必要になったときに手元のコンピュータでAtlasのMCPサーバを起動し、セッションが終わるとサーバは停止します。サーバは、オントロジーフォルダ内のMarkdownファイルを読み書きします。ポートを開くことも、自分からネットワークリクエストを送ることもありません。エージェント自体は、これまでどおり自身のモデルプロバイダと通信します。

このため、次のようになります。

- Atlasのアプリを閉じていても、エージェントはフォルダを読めます。
- エージェントが書いたものはマップに表示されます。マップは同じファイルを読んでいるからです。
- 接続はフォルダ内の設定ファイルなので、ほかの変更と同じように`git diff`に表示されます。

## アプリから接続する

1. アプリでオントロジーフォルダを開きます。
2. サイドバーで**エージェント**を選び、**MCP**タブを開きます。
3. **このフォルダをエージェントに接続**の下で、使うツールの行の**接続**を押します。

| ツール | ボタンが書き込むファイル |
|---|---|
| Claude Code | `.mcp.json` |
| Codex | `.codex/config.toml` |
| Cursor | `.cursor/mcp.json` |
| Antigravity | `.agents/mcp_config.json` |

各ボタンが書き込むのはそのツールのファイルだけで、しかもファイルがまだないときに限ります。既存のファイルをアプリが上書きすることはありません。設定はアプリに同梱されたMCPサーバを指し、フォルダの絶対パスを含むので、Node.jsもAtlasのソースコードのコピーも必要ありません。

`.mcp.json`や`.codex/config.toml`がすでにあっても、それがAtlasの接続ファイルでない場合、その行には警告が表示され、修正した設定をコピーできます。内容を読んで、自分でファイルにマージしてください。

そのあと、エージェントを終了してもう一度開きます。エージェントがMCPの設定を読むのは、セッションの開始時だけです。

ブラウザでは、Atlasは設定ファイルを保存できません。Webページはフォルダの絶対パスを知らないからです。代わりにMCPタブがそのパスと、Atlasのソースをチェックアウトした場所のパスを尋ね、コピーして保存するための設定テキストを組み立てます。何も書き込まず、何も送信しません。デスクトップアプリのほうが近道です。[こちらからダウンロード](https://ontologyatlas.com/ja/download/)できます。

## ソースのチェックアウトから接続する

Linuxなどでアプリを使わない場合は、リポジトリのクローンからサーバを実行します。Git、Node.js 24、pnpmが必要です。

```bash
git clone https://github.com/wlsdks/ontology-atlas ~/tools/ontology-atlas
cd ~/tools/ontology-atlas && pnpm install
pnpm --dir mcp install --frozen-lockfile
```

次に、エージェントにサーバを登録します。Claude Codeは自分のリポジトリのルートにある`.mcp.json`から読み込み、stdioでMCPを扱えるほかのクライアントでも、同じ3つのフィールドでサーバを登録できます。

```json
{
  "mcpServers": {
    "ontology-atlas": {
      "command": "node",
      "args": ["/absolute/path/to/ontology-atlas/mcp/src/index.js"],
      "env": { "OATLAS_VAULT": "/absolute/path/to/your/atlas" }
    }
  }
}
```

絶対パスを使ってください。設定ファイルでは`~`は展開されません。Codexでは、サーバをグローバルに登録することもできます。

```bash
codex mcp add ontology-atlas --env OATLAS_VAULT=/absolute/path/to/your/atlas -- node /absolute/path/to/ontology-atlas/mcp/src/index.js
```

Codexがプロジェクトの`.codex/config.toml`を読むのは、そのフォルダを信頼したあとだけです。信頼したあとは、`codex mcp list`に`ontology-atlas`が表示されるはずです。

クライアントに読み取りだけを許可するには、`env`に`"OATLAS_READ_ONLY": "1"`を追加します。するとサーバは読み取り用のツールだけを公開し、すべての書き込みを拒否します。

## 接続を確かめる

ディスク上に設定ファイルがあっても、エージェントがそれを読み込んだ証明にはなりません。再起動したあと、エージェントにこう頼んでください。

> connection_infoを呼び出して、どのオントロジーフォルダとどのコードリポジトリに接続しているか教えて。

`connection_info`は、サーバが解決したフォルダとリポジトリのパス、そして提供しているツールを返します。フォルダが想定と違っていたら、エージェントに書き込ませる前に設定を直してください。

アプリでは、見出しの横にある**接続を確認**に、再起動の手順と各ツールのファイルの状態が表示されます。

## エージェントが読み書きできるもの

正確な一覧は、サーバ自身のツール一覧です。ツールはいくつかのグループに分かれます。

- **作業前に読む:** `get_concepts`は概念を隣接する概念とともに返し、`find_backlinks`はある概念を指しているものを示します。`query_ontology`は、2つの概念がどうつながっているか（`path`）を示し、ワークスペースの概要や変更の影響といった問いに答えます。
- **コードを読む:** `analyze_repo_structure`と`infer_imports`は、何も書き込まずにリポジトリを調べます。
- **書き込む:** `add_concepts`、`add_relations`、`patch_concept`、`rename_concept`、`merge_concepts`、`delete_concept`などです。名前の変更、マージ、削除、関係の削除は、まず変更内容をプレビューし、確認付きでもう一度呼び出されたときにだけ書き込みます。
- **チェックする:** `validate_vault`と`compile_ontology`は、壊れた参照や欠けている部分を報告します。

書き込みはすべてMarkdownの変更になります。エージェントが読み込んだ時点の`expected_mtime`を渡すと、その後ディスク上で変更されたファイルへの上書きを書き込みツールが拒否します。渡さなければ、そのまま書き込まれます。

## あなたが決めること

- **書き込みに承認が必要かどうか。** 外部のエージェントでは、そのエージェント自身の権限設定が決めます。アプリに組み込まれたエージェントとの会話では、**自動承認**をオンにしない限り、書き込みのたびに先に確認を求めます。
- **意味が正しいかどうか。** 書き込みが成功しても、その意味が受け入れられたことにはなりません。コミットする前に差分を読んでください。
- **エージェントに何をさせるか。** マップでは、概念のアクションにある**プロンプトをコピー**で、その概念の文脈をエージェント向けにコピーできます。

同じページの**エージェント**タブには、このコンピュータで見つかったコーディングツールが一覧表示され、それぞれ実行できるかどうかをチェックします。アプリでは、同じMCPサーバを使って、そのうちの1つとの会話をマップの隣で開くこともできます。

次は、[コードから最初のマップを作る](/guide/from-your-repo)に進みましょう。何がコンピュータの外に出るかについては、[データ、プライバシー、安全性](/guide/trust)を参照してください。
