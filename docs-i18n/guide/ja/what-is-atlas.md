# Ontology Atlasとは

Ontology Atlasは、コードベースが何を作っているのか、なぜそうなっているのかをマップとして残しておくオープンソースのアプリです。このマップはオントロジー、つまり名前の付いた概念と、それらを結ぶ型付きの関係の集まりで、リポジトリ内にMarkdownファイルとして保存されます。人は画面上のマップとして読み、Claude Code、Codex、Cursor、Antigravityなどのコーディングエージェントは、同じファイルをMCP経由で読み書きします。

このガイドでは、その意味と始め方、そしてエージェントがコードを変えていく中でマップを正しく保つ方法を説明します。

## 解決する問題

コーディングエージェントは、チームが読むよりも速くコードを変更します。作業を任せて数週間もたつと、単純な問いにも答えにくくなります。このファイルはプロダクトのどの部分のためにあるのか、何がこれに依存しているのか、直前の変更はどこに触れたのか。エージェントが自分の作業をまとめた要約は、あくまでエージェント自身の主張であり、独立した根拠にはなりません。

Atlasはその答えをコードのそばに置きます。

- **各部分が何のためにあるか。** 「注文」のようなドメイン、「カートの購入を確定する」のようなケイパビリティ、そしてそれを実現する実装の要素です。
- **どこにあるか。** 概念には、それを実装しているソースパスを書けます。
- **何が何に依存しているか。** 関係を書き留め、必要なら理由を1行で添えます。
- **まだ誰も知らないこと。** 書かれていない関係は「不明」と表示し、「安全」とは表示しません。

## 画面で見えるもの

概念1つがMarkdownファイル1つです。ファイル先頭の数行にあるフロントマター（`kind`、`title`、関係などを書く情報ブロック）がマップ上の点になり、そこに書いた関係が線になります。概念を選ぶと、その概念が依存している概念と、その概念を使っている概念が明るくなり、パネルにそれぞれの名前が表示されます。

マップには、同じ概念を表示する複数のビューがあります。**フラット**、**ヘックス**、**3D**、**神経網**です。アプリには同じフォルダを読む別の画面もあり、**資料室**（ソース文書とWikiページ）、**企画**、**プロジェクト**、**ハーネス**（エージェントがリポジトリで読むものと、その作業をチェックするもの）、**変更**、**Git**などがあります。

## 誰が使うのか

- **あなた**は、システムを理解し、概念の裏にある根拠を確かめ、エージェントが書いた内容を修正したり却下したりするために使います。どの変更もMarkdownの差分なので、コードと同じようにGitでレビューできます。
- **あなたのコーディングエージェント**は、タスクを始める前にそのタスクに関わる概念、コードパス、未解決の問いを読み、コードを変更したあとに更新を提案するために使います。AtlasのMCPサーバはエージェントが手元のコンピュータで起動するので、アプリを開いたままにしておく必要はありません。

## 動作環境

- **macOSアプリ**（Apple Silicon）: 署名と公証を済ませており、MCPサーバはアプリに内蔵されています。
- **Windows x64ベータ**: 署名はありません。フォルダとMCPの機能は同じです。
- **ブラウザ**: ChromeかEdgeなら、ディスク上のフォルダを開いてマップを表示できます。ブラウザではエージェントを登録できず、エージェントとのチャットもなく、APIキーも保存しません。フォルダを開いていないときはサンプルのマップを表示します。
- **Linux**: ブラウザを使うか、ソースのチェックアウトからMCPサーバを実行します（[コーディングエージェントを接続](/guide/connect-agent)）。

アカウントも、Atlasのサーバも、テレメトリもありません。フォルダは、ディスク上の普通のMarkdownのままです（[データ、プライバシー、安全性](/guide/trust)）。

## 役立つとき、役立たないとき

コードベースが大きすぎて頭に収まらないとき、エージェントのセッションのたびに同じ背景説明を貼り付けているとき、変更を受け入れる前にそれが何に影響しうるかを見たいときに役立ちます。

数ファイルのプロジェクトや、コードの構造だけを知りたい場合には、あまり役立ちません。それなら検索や言語サーバのほうが速く答えます。マップ上の線は宣言された関係であって、実行時の振る舞いを証明するものではありません。また、Atlasはまだ初期段階です。Atlasを使うとエージェントの答えがよくなることは、自前のベンチマークでもまだ示せていません（[測定の状況](https://github.com/wlsdks/ontology-atlas/blob/main/docs/benchmark/README.md#current-measurement-status)）。
