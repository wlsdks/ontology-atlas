# 概念と関係を編集する

この章では、オントロジーを変更する方法を説明します。マップ上での関係や概念の本文の編集、概念の作成、Claude CodeやCodexなどのコーディングエージェントに変更を提案させてレビューする方法、そしてディスク上のファイルが先に変更されていたときの動作です。どの方法でも、最後に変わるのはオントロジーフォルダ内のMarkdownファイルです。もちろん、自分のエディタでそれらのファイルを直接編集してもかまいません。

独立したエディタ画面はありません。以前のStudioのアドレス（`/ontology/studio`と`/ontology/edit`）は、同じ概念を選んだ状態のマップにリダイレクトするだけです。

## マップ上で関係を編集する

1. マップ上で概念を選びます。
2. 概念パネルで**関係を編集**を押します。ドメインの場合は、**編集**を開いて**関係を編集**を選びます。
3. パネルが同じ場所で関係エディタに切り替わります。**つながりの種類**として、**上位概念**、**依存**、**包含**、**関連**のいずれかを選びます。
4. **つなぐ概念**を選びます。選べるのはフォルダにすでに文書がある概念だけなので、関係の参照先が見つからなくなることはありません。
5. **このつながりがある理由**を入力します。**依存**では必須で、ほかの種類でも書くことをおすすめします。
6. マップが2つの概念の間に描く破線のプレビューを確認します。書き込む前に、関係の向きを確認できます。
7. **変更を確認**を押します。理由を含め、フロントマターで変わる部分だけが表示されます。
8. **確定して書き込む**を押すとファイルに書き込み、**編集に戻る**を押すと前に戻ります。

関係を削除するには、エディタでその関係を開き、**このつながりを削除**を選びます。削除も同じレビューを通ります。既存の関係の相手を変えると、古い相手とその理由が1回の書き込みで置き換えられます。

エディタは一度に1つの関係を扱うので、マップはその横に表示されたままです。それぞれの型の意味と、どのフロントマターのキーに書き込まれるかは、[関係](/guide/relations)で説明しています。

## 概念の本文を編集する

概念パネルで**詳細を開く**を押して全体表示を開き、**本文を編集**を押します。定義、その概念が含むものと含まないもの、不確かなことを書き、**保存**を押します。ほかの言語での名前（`display_<locale>`）やほかのフロントマターのフィールドは、ファイル自体で編集できます。

## 概念を作る

**概念を追加**は3つの方法で開けます。マップの何もない場所を右クリックする、空のマップで**概念を作成**を押す、ドメインで**編集**を開いて**関係のある概念を作成**を選ぶ、のいずれかです。

画面の言語で名前を入力し（2つ目の言語は任意）、**種類**を選び、必要なら**ドメイン**も選びます。**作成**を押しても、まだ書き込みはされません。書き込まれるスラッグ、`uid`、名前、ドメイン、作成者を示すレビューが表示されます。**確認して保存**で`.md`ファイルが作られます。**編集に戻る**を押すと、入力した値を保ったままフォームに戻ります。種類を決めるときは[概念の選び方](/guide/what-becomes-a-node)が参考になります。

## エージェントに変更を提案させる

### デスクトップアプリの場合

概念パネルの**質問**を押すと、マップの横でコーディングエージェントとの会話が開き、その概念についての質問がすぐ送れる状態で入っています。エージェントはAtlasのMCPサーバを通じて作業します。

- オントロジーの読み取り（`list_concepts`、`get_concept`、`find_path`などの読み取りツール）では、会話は中断されません。
- 書き込み（`add_concept`、`add_relation`、`patch_concept`などの書き込みツール）のたびに、会話は**変更案を確認してください**という見出しのカードで止まります。カードには、何が作られ何が変わるのかと、関係の場合はその理由が表示されます。
- **今回のみ許可**を押すと、その1回の書き込みが実行されます。**拒否**を押すと何も書き込まれません。**拒否して修正**は書き込みを拒否し、あなたが送るための修正依頼の下書きを作ります。
- まとめて行う書き込みは1項目ずつ表示され、あなたの答えはまとまり全体に適用されます。
- 書き込みツールで**この会話の間、このツールを許可**が表示されることはありません。

チャットの**モード**を**自動承認**にすると、このフォルダ内のファイル編集と、概念や関係の追加・変更は、確認なしで進みます。削除、コミット、シェルコマンド、フォルダ外のものは、引き続き確認を求めます。この設定は、オフにするまでこのフォルダで有効です。プライバシーの設定にある**許可リスト**には**チャットの自動承認**として表示され、**許可を取り消す**で取り消せます。

### ターミナルのエージェントの場合

Claude Code、Codex、CursorがAtlasのMCPサーバを直接使う場合、何を実行するかはエージェント自身の権限確認で決まります。名前の変更、マージ、削除、関係の削除を行うツールは、デフォルトではプレビューだけを行い、`confirm: true`のときにだけ書き込みます。どちらの場合も、結果は普通のファイルの変更です。マップは数秒以内にそれを反映します。エージェントが作った概念には`created_by: "agent:<name>"`が付き、変更は`git diff`に現れるので、レビューしたり元に戻したりできます。

ファイルが書き込まれたことは、その意味が受け入れられたことと同じではありません。人が判断すべき概念には、エージェントが`review_state: human_decides`の印を付けられます。文書ビューでは、**決定済みにする**でその印を外し、**確認済みにする**で、人が概念を読んで意味が正しいと確かめたことを記録します。そのあとでファイルが変更されると、概念パネルがそのことを知らせます。

## ファイルが先に変更されていたとき

マップからファイルに書き込む前に、Atlasはあなたが開いたあとにファイルが変更されていないかを確かめます。その間に別のエディタ、チームメイト、エージェントが同じファイルを変更していた場合は、何も上書きしません。

- 関係エディタには「書き込めませんでした。ファイルが変更されていないか確認して、もう一度お試しください。」と表示されます。
- 本文の編集では、あなたの文章を保ったまま、ファイルが先に別の場所で変更されたことを知らせます。もう一度保存すると、あなたの文章で置き換えられます。
- MCPの書き込みツールは`expected_mtime`を受け付け、一致しなければ上書きせずに失敗します。

これらの画面の裏に、下書きの保存場所やレビュー待ちのキューはありません。提案は確定するまで画面の上にしかなく、書き込まれたあとはMarkdownファイルが唯一のバージョンです。
