# コードから最初のマップを作る

この章では、リポジトリについて最初のコードベースオントロジー、つまりコードが実装しているドメイン、ケイパビリティ、要素と、それらの関係を作ります。Claude CodeやCodexなどのコーディングエージェントがMCP経由でコードを読み、マップを提案します。それをあなたがレビューし、承認したものだけが書き込まれます。

## 誰が何をするか

Atlasが自分でコードを読み解いて意味を決めることはありません。エージェントがコードを読み、根拠とともに概念と関係を提案し、受け入れられたものだけをオントロジーフォルダにMarkdownとして書き込みます。コードは読まれるだけで、変更されることはありません。

リポジトリのスキャン結果は根拠であって、答えではありません。`analyze_repo_structure`、`index_project`、`infer_imports`は何も書き込みません。フォルダ名やimport文は、エージェントが観察した事実にすぎず、まだドメインでも、ケイパビリティでも、依存でもありません。

## アプリで始める

デスクトップアプリには、3つの始め方があります。

**コードからオントロジーを作る。** スタートカードにあるこのボタンを押すと、コードのフォルダを選ぶよう求められます。Atlasは、そのコードフォルダ内に作成する`atlas`フォルダのパスを表示し（既存のものがあればそれを再利用し）、**作成**が押されるのを待ちます。続いてコーディングエージェントとの会話が開き、エージェントがコードを読んで、1回の実行で最初のマップを書きます。書き込みのたびに承認を求めます。**自動承認**がオンでも、エージェントはコードフォルダを結び付ける前と、マップを仕上げる前には確認を求めます。

**はじめに。** まだマップのないフォルダを開くと、マップ上のカードがいくつかの手順を案内します。コードフォルダでは、最初の手順は**コードからエージェントにマップの下書きを作らせる**です。アプリでコーディングエージェントが使える状態なら、**エージェントに依頼**を押すと、マップの隣にあるエージェントとの会話に依頼文が入り、**送信**はあなたが自分で押します。そうでなければ、**プロンプトをコピー**で同じ依頼文をコピーし、ターミナルで動かしているエージェントに渡せます。その後の手順では、エージェントを接続し、スターターの文書を作るか、手作業で始めるかを選びます。

**ローカルモデルを使ってコードから作る。** macOSアプリでは、マップの隣にあるエージェントパネルに**コードから作成**があります。使うには、Ollama、LM Studio、llama.cppなどのローカルモデルを、**エージェント**の**モデル**で設定しておく必要があります。コードのフォルダを選ぶと、プレビューにコードフォルダ、レビューした変更の保存先、モデル、そのアドレス、対象となるファイルの数が表示されます。**実行**を押すと、コードの抜粋をそのローカルのアドレスにだけ送ります。結果は、提案された文書の変更の一覧として返ってくるので、必要なものを選んで適用します。

## ターミナルから始める

Atlasのソースをチェックアウトしてあれば（[CLI](/guide/cli)を参照）、自分のリポジトリで次のコマンドを実行します。

```bash
cd /path/to/your/repo
node ~/tools/ontology-atlas/cli/src/index.mjs init ./atlas
node ~/tools/ontology-atlas/cli/src/index.mjs bootstrap . --vault ./atlas
```

`init`は、5つのスターターファイルを含む`atlas`フォルダ、エージェントの設定ファイル`.mcp.json`と`.codex/config.toml`、そしてClaude CodeとCodex向けの3つのスタータースキル`atlas-review`、`atlas-grow`、`atlas-absorb`を作成します。スターターファイルは形を示す例であって、あなたのプロダクトを分析したものではありません。

`bootstrap`はリポジトリをスキャンし、レビュー計画を出力します。何も書き込まず、まだ承認が必要であることを示すために終了コード3で終わります。リポジトリでエージェントを再起動し、そこで続けてください。

## エージェントへの頼み方

最初のマップは小さく作ります。理解したい振る舞いを1つ選び、それに絞って頼みます。たとえば次のように頼みます。

```text
このリポジトリの最初のAtlasマップを作ってください。対象は[1つの振る舞い。
たとえば注文の受け付け]に絞ってください。

最初にconnection_infoを呼び出し、オントロジーフォルダとコードリポジトリを
確認してください。重複を作らないよう、list_kindsと既存の概念を読んでください。
スターターファイルは事実ではなく例として扱ってください。

エントリーポイント、その条件、失敗する経路を読んでください。書き込む前に、
小さなまとまりで提案してください。概念ごとに、定義の1文、含むものと含まないもの、
それを実装しているファイル、確認できなかったことを示してください。関係ごとに、
それが成り立つ理由を示してください。

私がそのまとまりを修正または承認できるよう、そこで止まってください。そのあと、
私が承認したものだけを書き込み、validate_vaultを実行してください。
```

最初は概念が数個あれば十分です。別の答えが必要になったら追加しましょう。

## 保存する前にレビューする

よい提案なら、特定の主張1つだけに異を唱えられます。概念と関係を1つずつ確認してください。

- **名前で何をするものかが分かる。** フォルダ名やライブラリ名だけでは、チームメイトに伝わる情報が少なすぎます。
- **本文に必要な部分がそろっている。** 定義の1文、`## Includes`、`## Excludes`、`## Uncertainty`です。どれかが欠けていると`validate`が警告します。
- **根拠がファイルを指している。** ケイパビリティや要素には、コードへの`path`があります。パスが存在しても説明が正しいとは限らないので、中身を読んでください。
- **関係が成り立っている。** 関係の相手を取り除いてもそのケイパビリティが動くかどうかを考えてください。importがあるだけでは依存の証明になりません。

実際に読んだまとまりを承認してから、次のまとまりを頼みます。マップの形が固まったら、エージェントは`connect_project_source`でプロジェクトをコードフォルダに結び付け、`finalize_project_meaning`で結果を記録できます。ただし、書き込みが成功しても、その意味が受け入れられたことにはなりません。コミットする前に差分を読んでください。

## CLAUDE.mdとAGENTS.mdを再利用する

エージェント向けの指示ファイルには、すでにコードベースの説明が書かれていることがよくあります。`absorb`は、それを概念に変えます。

```bash
node ~/tools/ontology-atlas/cli/src/index.mjs absorb CLAUDE.md AGENTS.md --vault ./atlas
```

デフォルトでは計画を出力するだけです。`--write`を付けると、方針やルールのセクションを`document`の概念として保存し、元のファイルのバックアップを`.pre-absorb.bak`として残し、元のファイルを短いポインタに書き換えます。取り込まなかったセクションはそのまま残ります。アーキテクチャのセクションは提案されるだけで、自動で書き込まれることはありません。エージェントはMCPツール`absorb_document`で同じことができます。

`init`は、自分の`CLAUDE.md`や`AGENTS.md`に貼り付けるための短い段落も出力します。この段落は、今後のエージェントのセッションに、オントロジーがあることと、いつそれを読むべきかを伝えます。Atlasがこれらのファイルを代わりに編集することはありません。

フォルダに、まだマップに載っていないMarkdownの文書がすでにある場合、**はじめに**のカードに**文書からマップを作成**という手順が加わります。

次は[マップの読み方](/guide/reading-the-map)を覚え、そのあと[コードの変更に合わせてマップを最新に保つ](/guide/growing-vault)方法に進みましょう。
