# データ、プライバシー、安全性

この章では、Ontology Atlasを使うときにデータがどこにあるのか、何がいつコンピュータの外に出うるのか、MCPで接続したコーディングエージェントがどう関わるのか、そしてダウンロードしたアプリが私たちのビルドしたものかどうかを確かめる方法を説明します。ここに書いたことはすべて、公開されているソースコードで確認できます。

## 要点

- オントロジーは、自分で選んだフォルダにある普通のMarkdownです。Atlasはそれをアップロードしません。
- Atlasには、バックエンドサーバも、アカウントも、テレメトリもありません。
- アプリがインターネットに接続するのは、下に挙げた経路だけです。そのほとんどは、ボタンなどを押したときにしか動きません。
- 接続したコーディングエージェントは別のプログラムです。エージェントは、プロンプトや読んだ内容をエージェント自身のプロバイダに送ることがあり、Atlasはその通信を見ることも記録することもできません。

## コンピュータに残るもの

- **オントロジーフォルダ。** Markdownファイルが唯一の正本です。アプリを削除してもフォルダは残り、どのエディタやスクリプトでも引き続き読めます。
- **フォルダ内の`.ontology-atlas/`。** フォルダの設定と、後述する送信ログです。Gitはデフォルトでこのフォルダを対象外にします。
- **アプリの検索インデックス。** アプリではデフォルトでオンです。フォルダのファイルから作られ、コンピュータのキャッシュフォルダに置かれ、どこにも送られません。設定の**プライバシー・データ** › **このコンピュータに保存されているもの**でオフにしたり削除したりできます。
- **モデルプロバイダのAPIキー**（アプリのみ）。macOSのキーチェーンなど、OSの資格情報ストアに保存されます。ブラウザ版はキーを一切受け付けません。
- **細かな設定。** 最近使ったフォルダの一覧などです。ブラウザは、次回も同じフォルダを候補に出せるよう、開いたフォルダへのハンドルだけを保持します。

Atlasが読むのは、自分で選んだフォルダだけです。フォルダを読むときは、`.env`や`.git/`のようなドットで始まるファイルやフォルダを読み飛ばします。

## コンピュータの外に出うるもの

アプリは、外部へのすべての経路を設定の**プライバシー・データ** › **外部への送信**に一覧表示します。経路は次のとおりです。

| 経路 | いつ | 送信先 | フォルダの内容 |
|---|---|---|---|
| アップデートの確認 | 自動。オフにできる | ontologyatlas.com | 含まない |
| アップデートのダウンロード | 押したとき | github.com | 含まない |
| モデルプロバイダ | 押したとき | Anthropic、OpenAI、GoogleのAPI | 送ったもの |
| ローカルモデルサーバ | 押したとき | 入力したアドレス | 送ったもの |
| 外部モデルでのレビュー | 押したとき | api.typesafe.ai | 送ったもの |
| コーディングエージェントのインストール | 押したとき | nodejs.org、npmレジストリ | 含まない |
| ACPアダプタのパッケージ | 押したとき | npmレジストリ、PyPI | 含まない |
| GitHub PRの説明の取得 | 押したとき | api.github.com | 含まない |
| Gitのプッシュ・プル・フェッチ | 押したとき | お使いのGitリモート | 送ったもの |
| フォルダに追加したMCPサーバ | エージェントが使うとき | それぞれのアドレス | エージェントが送る |
| コーディングエージェント | エージェントが作業するとき | エージェント自身のプロバイダ | Atlasからは見えない |

Atlasが行うモデルの呼び出しは、ローカルモデルサーバへの呼び出しも含めてすべて、フォルダ内の`.ontology-atlas/llm-audit.jsonl`に記録されます。自動のアップデート確認は、設定 › **情報** › **アップデートを自動で確認**で切り替えます。

ブラウザ版が読み込むのは、ontologyatlas.comにあるWebサイト自身のファイルだけです。フォルダは手元のコンピュータ上で読み、アップロードすることはありません。

## コーディングエージェントとMCP

AtlasのMCPサーバは、常に動き続けるサービスではありません。コーディングエージェントが必要なときに手元のコンピュータで起動し、標準入出力でやり取りし、セッションとともに停止します。ネットワークポートを開くことも、ネットワークリクエストを送ることもありません。

エージェント自体は話が別です。Claude Code、Codex、Cursorなどのエージェントは、プロンプトと読んだファイルをそれぞれのプロバイダに送ります。その通信はエージェントのものであり、エージェント自身の設定に従い、Atlasのログには載りません。

書き込みを誰が承認するかは、エージェントがどこで動いているかによって変わります。

- **アプリのエージェントチャットの場合**、ファイルの編集やAtlasへの書き込みはそれぞれ、あなたが**今回のみ許可**か**拒否**を押すまで待ちます。ただし、そのフォルダで**自動承認**をオンにした場合は別です。シェルコマンド、削除、フォルダ外のパスは常に確認を求めます。
- **MCPで接続したエージェント**は、それぞれのターミナルやエディタの中で、Atlasではなくそのツールの権限ルールに従って書き込みます。

どちらの場合も、変更はフォルダ内のMarkdownの差分になるので、Gitでレビューしたり元に戻したりできます。

## ダウンロードしたアプリを確かめる

- **macOS**: アプリはApple Developer IDで署名され、Appleの公証を受けています。リリースのビルドでは、公開前に署名済みのディスクイメージと、インストールしたアプリの両方を検証します。検証に失敗したビルドはリリースされません。アプリ内アップデートも署名されています。
- **Windows x64ベータ**: インストーラには署名がないため、SmartScreenが発行元不明の警告を出すことがあり、組織で管理されたコンピュータではブロックされることもあります。リリース前には、ビルドをMicrosoft Defenderでスキャンし、サイレントインストールして起動します。
- **Linux**: まだアプリはありません。ブラウザ版を使うか、ソースからMCPサーバを実行してください（[コーディングエージェントを接続](/guide/connect-agent)）。

[リリースページ](https://github.com/wlsdks/ontology-atlas/releases)のインストーラ（`.dmg`、`.exe`）とMCPバンドル（`.mcpb`）には、隣に`.sha256`ファイルがあります。ダウンロードしたファイルのチェックサムと比べてください。

macOSの場合:

```sh
shasum -a 256 <file>
```

WindowsのPowerShellの場合:

```powershell
Get-FileHash <file> -Algorithm SHA256
```
