name: design-directions
description: Sketch 3–4 structurally different ways a UI change could go — in text, before writing any code — and have the owner pick one. Use before implementing any non-trivial visual, layout, interaction, or motion change, and before convening the design council. This is the cheap step that prevents building the wrong shape: the model has a persistent default it returns to unless a concrete spec exists, and generic redirection ("cleaner", "not like that") only swaps one default for another. Skip for value-level edits inside an already-decided shape — a token swap, a copy fix, a spacing nudge.

# /design-directions — 짓기 전에 갈래를 그린다

## 왜 이게 필요한가 — 근거는 두 개다

**① 모델에는 지속적인 기본 스타일이 있고, 그것은 티어로 사라지지 않는다.**
Anthropic 공개 문서가 프론티어 모델의 프론트엔드/디자인 기본값을 명시적으로
기록한다 — 그리고 결정적인 문장은 이것이다:

> 일반적인 지시("크림색 쓰지 마", "깔끔하고 미니멀하게")는 다양성을 만들지
> 못하고 **다른 고정 팔레트로 옮길 뿐이다.**

즉 *"이거 말고"* 는 방향을 바꾸지 않는다. **구체적 스펙만 바꾼다.** 그리고
`temperature` 가 프론티어 모델에서 제거되면서, 문서가 지정한 대체 경로는
하나뿐이다 — **먼저 여러 방향을 제안하고 사람이 고른다.**

**② 학술 근거가 같은 처방을 낸다.** Dow, Glassco, Kass, Schwarz, Schwartz &
Klemmer, *"Parallel Prototyping Leads to Better Design Results, More Divergence,
and Increased Self-Efficacy"* (ACM TOCHI 2010) — **여러 개를 만든 뒤 피드백을
받는 쪽(parallel)이 하나씩 만들고 매번 피드백을 받는 쪽(serial)보다 결과 품질 ·
발산 · 자기효능감 **셋 다**에서 우월했다.** 실험으로 보인 것이다.

`/design-council` 은 정의상 serial 이다 — R1 비평 → R2 교차비평 → R3 평결이
전부 **이미 만들어진 하나**를 평가한다. 이 스킬이 그 앞에 붙는 발산 단계다.

**③ 이 저장소에서 실제로 그 비용을 냈다.** 2026-08-03 PO 카운슬은 액션 타일과
생성 컴포저를 두고 다섯 자리가 두 라운드를 돌았다. 나온 결론은 「7칸을 3층으로」와
「중앙 모달을 부모 옆으로」였는데, **그 둘은 처음에 세 줄로 그릴 수 있는
갈래였다.** 카운슬이 비싼 게 아니라 **갈래를 안 그리고 하나를 지은 것**이 비쌌다.

## 누가 갈래를 그리는가 — 짓는 쪽이 아니다

**소유자는 `chief` 다.** `design-guardian`(유일하게 코드를 고치는 자리)이 아니다.

만들 사람이 선택지를 만들면 **선택지가 자기가 만들고 싶은 것 쪽으로
기운다** — 나머지 셋이 허수아비가 되고, 그러면 이 절차는 발산이 아니라 변경을
정당화하는 의식이 된다. 그건 이 저장소가 카운슬을 만든 이유와 정확히 같은
실패다(*"자기가 만든 것을 자기가 통과시키면 안 된다"*).

`chief` 가 갈래를 그리고, 소유자가 고르고, 그다음에 구현자가 짓는다.

## 이 제품에서 「방향」은 팔레트가 아니다

⚠️ **문서의 예시(bg hex / accent hex / typeface)를 그대로 쓰지 마라.** 이 앱은
헌장이 색을 이미 고정했다 — 다크 단일 · 무채색 + 단일 인디고(`#5e6ad2`) ·
그라디언트/글로우/글래스 금지(`.claude/rules/design.md` · `forbidden.md`). 팔레트
갈래를 물으면 **헌장이 이미 답한 것을 다시 묻는 것**이고, 넷 중 셋은 반려될
것을 알면서 그리는 셈이다.

여기서 실제로 갈리는 축은 넷이다:

| 축 | 갈래가 다르다는 것은 |
|---|---|
| **위계** | 이 화면에서 **무엇이 주목을 이기는가**가 다르다 |
| **배치·밀도** | 같은 요소들이 **어떻게 묶이고 몇 줄인가**가 다르다 |
| **상호작용 모델** | 같은 일을 **모달/인라인/팝오버/제자리** 중 어디서 하는가 |
| **모션이 나르는 정보** | 무엇이 움직여서 **무엇을 말하는가**(장식은 갈래가 아니다) |

한 갈래가 다른 갈래와 **이 넷 중 하나 이상에서 달라야** 갈래다. 같은 구조에
값만 다르면 그건 갈래가 아니라 튜닝이고, 이 스킬의 대상이 아니다.

## 언제 돌리나

**돌린다** — 비자명한 시각/레이아웃/상호작용/모션 변경 **전에**, 그리고
`/design-council` **전에**. 카운슬은 이미 지어진 것을 심사하는 자리고, 이건 무엇을
지을지 고르는 자리다. 순서가 뒤집히면 카운슬이 갈래 탐색을 대신하게 되고, 그게
오늘 실제로 일어난 일이다.

**안 돌린다** — 이미 정해진 형태 **안에서의 값 편집**: 토큰 교체, 카피 수정, 간격
조정, 오타. 여기에 갈래를 그리는 것은 이 저장소가 경계하는 process theater 다.

**애매하면 물어라, 그리는 데 5분이다.** 이 스킬의 값어치는 싸다는 데 있다 —
비싸지면 존재 이유가 사라진다.

## 규율 — 이게 싸야 이게 산다

1. **코드를 쓰지 않는다.** 갈래는 **글과 ASCII** 다. 빌드도 스크린샷도 없다.
   하나라도 구현하면 그 갈래가 남은 셋을 이긴다 — 만든 것이 아까워서다.
2. **3~4개.** 둘은 이지선다라 갈래가 아니고, 다섯은 고르는 게 일이 된다.
3. **하나는 「지금 그대로」여야 한다.** 현행이 후보에 없으면 이 절차는 변경을
   정당화하는 의식이 된다. 현행이 이기는 결과가 정상적으로 가능해야 한다.
4. **각 갈래는 자기를 죽이는 조건을 같이 적는다.** 무엇이 참이면 이 갈래가
   틀렸는지. 이게 없으면 취향 투표다.
5. **헌장 위반 갈래는 그리지 않는다.** 그릴 거면 `forbidden.md` 를 여는 요청을
   따로 올린다 — 몰래 섞지 않는다.
6. **소유자가 고른 하나만 짓는다.** **합집합 금지** — 둘을 합치면 아무도 고르지
   않은 셋째가 나온다(PO 카운슬의 같은 규칙).

## 출력 형식

```md
## 방향 — <무엇을 바꾸려는가>

**지금 이 화면의 일**: <한 문장. 못 쓰면 아직 디자인이 시작 안 된 것이다>
**갈리는 축**: 위계 / 배치·밀도 / 상호작용 모델 / 모션 중 무엇인가

### A. 지금 그대로
<현행을 한 문단. 무엇이 이미 되고 있는지 정직하게>
**이게 이기는 조건**: <…>

### B. <이름 — 형용사가 아니라 구조를 말하는 이름>
```
<ASCII 스케치 — 실제 치수를 알면 적는다>
```
**바뀌는 것**: <위 네 축 중 무엇이 어떻게>
**대가**: <무엇을 잃는가. 없으면 갈래를 잘못 그린 것이다>
**이게 틀렸다면 보일 것**: <…>

### C. … / D. …

**실측이 이미 말하는 것**: <재 본 수치가 있으면. 없으면 "없음">
**내 추천과 이유**: <하나. 고르는 것은 소유자다>
```

## 고른 뒤

1. 고른 갈래를 **한 줄 스펙**으로 적는다 — 다음 사람이 읽고 같은 것을 짓게.
2. 그 스펙으로 구현한다. **나머지 갈래는 버리지 말고 기록에 남긴다** — 되돌릴
   때 처음부터 다시 그리지 않기 위해서다.
3. 되돌리기 어렵거나 비싼 변경이면 그때 `/design-council` 을 부른다. 카운슬은
   **고른 갈래를 심사**하지 갈래를 고르지 않는다.
4. 구현 뒤 `/design-audit`(실측) · 모션이 걸리면 `/motion-verify` ·
   브레이크포인트가 걸리면 `/responsive-sweep`.

## 이 스킬이 실패하는 방식

| 실패 | 어떻게 아는가 |
|---|---|
| 갈래가 사실 하나다 | 넷이 위 네 축에서 서로 안 다르다 — 값만 다르다 |
| 현행이 후보에 없다 | 「지금 그대로」 항목이 비었거나 허수아비로 적혀 있다 |
| 갈래에 대가가 없다 | 전부 좋기만 하면 아무것도 안 재 본 것이다 |
| 이미 지어 놓고 그린다 | 코드가 먼저 있으면 이건 사후 정당화다 |
| 합쳐서 짓는다 | 아무도 고르지 않은 형태가 화면에 나온다 |
