## 각 표면의 일 — 한 문장씩

- **앱의 일**: 볼트의 본거지 — 사람이 지도를 보며 판단하고, 안의 에이전트
  (패널)와 밖의 에이전트(MCP)를 연결·심판하는 워크벤치다.
- **웹의 일**: ① **관문** — 설치 없이 지도를 열어 보는 자리(데모·첫 5분·
  링크 공유). ② **차선 워크벤치** — 앱이 없는 환경(Windows·리눅스의
  Chromium)에서 같은 폴더를 읽고 고치는 자리. 에이전트 연결 허브는 아니다.

**서열이 중요하다 — 1번이 관문이다.** "웹은 윈도우를 위한 것"이 아니다.
실측(2026-07-27): 14일 순방문 35명이 전원 웹으로 들어왔고 Windows 사용자
관측은 0건이다. 순서를 뒤집으면(웹 = 윈도우 대체품) 지금 유일한 유입
경로의 품질이 2류로 강등된다. **Windows 앱이 나와도 웹은 안 사라진다** —
2번 일만 OS 별로 소멸하고, 링크로 열리는 관문은 앱이 대체할 수 없다.

## 코드베이스는 가르지 않는다

앱은 같은 정적 export(`out/`)를 Tauri WebView 에 싣는 **한 빌드**다
(`src-tauri/tauri.conf.json` 의 `frontendDist: "../out"`). 분리의 구현은
포크가 아니라 **능력 브리지 5개**다:

| 브리지 | 파일 | 웹에서 |
|---|---|---|
| 볼트 절대 경로 | `src/shared/lib/tauri-vault-fs.ts` | FSA 핸들로 대체(경로 없음) |
| git | `src/shared/lib/tauri-git.ts` | 실행 불가 → 강등 카드 |
| 키체인 | `src/shared/lib/tauri-secrets.ts` | 원리적 불가 → 강등 카드 |
| LLM 호출 | `src/shared/lib/tauri-llm.ts` | 원리적 불가 → 액션 자체를 안 그림 |
| 에이전트 연결 | `src/shared/lib/tauri-agent-setup.ts` | 절대 경로가 없어 실행 가능한 설정 불가 → 강등 카드 |
| **폴더 감시** | `src-tauri/src/lib.rs`(`start_vault_watch`) + `src/features/docs-vault-local/model/TauriVaultWatchBridge.tsx` | OS 워처가 없어 **적응형 폴링**으로 대체(burst 1500ms / idle 5000ms) → 강등이 아니라 **지연** |

관례는 하나다: `getInvoke()` → `isTauri()` 아니면 `null` → **화면 정직
강등**. 새 데스크톱 능력도 이 관례로만 붙인다. 갈래를 새로 만들지 않는다.

### 폴더 감시는 「강등」이 아니라 「지연」이다 — 등록부가 다른 이유

앞의 다섯은 웹에서 **못 하는** 것이라 강등 카드가 답이다. 여섯 번째는 다르다:
웹도 **결국 따라온다**. 다른 것은 *언제* 다.

| | 앱 | 웹 |
|---|---|---|
| 기제 | OS 파일워처(`notify`), 500ms 디바운스 | 적응형 폴링 |
| 반영까지 | 0.5초 안팎 | burst 1.5초 / idle 5초 |
| 탭이 숨으면 | 계속 감시 | 폴링 중단(가시성 게이트) |

그래서 **`DEGRADED_SURFACES` 에 넣지 않는다.** 그 등록부의 각 행은 *"브라우저는
원리적으로 이걸 못 한다 → 유일한 목적지는 `/download/`"* 를 주장하는데, 폴더
감시는 그 주장이 **거짓**이다. 넣으면 다음 감사자가 "웹은 파일 변화를 못 본다"
로 읽고, 그건 사실이 아니다.

**대신 이 표가 등록부다.** 강등에 축이 둘(웹↔앱 · 뷰포트 폭)이라고 아래에
적어 둔 것과 같은 이유로, **세 번째 축**이 여기 있다 — *즉시성*. 축이 다르면
게이트도 다르다.

⚠️ **마케팅이 이 차이를 팔 때의 규율**: "고치면 지도가 즉시 따라온다"는 앱의
문장이다. 웹에서도 따라오지만 **즉시는 아니다**. 시연 영상이 이 능력을 파는
근거로 쓰이므로(2026-07-29 원장), 그 문장을 웹 화면 위에 얹지 않는다.

## 데이터만 같다 — 경계표

**같다 (계약)**

| 층 | 보장 |
|---|---|
| 진실원 | 디스크의 마크다운 폴더 하나. 웹(FSA 핸들)과 앱(절대 경로)이 **물리적으로 같은 폴더**를 읽고 쓴다 |
| 해석 | frontmatter 파싱 3-way·검증 2-way 계약 테스트(`tests/contract/`), 스키마는 `mcp/src/schema.mjs` 단일 |
| 에이전트 기록 | `.ontology-atlas/activity.jsonl` · `llm-audit.jsonl` — **볼트 안 평문**이라 표면 무관 |
| 충돌 방지 | `patch_concept(expected_mtime)` — 어느 표면이 고치든 mtime 낙관 잠금 |

**안 같다 (의도)**

- **"마지막에 연 볼트"는 안 넘어간다.** 웹은 자기 IndexedDB, 앱 WebView 는
  자기 IndexedDB — 양쪽에서 각각 폴더를 고른다. 진실원이 아닌 편의 캐시라
  계약 위반이 아니다. 웹→앱 이동 순간의 안내는 `/download` 설치 02 단계가
  맡는다("앱이 처음 묻는 것은 폴더 하나입니다").
- **키·설정은 안 넘어간다.** API 키는 키체인(앱), 화면 취향은 localStorage.
  비밀과 취향은 볼트에 넣지 않는다.
- **브라우저 커버리지**: FSA 는 Chrome/Edge/Safari 18.2+/Opera 만. Firefox 는
  `unsupported` 로 정직 강등된다. "Windows 를 위한 웹"은 정확히는
  "Windows **Chromium** 을 위한 웹"이다.
- **두 표면 동시 편집 UX 는 계약 밖**이다. mtime 잠금이 데이터는 지키지만
  동시 작업 흐름을 매끄럽게 만들진 않는다.

### 규칙으로 승격

> **표면을 넘어야 하는 데이터는 전부 볼트 폴더 안에 산다.**

frontmatter 이거나 `.ontology-atlas/*.jsonl` 이다. 표면 간 상태를 브라우저
저장소·앱 전용 저장소에 두고 "양쪽이 같다" 고 말하지 않는다.

## 웹 동등물은 짓지 않는다

데스크톱 능력이 나갈 때 **웹 동등물을 백필할 의무는 없다.** 이 의무는
2026-07-27 에 공식 폐지됐다 — 그 의무가 있는 척하는 동안에도 실제로는 네 번
연속(키체인·MCP 번들·업데이터·git) 백필 없이 나갔다.

명시적으로 **짓지 않기로** 한 것:

- **웹 BYOK** — 브라우저 저장소의 키는 XSS 한 번에 유출되고, 벤더가 직접
  호출 헤더 이름에 `…-dangerous-direct-browser-access` 라고 써 뒀다.
  원리적 기각이라 재검토 조건은 "벤더가 브라우저 직접 호출을 공식 지원
  경로로 바꿀 때" 하나뿐이다.
- **웹에서 `.mcp.json` 등 에이전트 설정 쓰기** — 절대 경로가 없으면 쓸 값이
  없다.

대신 **강등 카드가 두 가지를 말해야 한다**:

1. **왜** 안 되는지 (능력의 부재를 사과문이 아니라 이유로)
2. **어디서** 되는지 (갈 수 있는 곳 — 보통 `/download/`, 또는 CLI 한 줄)

모범: `atlas-git-web-get-app`(기록) · `ai-connection-web-degraded`(설정 AI) ·
`first-run-starter-unsupported`(FSA 미지원). **"곧 됩니다" 는 강등이 아니라
거짓말이다.** 오늘 안 되는 것은 안 된다고 쓴다.

`tests/e2e/web-surface-smoke.spec.ts`:

2. **차선 워크벤치** — OPFS 스텁 픽커로 폴더를 골라 **실제로 파싱**되고

3. **정직한 강등** — 등록부의 데스크톱 전용 표면이 이유와 목적지를 함께

**게이트 배선**: `.github/workflows/e2e.yml` 의 `Web surface smoke` 스텝.
조건이 전체 스위트보다 **넓다** — `runtime` 만 바뀌어도(예: `src-tauri/**`
전용 변경) 돈다. 데스크톱만 건드린 변경이 웹을 한 번도 안 보고 머지되는
것이 정확히 이 게이트가 막는 부패이기 때문이다.

**새 데스크톱 능력을 붙이면 스모크 ③ 의 `DEGRADED_SURFACES` 등록부에 한 줄을
더한다.** 등록하지 않은 능력의 웹 강등은 아무도 안 본다.

### 강등에는 축이 둘이다 — 등록부는 그중 하나만 본다 (2026-07-28)

`DEGRADED_SURFACES` 는 **웹↔앱 축** 전용이다. 각 행이 "브라우저는 원리적으로
이걸 못 한다 → 유일한 목적지는 `/download/`" 를 주장한다.

두 번째 축이 있다: **뷰포트 폭 축**. 같은 웹 빌드가 넓은 화면에서는 그 표면을
그대로 여는데 좁은 화면에서만 못 여는 경우다 (첫 사례: 공방 `<lg` — 나침
무대는 고정 폭 카드 + 위성 기하라 1024px 미만에서 성립하지 않는다. 설치 앱은
`minWidth 1040` 이라 이 폭 자체가 없고, 남는 인구는 웹 태블릿·분할창이다).

**두 축을 한 등록부에 섞지 않는다.** 폭 축을 `DEGRADED_SURFACES` 에 넣으면
그 행이 "웹은 이걸 못 한다" 는 거짓 주장을 하고, 다음 감사자가 그대로 읽는다.
폭 축의 게이트는 폭이 독립 변수인 `tests/e2e/responsive-overflow-audit.spec.ts`
가 맡는다.

**「왜 + 어디로」 계약은 축과 무관하게 똑같이 적용된다.** 폭 강등도 왜 못
오는지와 어디로 가면 되는지를 함께 말해야 한다. 다만 목적지가 `/download/`
하나로 고정되지 않는다 — 창을 넓히는 것, 이 폭에서도 되는 이웃 표면이 함께
목적지다. 모범: `studio-too-narrow`.

**반쪽 강등이 가장 나쁘다.** 공방은 내비(`BottomTabBar`)에서만 탭을 뺐고
라우트에는 폭 가드가 없어서, 딥링크 세 갈래(데이터시트 「관계 편집」·인사이트·
문서함 frontmatter)가 검증된 적 없는 폭으로 사용자를 그대로 던졌다. 내비에서
지웠으면 **라우트에서도 답해야 한다** — 못 가게 막아 놓고 보내는 길만 열어
두면 그건 축소가 아니라 함정이다.

  Tier B(README · TROUBLESHOOTING · CLI/MCP README 등)는 **코드 블록 안만**
  금지다. "그건 안 된다"고 말하려면 명령을 이름으로 불러야 하고, 펜스 안은
  "복사해 실행하라"는 뜻이기 때문이다. 라벨 장식 게이트가 화살표를 글리프가
  아니라 위치로 판별하는 것과 같은 원리다.

게이트 안에 **프로브 케이스가 상주**한다(위반 6종은 잡고, 살아있는 경로와
정직한 산문은 통과). 탐지기가 조용히 무력화되면 거기서 먼저 터진다.

## 이 계약이 틀렸다면 무엇이 보이나

원장의 반증 조건이 그대로 이 규칙의 반증 조건이다:

- 웹 스모크가 **2주 연속 빨간 채 방치**되거나 방문자의 깨진-웹 제보가 나오면
  → 스모크 3종이 부족했던 것. 웹 검증 범위를 재확장한다.
