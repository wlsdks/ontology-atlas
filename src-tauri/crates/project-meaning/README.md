# project-meaning

What a project's five competency answers claim, and whether its measured source and ontology back
them. `finalize_project_meaning` is the one writer; `get_concepts` and the brief read the
assessment.

| File | Owns |
|---|---|
| `meaning_questions.rs` | The five fixed questions, their required witnesses and the contract names |
| `competency_answers.rs` | The `answers` argument: validation, the one refusal that lists every row to repair, and the section's place in a body |
| `competency_markdown.rs` | The exact `## Competency answers` layout, written and read back |
| `meaning_inventory.rs` | The concepts, relations, source paths and pinned citations an answer may cite |
| `meaning_assessment.rs` | The categorical assessment and the reasons a row's witnesses fail |
| `meaning_receipt.rs` | `.ontology-atlas/project-meaning.json`: written once per project, read strictly |
| `structure_readiness.rs` | Whether the graph is shaped, linked, healthy and valid enough for the assessment to call its structure ready |
| `stored_name_shapes.rs` | The spellings a stored slug, hash, time or path must have |
