## 1. 정체성 — 2층 구조

**Layer 1 (로컬 코어 — 불변의 신뢰 계약)**
git-native 마크다운 vault가 곧 온톨로지. MCP 24도구(Tier화) + CLI. 영원히 무료, 완전 오프라인 동작, 백엔드 0.

**Layer 2 (Atlas Network — 선택적, 수요 게이트 뒤)**
포맷 표준(Spec) + 커뮤니티 레지스트리(Hub, GitHub 기반) + 유료 Team Sync(좌표 모델) + org 그래프(v2).

**신뢰 헌장 (Layer 2 헌법 — 위반 기능은 ship 금지)**
① Layer 1은 영원히 무료·완전·오프라인 ② 조용한 수집 0, 모든 전송 opt-in + 로컬 감사 로그 ③ 로그인 강제 0 ④ 데이터 포터빌리티 절대 (평문 마크다운) ⑤ 소급 변경 금지 ⑥ E2E·verified 등 보안 주장은 구현 공개 + 감사 초청이 있을 때만, verified 뱃지는 구조 검증만 의미 (인젝션-불가 함의 금지).

**solo-dev 부하 상한**: 소유자 실 커밋은 코어 트랙 + N0/N1까지. Hub 운영은 커뮤니티 위임 설계, Sync·org 그래프는 수요 게이트 전 코드 0줄. 총부하 초과 시 표면 폐기 심사 자동 개시.

## 2. 비밀 (우리가 믿는, 남들이 동의하지 않는 진실)

1. **자동으로 쌓인 에이전트 기억은 자산이 아니라 부채다.** 병목은 기억의 양이 아니라 검증 가능성이며, 검증은 코드와 의미가 같은 커밋에서 원자적으로 움직일 때만 지속된다 (git-원자성 — 클라우드 메모리가 재현 불가능한 구조 속성).
2. **"사람이 읽고, 에이전트가 유지하고, git이 추적하는 프로젝트 메모리"의 표준 자리는 비어 있다.** MCP는 프로토콜이지 포맷이 아니고, 기존 메모리 포맷은 프레임워크 종속이다. 우리는 스펙·레퍼런스 구현·검증기·계약 테스트를 이미 가진 유일한 후보다.

## 3. 문제 (증거 언어, P1~P7)

P1 에이전트는 세션마다 프로젝트를 재학습한다 (20,574 상호작용 연구) · P2 지식 그래프는 조용히 썩는데 감지 도구가 없다 (Confluence 41% stale — 시장 1위 불만) · P3 자동 캡처 기억은 환각을 영구 오염시킨다 (+AI 신뢰 40→29% 하락) · P4 그래프 뷰는 장식이 된다 (Obsidian hairball 합의) · P5 비개발자는 맵을 유지하지 않는다, 질문한다 (EA 도구 <10%) · P6 팀 에이전트 컨텍스트 공유 인프라가 없다 ("3개월 후 CLAUDE.md 유지 중단") · P7 에이전트 메모리 포맷 분열 — 도구를 바꾸면 기억을 버린다.

## 4. 타겟

- **1차 (단일)**: 2~10인 팀 테크리드 — CLAUDE.md를 git으로 유지 중, AI 도구 월 $150~300. 트리거: 에이전트의 결정 망각 / 낡은 전제 확신 / 반복 온보딩. 공식 답: **CLAUDE.md는 대체가 아니라 흡수** (원본은 슬림 포인터로 잔존, 진실원 이원화는 lint 에러).
- **2차 (게이트 뒤)**: 같은 팀 질문자 — "답 배달" 흐름, Investigate first.
- **데모 자산**: OSS 기여자 시나리오 (타겟 아님 — Slice 4 플래그십 데모).
- **명시 제외**: 1인 개발자(통증 약함, 무료로 품기만) · 엔터프라이즈(v1.5 대기열) · 변호사/no-code.
- **매직 모먼트 (북극성)**: "흡수 직후 에이전트가 vault 노드를 인용하며 아키텍처 질문에 정확히 답하는 첫 순간" — 도달 ≤5분, 도달률 계측.
- cohort profile: 부록 D (Slice 0 통과 후 실측으로 대체).

## 5. 가치 제안과 해자

> **"코드가 말해줄 수 없는 것을 지키는, 스스로 신선도를 증명하는 프로젝트 기억."**
> 랜딩: "CLAUDE.md 300줄, 아직도 손으로 고치세요?" · 포지셔닝: "AI가 알아서"의 정반대 — "당신이 제어하는, 검증되는 기억".

**10x**: "에이전트 신규 작업 진입 시간" — Slice 1에서 대조 실험 실측 (10 repo × 3 시나리오 × 4회 중앙값). 실측치로만 말한다 (3배 미만이면 10x 문구 전면 철회 — kill criteria).

**해자 5층**: ① git-원자성 (구조적) ② 개방 포맷 + 운영 레이어 고착 (Obsidian 패턴) ③ 포맷 표준 선점 (Spec — 공백 시장) ④ 커뮤니티 콘텐츠 네트워크 (Hub — 서버 없는 네트워크) ⑤ 좌표 레이어 (Sync — 수익과 전환비용).

## 6. 운영 기판 (기록 → 게이트 → 액션)

| 단계 | 메커니즘 | 노력 | 시점 |
|---|---|---|---|
| 1 | **Decision Gate** — `kind: decision` 노드와 충돌하는 PR을 pre-commit이 경고 | S | Slice 1 |
| 2 | **Fitness Hook** — import 트리 vs vault 관계 대조, 위반 시 "vault 먼저" | M | Slice 2 |
| 3 | **Scaffolder** — element 노드 → 보일러플레이트 생성 | M | v2 |

의도·정책은 `kind: decision` / not-to-break 제약 노드로 1급화. forward-deployed: 디자인 파트너 3팀에 창업자 임베드, 운영 변화(게이트 발동·리뷰 시간) 공개 기록.

## 7. 신뢰 아키텍처

- **승인 3계층**: [자동: 추가·오타·경로 재확인] / [샘플: 내용 갱신, 20% 무작위 정밀 검토] / [강제: 삭제·관계·decision 노드]. rubber-stamp 탐지 (무편집 연속 승인 >30% 경고), 오염 회귀 CI 상설 (거짓 기억 주입 → 격리 확인), 승인 부담 ≤5분/주.
- **인젝션 방어**: vault body = untrusted data. Tier 1 (ship 조건): `<untrusted_vault_content>` 래핑·tool description 보간 금지·YAML safe_load + 패턴 스캔·쓰기는 승인 계층 뒤. Tier 2 (6주): 구조화 응답 + provenance + adversarial 3종 CI. Tier 3 (분기): taint 게이트·red-team 공개. Hub 등재 vault도 동일 CI.
- **show me the prompt**: 에이전트 제안의 근거 diff·프롬프트 상시 공개.
- **SessionStart 계약**: <500ms SLA · 주입 ≤5KB · 초과 시 파일-only fallback. MCP Tier 1 코어 10개만 기본 노출, Tier 2 호출 <5% 계측 → Slice 1 후 통폐합(삭제) 결정.

## 8. LLM 통합

기본 = MCP 역방향 (사용자의 기존 Claude Code/Desktop 구독이 뇌). 추가 = opt-in Q&A (BYOK keychain / localhost 로컬 모델), 그래프 순회 grounding + 근거 노드 강제, 전송 범위 UI + 로컬 감사 로그. 크레딧 번들 금지.

## 9. 로드맵 — 코어 트랙 + 네트워크 트랙

**표면 원칙**: Slice 0+1 = CLI+MCP만. 웹은 Slice 2, macOS 증명은 Slice 2 ship 게이트. Slice 0·1 통과 전 Slice 2/3/4 동결.

**코어 트랙**
- **Slice 0 — 흡수** (Build and verify): CLAUDE.md/AGENTS.md → typed 노드 흡수 도구 (단일 스파인) + `init --quick-start` + 인젝션 Tier 1 + 매직 모먼트 계측. 검증: 테크리드 3명 — 무수정 수용 ≥70% AND 수동 편집 ≤10분 AND 시간 절감 진술 AND adversarial 통과 AND 모먼트 ≤5분.
- **Slice 1 — 신선도** (Build and verify): drift 감지 + 승인 3계층 + Decision Gate + 10x 실측 + dbt 테스트 케이스 (kind 레지스트리 부채 노출).
- **Slice 2 — 그래프를 도구로** (Shape a slice): topology-map-v2 strangler 재구축 (기판정 6페이즈, Sigma v3 유지, WebGL 저알파 불변식) + Fitness Hook + 신선도 오버레이. kill: "그래프가 실제 결정을 바꾼 사례" 관찰 실패 시. ship 게이트 = 설치 macOS 앱 검증.
- **Slice 3 — 답 배달** (Investigate first): 개발자 5명 자발 생성 관찰 + 거절 사유 3분류 + 2주.
- **Slice 4 — 확산** (Shape a slice): 빌드-인-퍼블릭 격주 블로그 + 0-click 브라우저 플레이그라운드 + OSS 갤러리 + 기여자 에이전트 데모 + 보안 투명성 포스트. 지표: 베타 팀 3곳 (정직 명명).

**네트워크 트랙**
- **N0 (지금, 2주)**: SPEC v1.0 RFC (기존 schema·계약 테스트의 문서 승격) + 자체 준수 증명.
- **N1 (Slice 0 후, 3주)**: Hub 부트스트랩 (GitHub org + 갤러리 + CI Action + 시드 vault 5종). npm 발행은 소유자 명시 승인 후.
- **N2 (Slice 1 증거 후)**: 벤더 승인 타진, 커뮤니티 vault 10개 목표.
- **N3 (파트너 2팀+ 협업 수요 시)**: Team Sync 좌표 모델 — **셀프호스트 가능한 오픈소스로 배포** (과금 없음 — 소유자 결정 2026-07-17: 판매 목적 아님, 순수 OSS + 로컬 실행 모델. 후원은 GitHub Sponsors만 선택적).

**첫 100명 90일** (주 10h): 월1 디자인 파트너 5명 (Cursor Discord·r/devtools·X DM + 월 1회 관찰 콜) → 월2 커뮤니티 웨지 + 플레이그라운드 → 월3 Show HN + 추천 루프.

## 10. Non-goals

비개발자 유지자 기능 · 헌장 위반 클라우드 (백엔드·계정·조용한 수집) · 배제 세그먼트 · 새 시각화 엔진 · 크레딧 번들 AI · **과금·유료 티어 일체 (소유자 결정: 판매 목적 아님 — 순수 OSS·셀프호스트)** · 전사 스케일 (v2 문서화만) · kind 선행 리팩터 (dbt 케이스 진입 시) · 벤처식 성장 해킹.

## 11. Kill Criteria

| 가정 | STOP 조건 | 실패 시 |
|---|---|---|
| 흡수 수용 ≥70% | 3명 관찰 <50% | 대화형 마이그레이션 마법사 전환 |
| 부트스트랩 정확도 ≥70% | <50% | 자동 부트스트랩 폐기 → 수동 시드 |
| drift 승인 ≤5분/주 | 2주 dogfood >15분/주 | Slice 1 STOP·재설계 |
| 샘플 검증 신뢰 | 오류율 >10% OR 무편집 연속 >30% | Slice 1 STOP·검증 재설계 |
| 인젝션 방어 | adversarial 주입에 에이전트 추종 | Slice 0 ship 금지 |
| 10x 실측 | 3배 미만 | "10x" 문구 전면 철회 |
| 매직 모먼트 | 파트너 5명 중 도달률 <50% | 확산 활동 중단·온보딩 재설계 |
| 답 배달 | 자발 생성 0/5 + '불필요' 다수 | 2차 페르소나 v1 non-goal |
| Spec 관심 | RFC 8주 피드백 0건 | 표준화 동결·코어 전념 |
| Hub cold-start | 6개월 외부 vault <10 | Hub → 갤러리 격하 |
| Sync 수요 | 협업 요구 0팀 (Slice 2 시점) | N3 무기 연기 |
| 신뢰 헌장 | 위반 필요한 설계 발견 | 해당 기능 폐기 |
| OSS 베타 | 4개월 0곳 | 채널 재설계 |

## 12. 알려진 상한과 리스크 (정직 선언)

- 렌즈 상한: 윌리슨 보안축 ~8 (인젝션 산업 미해결 — 완전 해법을 주장하지 않는다) · 카프 ~8.3 (solo 구조 상한). 이는 결함이 아니라 범위 선언.

## 부록 B — 보도자료 초안 + 하드 FAQ (working backwards)

### 보도자료 (Slice 1 완료 시점 가정, 고객 언어)

> **"우리 팀 AI 에이전트가 어제의 결정을 오늘도 기억한다 — 설명 없이."**
> 6인 핀테크 팀의 테크리드는 매주 월요일마다 같은 일을 했다: 새 에이전트 세션에 아키텍처를 다시 설명하고, 300줄 CLAUDE.md에서 낡은 줄을 찾아 고치는 일. Ontology Atlas 도입 후 첫 주, 그의 팀은 `init` 한 줄로 CLAUDE.md를 검증 가능한 지식 노드로 바꿨다. "에이전트에게 '결제 모듈 바꾸면 뭐가 깨져?'라고 물었더니, 근거 문서를 인용하면서 정확히 답했어요. 5분 만에요." 이제 문서가 낡으면 도구가 먼저 알려준다 — 매주 월요일의 30분 설명이 0분이 됐고, 에이전트가 낡은 전제로 코드를 고치는 사고는 지난 한 달간 0건이다. 설치는 무료, 데이터는 전부 팀의 git 저장소 안에만 있다.

### 하드 FAQ (one-way door 정책 포함)

- **Q. 내 CLAUDE.md와 vault가 어긋나면 누가 이기나?** A. **원본 충돌 해결 정책 (one-way door 확정)**: CLAUDE.md는 흡수 후 "슬림 포인터 + 사람 전용 메모"로 남고, 구조화된 사실의 진실원은 vault다. 충돌 감지 시 도구는 vault 기준으로 CLAUDE.md 갱신 diff를 제안하고, 역방향(사람이 CLAUDE.md 수정)은 다음 sync 때 vault에 흡수 제안된다. 진실원 이원화는 lint 에러로 차단.
- **Q. 팀 협업·접근 제어는?** A. v1은 git이 곧 협업(브랜치·PR·리뷰). "권한 분리·감사 로그" 요구가 파트너 2팀 이상에서 나오면 v1.5 분기 — 그때도 신뢰 헌장 안에서만.
- **Q. 에이전트가 vault를 오염시키면?** A. 승인 3계층 + 오염 회귀 CI + 샘플 오류율 공개(§7). 샘플링을 통과한 오염 사례는 이슈로 공개한다.
- **Q. 이 포맷에 갇히는 것 아닌가?** A. 전부 평문 마크다운 — 어느 에디터로도 열리고 언제든 들고 떠난다. 남는 이유는 잠금이 아니라 검증 이력의 가치여야 한다는 게 설계 원칙.

## 부록 D — Layer 2 보도자료 + cohort profile

### Layer 2 보도자료 (Team Sync 수요 게이트 발화 시점 가정)

> **"우리 팀 셋이 같은 지도를 본다 — 서버에 코드 한 줄 안 올리고."**
> 8인 커머스 팀은 repo 3개에 흩어진 아키텍처를 놓고 매번 "그건 B repo 얘기죠"를 반복했다. Atlas Team Sync를 켠 날, 세 repo의 온톨로지가 하나의 지도로 연결됐다 — 코드와 문서는 각 팀의 git에 그대로 남고, 중앙에는 "무엇이 무엇과 연결되는지"의 색인만 오간다. "보안 검토가 하루 만에 끝났어요. 서버가 우리 내용을 못 보니까요." 신입 개발자는 첫날 오후에 세 repo의 영향 관계를 에이전트에게 물어 답을 받았다.
