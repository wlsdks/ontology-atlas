**Observed**: A planted non-UTF-8 archive filename failed during `fs::write` on macOS with `Illegal byte sequence` (OS code 92), before the history reader ran. `archive-safety-green.log` recorded 11 passing tests and this one fixture failure. The unsupported fixture assertion was removed; the unchanged reader still rejects non-UTF-8 names when the filesystem supplies them.
**Cost**: One targeted native test round; elapsed fixture generation about one second. No CI round.
**Suspected cause**: The host filesystem enforces filename encoding before the application can observe this planted input.
**Proposed change**: none. Treat an input rejected by the host as an unperformed application probe, and use a compatible platform when that boundary is changed. Do not label fixture creation failure as a demonstrated reader refusal.
