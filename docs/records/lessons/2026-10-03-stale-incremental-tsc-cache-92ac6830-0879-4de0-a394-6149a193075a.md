**Observed**: on the flat-dial slice worktrees (2026-10-03), `node_modules/.bin/tsc --noEmit` printed nothing while sibling files were broken by a `dial/types.ts` change; `node_modules/.bin/tsc --noEmit --incremental false` on the same tree listed the errors. A slice reported "typecheck clean" from the first form.
**Cost**: one merge round of the flat-dial branch re-run after the false green; about 30 minutes.
**Suspected cause**: the root `tsconfig.json` sets `incremental`, and a worktree created from another checkout reuses a `tsconfig.tsbuildinfo` whose recorded hashes match files that later changed through merges.
**Proposed change**: script, `pnpm typecheck` (and any agent brief) passes `--incremental false` or writes the build info under a per-worktree path, so a reused cache cannot print a green.
