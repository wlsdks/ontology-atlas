## 2026-11-25 — Work status shows the name Claude Code gives each session

**Why**: The owner, 2026-11-25: "showing the name is allowed". Several Claude Code sessions in one checkout read as "Claude Code 1 · Claude Code 2" with one state, so a room cannot say which one waits, and a number matches no window. Read that day (Claude Code 2.1.332, five sessions): every entry had a `name`; four were the folder's name plus a short suffix, one a twelve-character title in Korean.
**Prior**: Amends `docs/records/decisions/2026-11-23-work-status-session-list-no-network-929c2179-7882-4c40-a4bc-83cfbb2612cf.md`: `name` is read; `sessionId` and `id` are still never read; the call, its sandbox, its pace and the join stand.
**Decision**: While the session-list read and a second switch, Show session names (on by default), are both on, Rust reads `name` when it is a string, removes control and direction-override characters, keeps one line of at most 60 characters, and returns it on that session's row. It is held with the last list and dropped with it, or at once when either switch goes off. The page holds it in view state only and draws it as plain text. It reaches no file, log, error text, storage, URL, command argument, agent session or network. A session without a name stays "{tool} {number}".
**Dissent**: A name can be a title Claude Code wrote from the conversation, so it can show what the person asked on a shared screen; the first line of a question stays refused, and a generated title is close to it. A default name only repeats the folder.
**Falsifier**: A name in a log, file, storage key, URL, command argument or line sent to an agent; a name on screen after its switch went off; a `sessionId` or `id` in any value; the owner turning names off within a week.
