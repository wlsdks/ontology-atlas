## 2026-09-13 — Reuse successful required CI only for the identical merged Git tree

**Why**: A ready PR passed required CI, then its identical squash-merged main tree repeated the same expensive suites.
**Prior**: The 2026-09-13 independent-worktree-records decision stands; this narrows only redundant main-push execution.
**Decision**: Reuse only a uniquely associated merged PR whose head tree equals the pushed tree and whose latest live required checks all succeeded under GitHub Actions. Read protection policy from GitHub; incomplete data, rulesets, failed checks, direct pushes and unknown paths retain normal CI. Recheck the calendar-sensitive PO pilot without installation. Daily, manual, merge-group and PR evidence remain active.
**Dissent**: Equal source trees do not prove fresh infrastructure or external services. Keep scheduled/manual exhaustive verification and bounded online registry checks; never use a persistent local success cache.
**Falsifier**: An unreviewed or different tree skips evidence, an API failure produces reuse, or the calendar-sensitive pilot can be bypassed.
