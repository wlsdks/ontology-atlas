## 2026-10-02 — The map draws a folder while it is still being read

**Why**: the owner asked on 2026-10-02 that a folder stop arriving all at once; at 120 ms per native answer a 10,000-document vault showed nothing for 77.7 s.
**Prior**: narrows the rule in `docs/ARCHITECTURE.md`, "Vault mode", item 7: destination content commits only after one local manifest is ready. That rule now holds for every destination, write, check and count except the map, which draws the arriving part while `status` is still `loading`.
**Decision**: reads go project, `domains/`, `capabilities/`, `elements/`, then the rest. In a folder of 400+ documents, after 0.2 s, what has arrived is published at most once a second. Only the map draws a part: documents only, the overview framed, marks gliding up to 2,000 documents (`ARRIVAL_GLIDE_CONCEPT_CEILING`) and landing without travel above it. The first part drops the previous folder; writes wait for the whole folder. The app reads 64 Markdown files per call. The finished manifest equals a build that publishes nothing.
**Dissent**: a vault that ignores the folder convention gets quarters of one flat folder instead of a domain-first reveal, and every publish rebuilds the map's world, so a slow read of a huge vault spends more main-thread time in total than one build would.
**Falsifier**: a person reads a partial map as the finished one (a missing node reported as absent, a check run on part of a folder), or a mark is seen to jump while documents arrive; then hold the map until the capabilities have arrived and publish nothing earlier.
