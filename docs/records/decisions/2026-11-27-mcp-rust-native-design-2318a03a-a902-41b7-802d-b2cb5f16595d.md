## 2026-11-27 — The Rust MCP server is designed in Rust, not translated, and reaches main in one merge

**Why**: The owner asked that the Rust server be built the way Rust is written, not by following the JavaScript, that well-known current libraries may be adopted, that equal answers are the lead's to judge, and that the whole port land at once after every check, with no soak period.
**Prior**: Narrows 6c76a2d9 "The MCP server is ported to Rust behind a differential harness": its "function-for-function port", its byte-equal-only rule and its beta-then-stable cut-over are replaced; its surface, safety-first order, harness, `'en'` order, no-worse gate and deletion stand.
**Decision**: `docs/specs/2026-11-27-mcp-server-in-rust.md`. Decided by the lead. Each family is designed in Rust idiom; the JavaScript is a behaviour reference, never a structure. Tool names, schemas, instructions, answer shapes and error codes stay compatible; an answer may differ only as an entry in the spec's declared behaviour changes (tool, field, before, after, why), checked by the harness per request id and path and summarised in the change record; bytes written to disk are never declared. Crates as the spec lists: a hand-written stdio loop, threads and rayon without tokio, typed serde_json answers, Atlas's own frontmatter parser, tree-sitter with MIT grammars, the person's git. An eighth crate `answer-format` owns JavaScript-compatible text; `source-evidence` splits into `source-scan` and `repository-survey`. All slices meet in `integration/mcp-rust-2026-11-27`, and it merges to main once, deleting the JavaScript, Bun and the LGPL notice.
**Dissent**: One merge concentrates risk in a large branch while main moves; declared changes can grow into a rewrite by another name; tree-sitter grammars cost program size.
**Falsifier**: An undeclared difference reaches a release; the declared list outgrows 30 entries; the program exceeds the Bun binary's size; or the 14-day drift rule fires.
