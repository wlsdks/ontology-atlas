## 2026-09-27 — The web page carries its own policy, opens only inert sources, and pins what the catalogue runs

**Why**: security review: the web build should give folder content no path to run in the site's origin or to reach outside hosts on its own, and a catalogue line should run the program that was checked.
**Prior**: keeps 2026-07-27 "web and app do not promise identical screens" (one build) and the 2026-09-07 committed catalogue; the app's `tauri.conf.json` policy is unchanged.
**Decision**: the production export carries a meta CSP (no remote image, connection, plugin, base or form target; inline scripts until hashed), allowing everything the app's policy does so the app is never narrowed; the browser opens a copy only of PDF, raster images and plain text, rewrapped by extension, and saves the rest; a remote image stays a placeholder naming its host; each catalogue program is pinned to the release current on its check date, an image by digest.
**Dissent**: `script-src 'unsafe-inline'` leaves inline injection unblocked until the export's inline scripts are hashed; the meta follows Next's own same-origin chunks in `<head>`, which load before it applies.
**Falsifier**: a policy violation on a shipped destination; the app losing IPC or an image under the meta; a `.html` or `.svg` source opening in the site's origin; a remote image requested while reading; a catalogue line without a version.
**Owner**: Stark (proposed in the pull request that lands it; landing it accepts this record)
