## 2026-11-24 — In a running chat turn, an in-app agent reads a file of the vault's connected code folder without a card

**Why**: A person who connected a code folder and asked an in-app agent about it got one "allow once" card per file the agent opened outside the vault, and named it the reason a conversation could not go on. Every such card was a read they always allowed.
**Prior**: Overturns in part 2026-08-16 (2) §3 ("inside the vault auto-allow, outside ask"): one place outside, the bound code folder, now passes file reads. Keeps 2026-09-01 "Inside-the-vault auto-allow narrows to read-only tool kinds" and goes narrower than it here: kind `read` only, never `search`. Keeps 2026-09-17 `0e82da66` (a Library round rejects anything outside its scope and names it in the pass ledger): the round's own rule runs first and its refusal wins. Reuses the root, grant and hidden-folder checks of 2026-10-17 `e35a25fe`. 2026-11-16 standing approval still covers vault edits only.
**Decision**: Rust answers a new verdict, `allow-inside-code-folder`, only when the vault verdict is `ask` and the path, unpadded and free of control or format characters, is an existing regular file after links resolve, inside the code folder of the vault's one project binding as `authorized_source_root` grants it. No component below that root may start with `.`, end in `.git`, match Harness's secret names, or hold a secret fragment (`secret`, `credential`, `password`, `apikey`, `id_rsa`, `tfstate`, `kubeconfig` and the like); the file name may not hold the word `env`, `token`, `key` or `private`. The app then selects `allow_once` without a card only inside a running turn, after the surface's own rule (`autoDecide`) has answered nothing, for a non-Atlas tool of kind `read` whose every string argument is that one path. A search, a folder, a missing file, an edit, a command, an unknown kind, a request outside a turn and any other path still ask, and `allow_always` is never chosen. What the agent reads goes to its own provider as before; the card no longer precedes it. Codex reads arrive as commands (`execute`), so this changes Claude Agent chats only.
**Dissent**: Passing searches as well would remove more cards. It lost: a Claude Glob takes its folder from an absolute `pattern` the path verdict never sees, so a search judged on `path` can list any folder, the code folder's `.git` included. A positive list of source extensions would be stricter than the name rules; it lost because it asks about every README, manifest and config a code question needs, and the name rules fail closed on the rest.
**Falsifier**: A dot file, a `*.git` folder, a secret-looking name, a file reached through a link that leaves the code folder or lands on such a file, a padded path, a folder, a search, a request of a Library round, or a file of an unbound folder reads without a card; or people still abandon code-folder conversations because of read cards, in which case searches need their own ruling with the pattern judged too.
