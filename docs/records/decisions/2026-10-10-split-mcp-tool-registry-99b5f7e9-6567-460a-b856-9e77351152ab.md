## 2026-10-10 — Split the MCP tool table into per-family files

**Why**: `mcp/src/server/registry.mjs` was 4,934 lines, most of it the 40 tool definitions, so changing one tool meant paging through the whole table. The definitions now sit in `mcp/src/server/tool-definitions/`, grouped like the handlers in `mcp/src/tools/`, and `TOOLS` in the registry lists them in the old order. This change trips the gate only because it moves the whole public contract between files.
**Prior**: None. It keeps the contract defined by the registry intact: tools/list output, order, annotations and the read-only and profile filtering did not change.
**Decision**: Definitions moved verbatim into named exports, one file per family, one file per large tool. Probe: `JSON.stringify` of `TOOLS_FOR_LIST`, the `TOOL_BY_NAME` entries, `READ_TOOL_NAMES` and both modes, plus the stdio `tools/list` response, were byte-identical before and after in the default, `OATLAS_READ_ONLY=1` and `OATLAS_TOOL_PROFILE=construction` environments. `scripts/check-decision-record.mjs` now watches every file under `mcp/src/server/tool-definitions/` as well as `registry.mjs`, so a description change in a family file still needs a record.
**Dissent**: A tool's schema is now one import away from the table that publishes it, so a reader can no longer see order, annotations and schema in one file. The registry table of contents and the per-file tool names carry that navigation.
**Falsifier**: A tools/list byte difference appears between this split and the previous registry, or a change to a family file lands without a decision record.
**Owner**: The lead agent's brief for this change, 2026-10-10; the repository owner has not ruled on it.
