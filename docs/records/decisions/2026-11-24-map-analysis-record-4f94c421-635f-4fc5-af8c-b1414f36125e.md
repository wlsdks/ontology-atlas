## 2026-11-24 — The MCP server keeps one line per agent session in `.ontology-atlas/map-analysis.jsonl`, and the map reads it

**Why**: The map showed a share with no date, no count of analyses and no word on who mapped it; the owner could not tell a fresh map from a stale one.
**Prior**: Extends 2026-11-23 `f7ea68cd`: a line records that count, the one `validate_vault` gives. Extends `a24bde01`: a press names its requests as one analysis; its "nothing is persisted" still holds for the run's state.
**Decision**: After a concept write, the server appends one line of counts: version, analysis and session ids, number, origin, start and last times, agent name, commit and dirty flag, abilities and areas off the map, concepts added, changed, removed. A press's requests share one analysis; any other session is one, split after 60 idle minutes. A read-only session writes nothing. A failed append never fails the write. The app only reads the last 1 MiB. Counts only: no path, file name, title or code.
**Dissent**: Git leaves the file out, so the record does not follow the map to a clone or a worktree; one tracked file per analysis would.
**Falsifier**: A line holding a path, file name or code; a write that failed because the append failed; the app writing the file; a count that differs from `validate_vault` at that moment; a session that wrote nothing listed as an analysis.
**Owner**: Stark
