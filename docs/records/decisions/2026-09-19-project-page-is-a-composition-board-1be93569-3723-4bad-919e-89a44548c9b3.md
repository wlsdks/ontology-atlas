## 2026-09-19 — The project page is a composition board, not a document reader

**Why**: The owner, reading a project page: the overview is too long and does not need to be shown whole, the page is unattractive, and what a project page is for is showing how much ontology, harness and library is built inside it, fast enough to choose from. The page instead opened with the whole document, said its figures twice (hero chips and nothing else), and drew three controls at three weights in one row.
**Prior**: 2026-09-15 "Projects stays a compact index" governs the list and is untouched. 2026-09-19 "The project overview is a brief the agent lays out" stands for the document; what changes is how much of that document this page draws.
**Decision**: The page leads with a composition board, one cell per Atlas surface: ontology (this project's domains, capabilities, elements, and how connected it is), Library (the folder's sources and wiki pages), Harness (what it holds, and its door). Each cell states only what its surface can honestly answer from here, and a cell with no honest figure shows none. The domain rows keep the detail below it, the document is summarised to its opening paragraph plus a contents line of its section titles, and the two tabs are gone. One agent card, in the rail.
**Dissent**: none recorded. The nearest objection is that the harness cell carries no number and so reads as weaker than its neighbours; the reply is that the harness is read from a source tree the browser has no path to, and a fabricated count is worse than a named door.
**Falsifier**: a person who cannot tell which figures are this project's and which are the folder's, or who opens the page to read the write-up and cannot find it. Then the scope caption becomes per-cell and the document returns to the page.
**Owner**: the owner (2026-09-19 instruction); applied by Claude.
