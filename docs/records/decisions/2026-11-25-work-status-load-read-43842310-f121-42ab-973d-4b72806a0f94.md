## 2026-11-25 — Work status reads memory and CPU of agent command trees and this Mac's load

**Why**: The owner, 2026-11-25: show load per worktree and, where it can be shown, Gradle, CPU and GPU use, within the license policy. On 2026-11-21 the owner had asked which work makes the Mac slow.
**Prior**: Extends `docs/records/decisions/2026-11-22-work-status-agent-processes-87d3ada9-4740-430a-8cee-a580ce7e638e.md` by fields it requires a record for; arguments, environment and open files stay unread. Pulls the load read of slice 12 in `docs/specs/2026-11-22-work-status-coordination.md` forward, read only.
**Decision**: macOS only, every 5 s while Work status is visible and its load switch (on by default) is on. For each of the person's processes under an agent program: memory, CPU time and kernel name, the name matched to a closed list of tool groups and any other counted as other; it counts for the worktree its own working folder lies in, else its nearest ancestor's. For a process named `java` outside every tree: memory and working folder, to place a Gradle daemon. For the Mac: memory in use and macOS's pressure level, CPU in use, and the GPU's "Device Utilization %" from the IOKit registry. The page gets per-worktree totals and every group with a process there, and shows the five largest; never a path, a command line, a name off the list or a new pid. System APIs through crates already in `Cargo.lock`: no new crate, no spawned program, no root.
**Dissent**: macOS names no process for GPU use without root, so the GPU figure is the whole Mac's. Without arguments `node` cannot be told into Vitest or Playwright, and a Gradle daemon is named only if its folder gives it away. A load monitor is far from a codebase ontology.
**Falsifier**: An argument or environment value read; a path or unlisted name in a payload; a sample that spawns a program, or reads usage for a process outside the agent trees other than `java`; over 1 % of one core with 40 worktrees; a crate added to `Cargo.lock`.
