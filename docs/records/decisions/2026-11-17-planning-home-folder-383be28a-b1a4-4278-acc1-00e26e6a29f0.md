## 2026-11-17 — Planning writes in a home folder inside the open folder
**Why**: A new person has no planning folder to pick, the picked folder is forgotten on every launch, and the owner asked Atlas to make the folder inside the opened folder, as it does for the ontology, and to let people write documents there.
**Prior**: Narrows docs/records/decisions/2026-11-01-planning-folder-reader-bf766fb3-87b3-449e-ae69-5bb0ce46c1f2.md to "a folder the person picks": that folder keeps its session-only, read-only, macOS-only grant through the native picker, unchanged.
**Decision**: Planning gains a home folder, `planning/` directly inside the opened ontology folder, read and written through the existing folder grant (the app's folder handle and the browser's File System Access handle); no native command, permission or Rust change. A loaded folder with `planning/` opens it on arrival; without one the stage offers to create it, with picking another folder as the second, app-only door. The home scan lists the picked scan's file types and skips dot entries and the same build folders, but it does not refuse a Markdown name for secret-looking words such as "token" or "password": the vault session already reads every Markdown file of the opened folder, and refusing would hide a document the person just titled. Images keep the secret-word rule. Unlike the picked scan, it lists hard-linked files, and in the app symbolic links are dropped by the folder listing without being counted. A document is identified by the first 32 hex characters of its SHA-256. New documents are named in NFC, compared with existing names ignoring case and Unicode composition, and never written over an existing file. Edit is offered only when the text re-encodes to the same bytes (UTF-8), and CRLF files are saved in CRLF. Save compares the bytes on disk with the identity the editor opened and then writes, in two steps, so an outside write landing between them is overwritten; closing that window needs a native compare-and-write, which is out of scope. On the web the 16 MiB read bound is checked from the file size before reading; in the app the folder listing carries no size, so the bound is applied after the bytes are read. Unsaved editor text is kept in memory across screens and folder switches, with a leave warning on reload or quit; quitting after that warning loses it, and nothing is written to disk or browser storage. Markdown under `planning/` carries no `kind:`. The vault loader still parses it like any other Markdown in the folder, so it is a document in the folder's file list, and it becomes a concept if a person types a `kind:` frontmatter into it; that is the folder's general rule and is not prevented here. Planning marks its own writes so the folder-change notice does not report them.
**Dissent**: Writing inside the ontology folder mixes planning prose with the meaning graph's files and puts both under the same Git history; a separate folder would keep them apart. The owner chose one folder people already opened over a second grant to remember.
**Falsifier**: Revisit if a planning document without a `kind:` appears as a map concept, a write lands outside `planning/`, a save overwrites an outside change in practice, or a person cannot tell which folder Planning can write to.
**Owner**: The project owner asked for the home folder; the implementation was delegated, with the lead reviewing before merge.
