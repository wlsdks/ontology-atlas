## 2026-09-15 — Save named constellations as shared task scopes over existing concepts

**Why**: The owner wanted to keep a meaningful group of Galaxy stars for later human and agent work. Existing pins and recent walks could not preserve a named purpose and stable membership across those surfaces.
**Prior**: The 2026-09-15 Galaxy three-arm ontology sky decision (`2026-09-15-galaxy-three-arm-ontology-sky-c20717d0-2ec0-4a00-8eda-42f86250092f.md`) remains standing: only actual concepts and relations carry ontology meaning; Galaxy retains its own stable layout.
**Decision**: Store constellations as root folders with optional constellation presentation and purpose in the compatible vault-local library-collections/v1 folders/items sidecar. Resolve ontology members only through unique primary or merged UID claims, keeping missing members visible. Use a compact Galaxy list, centered dimmed editor and reversible focus, with the same records in Library Collections and read-only MCP/CLI. Membership never creates a graph edge or certifies meaning acceptance or complete impact. Agent preparation freezes the shown membership, purpose and version; sending remains an explicit existing action.
**Dissent**: A separate constellation node kind or a disconnected visual-only bookmark store could simplify one surface, but would duplicate meaning or prevent the next agent from recovering the same scope. Those alternatives are not selected.
**Falsifier**: Reopen this choice if a saved scope resolves a replaced UID by name/path, silently changes prepared membership, creates a relation from membership alone, or cannot be recovered by a fresh agent with its saved ID.
**Owner**: Atlas product owner; Astra accountable for design and proof, Sol for implementation.
