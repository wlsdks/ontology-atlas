## 2026-10-14 — Group the CLI command runners and libraries by responsibility

**Why**: `cli/src/commands/` held 78 files and `cli/src/lib/` 77 directly, so finding the runner for one command meant scanning a flat list. Commands now sit in eight folders and lib in seven, by what they do. The gate fires only because `cli/src/lib/cli-commands.mjs` changed the runner import paths.
**Prior**: 2026-08-30 "The CLI executes the MCP modules instead of copying them" and 2026-09-04 "A CLI exit code says whether the input could be answered" stand untouched: no command, flag, exit code or output changes. 2026-10-11 "Split the MCP tool schema fragments by subject" set the pattern followed here: move verbatim, no barrel, importers name the owning file.
**Decision**: Runners and libraries moved verbatim; the registry loads each runner by its `group/file.mjs` path. The 61 command names and the 14,312-byte `--help` output were identical before and after the move, and the CLI integration suite (318) and node tests (391) pass.
**Dissent**: A flat folder keeps one `ls` for every command; answered by the registry, which names every command and its runner in one file, not by a re-export barrel.
**Falsifier**: A command name, flag, exit code or `--help` byte differs from the previous layout, or a published entry point no longer resolves a runner.
**Owner**: Project owner; asked on 2026-10-14 to split every folder that needs it and to group what can be grouped.
