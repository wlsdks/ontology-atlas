## 2026-09-28 — Large MCP answers are bounded by default and name the rest

**Why**: owner, 2026-09-27: keep the MCP server low on memory. At 12k nodes each brief embedded the whole 30 MB `validate_vault` report, a bare `compile_ontology` was 44 MB and an unlimited `find_evidence` 12.8 MB; each is sent twice and sets the server's peak.
**Prior**: extends 2026-08-14 "A large ontology list marks omissions and reads through to the end" (its paging shape) and 2026-08-14 (7) (counts plus a `nextCall`); names every cut as 2026-07-28 did for `cycles`. 2026-08-17 (66) stands.
**Decision**: briefs keep whole-vault counts but carry 20 problem files, 20 drifts and a `validate_vault` `nextCall`; `validate_vault` pages by `offset`/`limit` (default 100); `compile_ontology` answers its summary unless `full: true` or a page argument; `find_evidence` returns 50 unless `limit` says otherwise. `ok()` holds an answer the caller did not size to 128 KiB of text, cutting its longest lists under a declared `truncated`/`truncation` note and correcting their pages. Text and `structuredContent` both stay.
**Dissent**: sending only `structuredContent` halves the wire, but the MCP spec asks for the text and Codex is unconfirmed; 10 brief rows leave more room than 20 (`agent_brief` is 243 KB of a 256 KiB wire budget on the memory fixture).
**Falsifier**: an agent that reads a brief's 20 rows or a cut list as the whole vault, a page walk that loses or repeats a file, or a client that refuses `truncated`.
