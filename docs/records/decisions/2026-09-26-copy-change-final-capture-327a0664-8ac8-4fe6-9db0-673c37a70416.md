## 2026-09-26 — A copy-only change proves itself with one final capture

**Why**: owner, 2026-09-26: the router required the full build-look-correct Computer Use loop (baseline, slices, checkpoints) even when only visible words changed. The Opus 5.5 guidance says scaffolding for visual inputs and extra verification steps should be re-tested, since the model reads screenshots precisely and self-corrects; a copy change has no slices to look at.
**Prior**: narrows 2026-09-01 "Design proof follows the changed failure mode; rendered work is observed while it is built" for the `copy` class only; every other rendered class keeps the loop, motion keeps the recording.
**Decision**: `copy` routes to `final-capture:affected-state` (one fresh Computer Use capture of the state that shows the words, after the change). Combined with any other rendered class the loop wins and the final capture is dropped as redundant. Policy version 2.
**Dissent**: longer words can wrap and move geometry; the class reason already says to add `responsive` then, which brings back the loop and a sweep.
**Falsifier**: a copy-only change that ships clipped, overflowing, or overlapping text the final capture showed or should have shown.
