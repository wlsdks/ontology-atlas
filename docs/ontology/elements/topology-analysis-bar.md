`src/views/home/ui/TopologyAnalysisBar.tsx` is the compact mode switcher shown over `/topology`.

It owns the visible Overview / Focus / Path / Health controls, the small metrics line, the Health stale/orphan/promotion chips, and the first actionable Health inspect target. The bar is reachable on mobile as a stacked control surface, hidden only in the intermediate tablet range where it would collide with the left workspace panel, and returns to the centered desktop overlay at the large breakpoint. When a selected-node drawer is open, the desktop bar reserves the drawer rail so mode actions remain clickable instead of sitting underneath the drawer. Path primer, progress, and result overlays move below that mobile bar while keeping their original desktop position.

Touch target contract: the compact bar keeps its primary mode tabs, Actions summaries, health copy icons, and direct handoff links at a minimum 32px hit target. The topology map still reads as a dense graph workbench, but the actions that move evidence into Claude Code, Codex, `/ontology`, or the builder remain tappable on mobile and precise on desktop.

**(W3 분석 보기 은퇴, 2026-07)** Overview mode's action-panel body was retired — the reader lens (a colored kind-ring legend), the map brief/reanalysis/sync-gate handoff copy, and the relation-provenance/quality/agent-readiness disclosure all lived here and duplicated what the map, INDEX, and insights already show. Each piece moved to a single home instead of staying triplicated:
- the relation-line key (containment spine/terminal vs. quality stroke) moved to `TopologyRelationLegend` — an always-on readout next to `FirstRunReadout` at the map's bottom-right (not gated by overview mode or first-run state, since the map's line encoding needs explaining in every mode);
- the map-brief / reanalysis-command / sync-gate copy actions moved to the INDEX panel footer's "인계"/Handoff menu (`TopologyIndexAgentHandoff`, `src/widgets/topology-index-panel/ui/`);
- the relation-quality-derived agent-readiness gauge moved to `/ontology/insights`' relations tab (`RelationsTab`), the single place readiness is now surfaced — provenance/quality breakdown were dropped rather than duplicated a third time.

Overview mode's floating panel now only shows the mode rail and a single-line prompt ("Start with the product/system map…"), the same skeleton every mode shares; it carries no mode-specific body content of its own any more. The prompt still names the visible counts as ontology `concepts` and `relations` (not legacy project totals) — the collapsed workspace card, the analysis metric row, and the canvas `application` label all keep that same ontology-map language.

When Focus mode has a selected node, the bar first shows the review order: read the concept brief, trace incoming impact, edit or confirm the meaning, then run the sync gate if the review turns into a change. It then exposes a focused review brief plus dedicated concept check, impact, and post-change sync-gate copy actions for that node. The visible labels stay concept-first for planners and reviewers, while the copied packet still carries the exact MCP/CLI proof payloads for agents. It also shows direct `/ontology` and `/ontology/edit` links beside the copy actions, so a focused visual neighborhood can move into browse or builder repair without requiring the user to paste the copied brief first. The review brief includes the selected node, the current topology URL, a focus URL that reopens the same node in Focus mode, `/ontology` and `/ontology/edit` handoff URLs, a read-only `ontology-atlas node <slug> [vault] --limit 12` CLI check, the matching MCP `node_profile` payload, incoming `blast_radius` impact checks, and the shared 14-check runtime graph DB plus health / cycles / growth / maintenance / validate sync sequence. The profile payload is `query_ontology({ operation: "node_profile", slug, depth: 2, limit: 12 })`; the impact payload is `query_ontology({ operation: "blast_radius", slug, depth: 2, direction: "incoming" })`. This lets a focused visual neighborhood become either a collaborator review artifact or an agent-ready node inspection, and it gives the user the same closing gate if that focus review turns into a builder edit.

When Health mode is active, the bar can copy a markdown health evidence brief. The brief includes total issue count, stale/orphan/promotion bucket counts, the first inspect target, the current URL, an inspect URL that reopens `/topology?mode=health` with the target node selected, an `/ontology` browse URL, a builder repair URL for the same target, a kind-specific next action, a read-only `ontology-atlas node <slug> [vault] --limit 12` CLI check, the matching MCP `query_ontology({ operation: "node_profile", slug, depth: 2, limit: 12 })` payload, and incoming impact checks via `ontology-atlas blast-radius <slug> [vault] --depth 2 --direction incoming` plus the MCP `blast_radius` payload. The brief embeds the full shared post-change ontology sync packet under the post-repair sync gate, including run conditions, the 14-check runtime graph DB gate, `health` / `cycles` / `growth_plan` / `maintenance_plan` / `validate_vault` MCP checks, CLI fallbacks, and skip cases. The visible Health target is labeled as the current repair target, then gives the builder repair action a full-width primary row before the health-check copy and concept document exits. That keeps the non-developer next step readable in the narrow rail while still letting Claude Code / Codex inspect the same target without expanding the secondary proof panel. Impact and sync-gate copy actions remain in Actions because they are follow-up checks after the target is understood. The Health panel now shows the same repair order explicitly: inspect the target, repair ownership or source evidence in the builder, then run the shared sync gate. A visual graph-health read can therefore become either a portable review artifact for agents and collaborators or a focused MCP handoff payload.

Focus mode uses the same rule for its selected-node review brief. The copied brief keeps the topology / ontology / builder URLs and concept / blast-radius checks readable for humans, then embeds the full sync packet instead of a one-line shorthand so the same artifact can be pasted directly into Claude Code / Codex after a non-trivial concept or frontmatter change.

It names the current analysis mode, shows a short next-action prompt, and keeps node / relation / issue metrics visible without expanding the heavier Sigma controls panel. Its Path prompt uses the same source-click then target-click workflow as the Sigma-side primer. When `pathFrom` and `pathTo` are already present in URL state, the bar resolves both graph IDs into readable titles and states the completed source-target route instead of asking for another target. The resolved Path state now exposes a compact proof-order panel, a compact path evidence copy action, and direct proof copy actions for agent path checks, schema-aware relation checks, relation explanation, bounded path planning, and bounded path execution next to source / target handoff links into `/ontology` and `/ontology/edit`. The proof-order panel now includes a visible checklist in human review language: the visible path is a ready clue, relation direction, connection explanation, and alternate paths must be checked before using the route as write evidence, and sync after edits is marked as after-write work. The compact evidence includes the current topology URL, endpoint browse and builder URLs, the CLI path check, MCP `path`, inferred relation preflight reason, MCP `relation_check`, MCP `explain_relation`, bounded `query_plan(all_paths)`, bounded `all_paths`, the all_paths evidence contract, the same proof checklist, and the shared post-write sync gate, so a restored route can move immediately into Claude Code, Codex, collaborator review, or frontmatter-backed repair without relying only on the Sigma banner.

In Health mode, the bar now breaks the issue count into stale, orphan, and promotion chips, then exposes a compact inspect button, an `/ontology` browse link, a builder repair link, and a one-line next action for the first actionable bucket. That makes the graph-health overlay actionable at a glance instead of forcing users to infer every repair class from color alone.
