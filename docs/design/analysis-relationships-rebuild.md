# Analysis relationship and evidence workspace

The owner requested a full redesign after rejecting both an embedded main map
and a tall responsibility/implementation table. Direction B remains selected:
relationships lead and evidence is read beside the selected claim. The discarded
prototypes are process evidence, not approved shapes.

## Product pass

**Prior decision**: the 2026-09-19/20 brief/census hierarchy no longer meets the
owner's intended entry. The bounded DOM structure decision
`dc9455e4-f63c-432b-9e17-eb5e3ad32eb7` supplies a renderer precedent, not proof of
this diagram's usefulness.
**Human loss and moment**: a developer opens Analysis and must discover a useful
question and reconstruct its evidence across unrelated maps and maintenance tabs.
**Atlas outcome**: judge one recorded relationship or implementation claim with
its exact evidence and unknowns in the same view.
**Evidence state**: owner rejection is observed. Graph counts, frontend contracts
and recorded document fields are inspected source facts. Their usefulness beyond
the observed walkthrough remains a product hypothesis.
**Change signals**: rollback-cheap; truth, transfer, agent-write and
human-correction boundaries unchanged. The existing Map editor still owns correction.
**Computed route**: PO solo/two-way/judge, no new authority. Design changes are
information architecture, attention, interaction model, topology encoding,
responsive and journey. The route requires full-surface render-loop, graph
readability, contrast, responsive and journey evidence, then one independent reviewer.
**Recovery proof**: given a loaded ontology, the first viewport shows a recorded
responsibility pair and an exact dependency/document action; fail if a count has
no inspectable witness, a source gap becomes clean or a saved link opens the old board.
**Decision**: build and verify the selected graph/evidence direction. The root
session owns the final independent review and native recording.

## Shape and encodings

The selected responsibility pair owns a 30px canonical hero heading. A compact
comparison rail exposes actual pair counts; it does not compete with the selected
fact. The central graph shows its named concept endpoints and one thin arrow per
exact declaration. Canonical kind glyphs, measured ports, selected frames, explicit
selection text and visible declaration units encode identity, direction and state.
The count-width ribbon prototype was rejected and is retired. Four declarations
are drawn at a time with explicit paging; selection remains visible. A concise
adjacent chain connects the chosen claim, declaring document, structured relation
note, recorded implementation anchors and uninspected source. It does not claim
that an absent relation note means there is no explanation anywhere in the body.

The evidence question exposes named capability choices, with direct continuation
from the selected dependency. It separates real role documents, recorded paths,
document findings and source date evidence. Absent/ambiguous ownership is not
assigned to make the diagram complete. In a scope with no cross-domain
relations, recorded capability evidence is still useful and immediately available.

The page owns vertical scrolling. At wide and guaranteed minimum app widths,
relationship context and evidence share the viewport. Below the narrow content
band, evidence follows the diagram in page flow; it never overlaps controls.
Long disclosures use the page's scroll owner. Supporting records use section tabs,
not a second maintenance navigation row. Existing primitive motion and reduced
motion remain in place; there is no idle diagram animation.

## Boundaries and retirement

The old census, seven ontology tabs, global repair and batch-containment entry,
file-date freshness view and bottom handoff are removed from this screen. The
underlying schema, CLI/MCP maintenance contracts and typed Map correction remain.
A local source inspection is eligible only when the bound code root equals the
vault Git repository root. A separately bound source remains unknown with the
current native API. File-date comparison never accepts meaning.

Saved ontology tab URLs enter the current relationship or evidence question.
Record tabs retain their subjects. Claim correction and document links carry
named return context. Switching sections preserves an ACP draft and never sends it.

## Verification ownership

Pure tests cover direction/deduplication, ambiguous responsibility, real versus
reference-only implementation roles, reversed containment, unchecked findings
and cyclic containment. Source-hook tests cover wrong-root refusal and late
results after same-slug path replacement. Browser journeys cover exact pair
count/witness agreement, keyboard selection, the document continuation, minimum
viewport reachability, legacy links and the actual native probe. Gate probes
remove each protected subject and require a diagnostic, with a nonempty scan.

Captures, logs and static-export evidence are outside Git under
`/tmp/atlas-analysis-astra-rebuild-proof`. Headless captures are layout evidence;
they do not establish native motion smoothness. Final recording and independent
review belong to the coordinating session.

## Ontology sync proposal, not applied

The 2026-09-04 decision "Analysis owns one ACP conversation; Map is an explicit
continuation" keeps browser requests copy-only. Its assumed active-folder
context does not hold for the bundled example or a browser-known folder name
without an absolute root. The sample explanation therefore shows its empty
record state and a folder entry without an executable request. Local explanation
requests require matching `connection_info` and recorded identity anchors first;
unknown browser roots halt before concept reads. This preserves the Atlas-only
tools, twelve full reads including identity checks, citations, explicit Send and
existing archive contracts. Supporting records also name the actual model scope.

`capabilities/ontology-insights` currently defines a maintenance board and names
maintenance-queue elements. Proposed definition: "Compares recorded relationships
between responsibilities and lets a person inspect a selected dependency or
implementation claim alongside its declaring documents and explicit unknowns."
Keep the capability UID and page entry path. Review its four old maintenance
element relations and three dependencies against the retired page imports before
proposing their exact removal or replacement. The new read projection does not
authorize fresh semantic dependencies from imports alone. No vault write or
meaning acceptance is performed by this implementation.
