# Library maintenance across ordered source arrivals — 2026-09-11

An ACP compilation read and cited a newly arrived handbook while leaving the old
statement that the handbook was absent. The revised Compile brief repaired that
failure in a replay from the exact previous file state. It also distinguishes an
explicit approved policy replacement from a draft or an observed configuration.
Originals, a scripted personal correction and a separately retained answer stayed
unchanged throughout the measured updates.

This is a bounded result for the [Library quality program](../plans/LIBRARY-QUALITY-PROGRAM.md),
not a general accuracy guarantee, provider ranking or proof of recurring owner
value. It follows the [source-fidelity comparison](LIBRARY-ACP-SOURCE-FIDELITY-2026-09-11.md)
and tests the accumulation hypothesis from the [community research](LIBRARY-COMMUNITY-2026-09-11.md).

## Frozen baseline

Three short synthetic originals have different roles:

| Original | What it establishes in the provided material |
|---|---|
| Handbook, issued August 2 | Approved routine retention of 31 days; incident-held records separately at 45 days |
| Bulletin, issued September 3, effective September 4 | Explicit approved replacement of routine 31 days with 14; incident-held 45 days unchanged; no implementation or announcement approval proof |
| Bench snapshot, observed September 6 | Unit R2 configured to 31/45 days; migration unconfirmed; a dated observation, not newer policy or proof of subsequent state |

Claude Code and Codex ACP each compiled the corpus in two orders: handbook then
bulletin, and bulletin then handbook. The bench snapshot arrived third in every
case. After the first compilation, the controller inserted the same explicitly
personal workflow constraint into the first wiki page and filed a separate
synthetic retained answer. The note required dated written storage-owner approval
before an external announcement and expressly did not establish such approval.
This simulates an edit; no real owner adoption or approval is inferred from it.

All four three-stage runs completed. Every original retained its bytes. All eight
later-stage transitions kept the exact personal note on its page and the exact
retained-answer file. The source-specific pages linked their evidence, and all
384 baseline source-locator occurrences resolved to valid original paths/lines.
Locator validity did not prevent the stale absence statement.

Six questions were frozen before generation. The key was withheld until all six
reader responses were sealed. Reader conditions were originals plus the personal
note for each provider, and four wiki-only folders from the generated conditions.
Every wiki-only folder contained its four wiki files and an empty `sources/`.
Completed tool output contained each complete supplied wiki body, 16 of 16;
observed reader calls stayed inside those folders and all fixtures stayed unchanged.
This is a provided-file and trace boundary, not operating-system isolation.

The independent source-aware answer audit found the required numeric values,
scope and personal constraint in every answer. Conservative sentence-level
grading marked 34 of 36 cells correct and two partially qualified: two answers
began with “No one” or “Nobody” before explaining that approval was not recorded
in the supplied material. Additional wording sometimes overstated what a dated
configuration observation proved. These are related questions on one small
corpus, not 36 independent replications or a combined product-quality score.

## Failure and repair

The Claude reverse-order bulletin page simultaneously said the handbook had not
been read and had since been read. Its `Not in sources` section also retained an
unqualified absence. The same page left the stated policy undecided despite the
bulletin's explicit replacement clause. The older 31-day source claim needed to
survive as history; the current absence and artificial policy uncertainty did not.

The bilingual brief now:

- Reuses a source's own existing page while keeping different originals distinct.
- Compares scope, source dates, source approval/draft status and policy/observation
  roles before treating values as an unresolved conflict. A later date alone
  cannot approve a draft or turn a configuration observation into policy.
- Revisits existing `Open questions` and `Not in sources` entries on updated
  pages. It resolves only answered parts, preserves remaining uncertainty and
  distinguishes a document's own limits from the current folder's contents.
- Preserves personal notes as personal notes and keeps retained answers on their
  separate explicit refresh/revision path. Decisions record sourced decisions,
  rather than issuing new approval commands.
- Supplies the measured request time to every created or modified page as
  `compiled_at` guidance. That value is not an attested completion receipt.

Evidence and Steward independently recommended this bounded repair with exact-state
replays and a held-out negative control. Neither review grants additional write
authority. The existing app/runtime permission boundaries remain in force.

## Exact-state replay

For each provider, the pre-second-arrival folder was reconstructed from its sealed
first-stage page, the exact scripted note, the unchanged retained answer and the
arriving handbook. Every file hash matched the original before-state. The changed
brief then replayed the second and third arrivals through the same real adapter
versions and model settings. Sources, page targets and model projections used the
production helpers; the caller supplied `now` but no precomputed `hashes`, matching
the Library action.

| Required outcome | Codex | Claude |
|---|---|---|
| Present/read handbook no longer described as globally absent | Pass | Pass |
| Approved 14-day replacement distinguished from historical 31 days | Pass | Pass |
| Unit R2's dated 31-day observation remains separate from policy/implementation proof | Pass | Pass |
| Actual before-state uncertainty preserved or resolved with remaining limits | Pass | Pass |
| Original bytes, personal note and retained answer preserved | Pass | Pass |

The Claude page now records the earlier handbook gap as resolved history while
explicitly retaining the missing handbook effective date. The later bench
observation supplies a dated configuration value without closing migration or
post-observation-state questions. The Codex seed had only a bench/migration
question and an empty `Not in sources`; that actual question survives in a more
specific Unit R2/current-state form.

A fresh wiki-only reader for each candidate again recovered the requested
values and personal constraint and disclosed that originals were absent. The
Claude reader still used categorical approval-absence wording before bounding
it to the supplied records, and some causal wording was stronger than necessary.
The maintenance repair does not certify every later answer or its phrasing.

## Held-out counterexample

A different synthetic corpus contains an approved 4800-pixel final-panorama
standard, a separate 1200-pixel preview standard, and a later unapproved draft
proposing 3200 pixels with a conditional September 20 start. The draft explicitly
says its authors did not inspect the original standard, a historical author-read
limit that remains true after Atlas reads that standard.

Both providers completed two-stage compilations with the changed brief. Independent
source-aware review confirmed that 4800 remains the stated approved value, 3200
remains a proposal, the date remains conditional, and 1200 stays in its separate
scope. Both preserve the authors' non-inspection statement without misdescribing
the current reader's available files. No approval or implementation result was
invented by the compiled pages in this control.

## Audit corrections and limits

Two evaluation errors are preserved alongside their corrections. The initial
answer grader read the previous experiment's corpus; its report is setup-invalid.
The corrected audit records the exact permitted source paths and hashes. A later
audit initially called the Codex candidate's narrower newly generated gap coverage
a loss of existing gaps. Direct comparison with the exact seed and stage-2 text
showed those entries had never existed in that branch. The before-state
adjudication corrects the preservation verdict without rewriting any model output.

A seal's `questionsReleased: false` describes its creation time. It does not prove
current access isolation or that a later audit preceded question release. Likewise,
the synthetic human marker is not human acceptance, successful transport is not
semantic proof, and a matching source hash is not coverage or entailment.

The source-aware audit also distinguishes uncited process-history statements from
facts of the originals. The snapshots support this experiment's history, but an
original-source citation alone cannot prove what an earlier agent read. New gap
coverage differs between providers/runs and is not claimed complete.

The local model executor has a separate confirmed limit: it captures an existing
page for the consent diff but does not return that body to the model. An isolated
executor probe produced a valid replacement without an existing personal note;
no consent or filesystem write occurred in that probe. This repair does not
close that missing-context path or make generic ACP filesystem writes immutable.

Native final visual verification remains pending while the Mac is locked. A
formal unfamiliar-repository ontology field trial and recurring real owner work
also remain open. These synthetic wiki experiments substitute for neither.
