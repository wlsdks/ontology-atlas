# Node detail actions

#### Node detail actions
- The detail panel opens on what a person needs before they rely on a concept,
  in one screen at 1512x949 and 1920x1080: a header, the definition, whether a
  person must settle something, and the two reach lists. Its root names the one
  emphasised thing in `data-panel-emphasis` (`none`, `judgment`,
  `open-document`, `meaning-review`, `project-source`); a calm concept has no
  filled control.
- The header is one meta line (kind, the direct owner, one time fact) and the
  name on up to two lines. A capability's owner is its domain and an element's
  is its capability; pressing it selects the owner. The time fact is the
  confirmation date while a person's confirmation still matches the file,
  else the changed label inside the recent window, else nothing.
- The definition shows as written, without a label, cut at three lines and
  opened in place by a press. A concept without one says so in a quiet line.
- A judgment row stands between the header and the definition only when a
  fact holds, in this order: the document is marked for a person to decide
  (with its note, two lines), a confirmation the file has since outgrown, a
  confirmation whose file could not be read, connections without a recorded
  reason, then the edit conflict and summary lines. The first fact is one row
  of the panel's row height: a warning icon, the sentence and its action
  (**Open document**, or **Ontology review** for missing reasons) as a quiet
  chip at the right edge, set off by a hairline, never a filled or bordered
  box. The rest open under a plain "+N more". A concept with no review mark
  shows no row and no review word. A project's source receipt sits below it,
  and its remedy is the project's filled action.
- The footer holds the slug, **Ask** in the installed app, the edit actions,
  **More** and a quiet **Details**. The panel covers the map's agent tile, so
  **Ask** is the one press from a concept to the agent: it opens the dock on
  Conversation with a first question seated, and sending stays manual. A menu
  holding one action is that action, named by it: a capability, element or
  project shows **Edit relations** itself, while a domain, which can also
  create a linked concept, keeps the **Edit** menu. **More** starts with
  **Ontology review**, then **Copy prompt**, then explore overlooked areas, the
  document and the realm. A project whose code check is current shows
  **Copy prompt** beside that status only on the web; beside an agent the
  status stands alone and the copy stays in **More**. A menu opens directly above its trigger with their right edges
  aligned, on the app's raised menu surface with the popover shadow and a
  bright edge, never past the panel's left padding. A document selection's
  footer is the slug, **More** and **Open document**, its one filled control.
- The relation-line guide is pull-only in the existing `?` shortcut sheet. The
  map corner no longer carries a persistent legend, and INDEX no longer repeats
  agent/growth/handoff controls below the tree.
