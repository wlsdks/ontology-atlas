# 온톨로지 스튜디오 & 작업 트랙 마스터 플랜 (2026-07-24)

> 이 세션에서 소유자와 확정한 모든 트랙의 단일 추적 문서. 흩어진 결정을 한곳에
> 모아 "무엇을 하기로 했고 어디까지 됐는지"를 잃지 않게 한다.

## A. 온톨로지 스튜디오 트랙 (헤드라인)

**정체성**: 노드를 게임 아이템처럼 **강화(enhance)/구축(create)**하는 몰입 표면.
관계 = 소켓에 끼우는 보석. 빈 소켓(is_a·정의)이 곧 채우고 싶은 퀘스트 → 레벨업.
게임 에너지(glow·파티클·레어도)는 `--studio-*` 토큰으로 **격리된 헌장 예외**.
확정 시안: `node-studio-game.html`(강화) · `node-studio-create.html`(만들기 버튼 조립).

| 슬라이스 | 내용 | 상태 |
|---|---|---|
| **S1** | 헌장 예외 문서화 + `/ontology/studio` 라우트 + LNB "스튜디오" + 실제 노드 관계를 보석/소켓으로 렌더(읽기) + 능력치·강화도 계산 | 🔨 구현 중 |
| **S2** | `is_a`/`definition`/`includes`/`excludes` frontmatter 스키마 + 관계 domain/range 검증 + **소켓에 보석 끼우기 = patch_concept 쓰기** | 계획 |
| **S3** | 변동 원장(변동지점 기억) + **직접 적용(디스크 쓰기) / 에이전트 위임(MCP)** | 계획 |
| **S4** | **만들기 흐름(버튼 조립 폼)** + **빌더(/ontology/edit) 폐기** — 딥링크 스튜디오 이관, e2e/라우트/문서 스윕 | 계획 |

> **빌더 제거는 S4에 명시적으로 포함.** 지도=읽기 · 스튜디오=쓰기 · 에이전트=대량.

## B. 온톨로지 리거 공백 (전문가 8인 심사, partial 판정) → 스튜디오 S2로 흡수

전부 평문 frontmatter로 해결(reasoner 0):
- `is_a`/`broader` 관계 타입 (모든 위계가 part-of로 강제되던 #1 공백)
- `definition`·`includes`·`excludes` durable 필드 (near-duplicate 방지)
- `related_to` catch-all 세분화 여지 (supersedes/implements 등)
- 관계 domain/range 검증 (의미상 무효 엣지가 validate 통과하던 soundness 결함)
