# Build the app and the website with Vite and remove Next.js

**In one minute.** Next.js builds every Atlas screen today, yet Atlas uses none of its server: the
build writes plain files. That costs a 31 s build peaking at 3.3 GB and 13 s from `pnpm dev` to the
map. On 2026-11-27 the owner decided to move the installed app's screens and the public website to
Vite, one toolchain, with Next.js removed. This spec decides how:

- **Addresses in the app stay exactly as they are** (`/<language>/<screen>/?…`). They are how
  screens keep a selection, how the install link lands and how 466 test navigations enter; changing
  them in the same move would make a red test run unreadable.
- **Every public page stays a real HTML file at the same address**, written at build time by a
  step Atlas owns. Titles, descriptions, language tags, the sitemap and `llms.txt` do not change.
- **Nothing a person reads on a screen changes.** No message catalogue is edited.
- **Four slices.** Vite builds the app beside Next and must beat it on three measured numbers;
  Vite builds the website and must match Next page by page; the shipping build switches and one
  beta ships; only then is Next deleted.

Words used below: the *app folder* is the files the installed app embeds; the *site folder* is the
files the website host serves; to *prerender* is to write a page's HTML at build time; a *shim* is
a small stand-in file that answers an import of `next/…` while both builds exist. It builds after
the spec "Remove the browser workbench" (branch `docs/remove-browser-workbench`, not merged yet)
and assumes that removal; "the removal spec" below means that one.

## Person and moment

1. **The owner and the coding agents that build Atlas.** They start `pnpm dev` or a build, often in
   several worktrees at once, and wait. Owner, 2026-11-27, translated: "Let's switch to Vite! If
   it's fine to do, do all of it." "Can't the intro site also be Vite only?" "Instead of keeping
   the URL format, if there's a different way, you can do that — there will be no web browser
   anyway." Standing instruction, 2026-11-19 (the owner's words, not in the repository): memory
   use is held to the highest standard.
2. **A person using the installed app.** They launch it, move between screens, switch language,
   follow an install link from an agent. They must notice nothing.
3. **A visitor or a search engine** opening `https://ontologyatlas.com/ko/guide/relations/`. The
   address, the words and the page's description must be what they were.

Not observed: the owner waiting on a dev server or a build (no capture; criterion 1 takes the
measurement), and any visitor. Someone who uses Atlas without agents sees no difference.

## Patterns that already worked

| Pattern and source | Why it worked | How it fails | What Atlas borrows | What is new here |
|---|---|---|---|---|
| Replace a system beside the running one, behind an unchanged interface, then delete the old ([Strangler Fig](https://martinfowler.com/bliki/StranglerFigApplication.html)) | The old system stays the reference, so every difference is visible before anyone depends on the new one | Both run forever and cost double | Old and new builds judged by the same specs and a page-by-page diff, with a named moment for deletion | The diff compares two bundlers' HTML: head tags, visible text, bytes |
| A desktop shell fed a static folder by Vite ([Tauri's Vite guide](https://v2.tauri.app/start/frontend/vite/); fallback read in Tauri's source, above) | The shell needs files and a fixed dev port, which is Vite's native output | A one-document app breaks on reload where the host has no fallback | The pairing, and history addresses instead of hash addresses | The same bundle also feeds a prerendered website |
| Client-only products leaving Next for Vite and a route table ([Plane](https://plane.so/blog/why-did-we-migrate-plane-from-nextjs-to-react-router-vite), [Railway](https://dev.to/sarah-railway/moving-railways-frontend-off-nextjs-2hg5); search summaries only, not read in full) | Page logic was lifted out of route files first, so routes could be regenerated from a table | Metadata regresses unseen; a long branch rots | The order: table first, switch, delete | Atlas's route files are already thin, so the lift is done |
| Build-time prerender with the framework's static renderer ([Vite's SSR guide](https://vite.dev/guide/ssr), React's `prerender`; summaries only) | One client bundle plus a script that renders each route to a file needs no framework | The page and its hydrating script disagree; the page list drifts from the router | A script over one route table | Per-language pages with a message subset each |

## Problem and alternatives

The slow build is the symptom. The cause: Atlas pays for a server framework to get static files,
then maintains six corrections to its output (Today, third bullet), and agents arrive with Next
habits the repository must talk them out of (`AGENTS.md:173-177`).

**Ranked.** 1. The app on Vite: the daily wait and the peak memory of every parallel session come
back, and it proves the swap under the whole suite. 2. The website on Vite: no visible gain, but
Next cannot go without it, and it carries the search risk. 3. A different address format in the
app: no person can see it; it costs 466 test navigations, two Rust scripts and the scripts that
verify the installed app. First is 1, next is 2, and 3 waits under Later.

| Way | Value | Usability | Feasibility | Local-first fit | Verdict |
|---|---|---|---|---|---|
| Keep Next (status quo) | None gained | Familiar; agents' habits fit | Free | `next/font/google` fetches a font at build (Next's documented behaviour, not re-observed); telemetry must be switched off (`next.config.ts:16`) | Lost: the cost recurs on every build |
| Vite for the app, Next for the website | Most of the dev gain | Two toolchains, two translation set-ups | Smaller move | Same | Lost: every correction script stays, and the owner asked for one toolchain |
| Keep the Next API on Vite through a compatibility layer (vinext; not evaluated beyond a search summary) | Build gain | `app/` and Next habits stay | Young; depends on a re-implemented framework | Unknown | Lost: keeps a framework surface Atlas uses only to write files |
| **Vite, an Atlas-owned router and prerender script** | Build, dev loop, memory; six correction scripts deleted | One command set; one route table | Four slices | Build needs no network | Chosen |

**Address format in the app.**

| Option | What breaks | Verdict |
|---|---|---|
| Keep `/<language>/<screen>/?query#hash` on the History API | Nothing: Tauri's fallback serves the one document for every path | **Chosen** |
| Drop the language from the path, read it from the stored setting | 466 navigations, both Rust scripts, `deploy-macos-app-local.mjs:16`; app and site would speak two grammars through one `Link` | Later 1: cheap on the product side (one wrapper), costly in tests, and it would change the instrument while changing what it measures |
| Hash addresses | 43 files reading `location.search` and `pathname`; the hash is taken by heading anchors | Lost |
| No address (memory only) | Reload loses the screen; no test can open a screen; the install link and verifier scripts stop working | Lost |

**Decisions.**

1. **Router.** Atlas owns a small router over the History API, exported from `@/i18n/navigation`:
   `Link`, `useRouter` (`push`, `replace`, `back`), `usePathname`, `useSearchParams`, `notFound`,
   and one route table in `src/app/routes`. No router package: the surface in use is four hooks,
   one component and three calls, and 67 test files already mock that module. A change of path is
   a transition, so the screen showing stays until the next one is ready. In the app `/` picks the
   language in memory.
2. **One bundle, two folders.** `pnpm build` writes the app folder (`src-tauri/target/desktop-frontend`,
   one `index.html`, no website-only media) and the site folder (`out/`: the same bundle plus one
   prerendered HTML file for every route and language Next exports today, `404.html`,
   `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt`). An app screen's address on the website
   gets the page the removal spec defines for it, as a file, so no address that answers today
   starts answering "not found". Both names are kept so `frontendDist` and the Pages upload do not
   move. Which face `/` shows stays a runtime fact (`isGatewaySurface`), as
   `.claude/rules/surfaces.md:27-34` requires.
3. **Prerender.** An Atlas script renders each route of the table with React's static renderer; a page's
   head (title, description, canonical, hreflang, Open Graph, robots, JSON-LD, verification tags,
   icons) comes from `buildPageMetadata`'s facts, its `<html lang>` from `LOCALE_META`, its data
   from a non-executing JSON block. Social cards stay the PNGs `pnpm og:build` writes. No new
   dependency.
4. **Translation.** `use-intl` replaces `next-intl`: same hooks, no Next peer. Loading stays as it
   is: one catalogue chunk per language in the app, the listed subset inlined per public page. The
   four languages and their addresses stand.
5. **Fonts, images, lazy parts, CSS, variables.** Fonts become plain `@font-face` rules; JetBrains
   Mono ships from `@fontsource-variable/jetbrains-mono`, so the build fetches nothing. `next/image`
   becomes `<img>` with its size (optimisation is already off). `next/dynamic` becomes React `lazy`.
   Tailwind runs through `@tailwindcss/vite`, and `app/globals.css` lists every `@import` before
   `@source`. `NEXT_PUBLIC_*` becomes `ATLAS_PUBLIC_*`, the only prefix the bundle may read:
   `RELEASE_VERSION`, `ROW_PRODUCER`, `BASE_PATH`, `GOOGLE_SITE_VERIFICATION`,
   `BING_SITE_VERIFICATION`, `DOGFOOD_VAULT_PATHS`; `NEXT_DEV_ALLOWED_ORIGINS` becomes
   `ATLAS_DEV_ALLOWED_HOSTS`; `NEXT_TELEMETRY_DISABLED` goes, and so does
   `NEXT_PUBLIC_OATLAS_FIRST_RELEASE_PENDING` (`.env.example:15`), which no product file reads.
6. **New dependencies, each replacing one.** `@tailwindcss/vite` for `@tailwindcss/postcss`;
   `use-intl` (MIT, read) for `next-intl`; `@fontsource-variable/jetbrains-mono` for the build-time
   download. The first and third licenses were not read; `pnpm licenses:check` on the slice-1
   branch decides (`docs/engineering/third-party-code.md`, rule 5).
7. **Commands.** `pnpm dev` is Vite on port 3000, refusing a taken port; `pnpm build` is type
   check, bundle, prerender, reports; `pnpm typecheck` is `tsc --noEmit`;
   `ATLAS_BUILD_SKIP_TYPECHECK=1` and `pnpm build:static`'s reuse stamp keep their meaning.
   Browser specs keep both modes; in static mode a spec that opens a public page is served the
   site folder and every other spec the app folder, on two ports.

## Flow

1. When a contributor or agent runs `pnpm dev`, Atlas serves one document on port 3000 for every
   path; a second server on the same port exits naming the port.
2. When they run `pnpm build`, Atlas writes the app folder and the site folder and prints first-load
   sizes for the app's map and the site's download page.
3. When a person launches the installed app, the window loads one document, picks the language
   from the stored choice or the system list without loading another document, and shows the map
   or first run.
4. When they press a destination or select a concept, the address changes and no document loads.
5. When they switch language, the first path segment changes in place; query and hash are kept
   byte for byte and the open folder stays open.
6. When an agent's install link arrives, the app opens `/<language>/mcp/?tab=connectors&install=…`
   and shows the pre-filled form, as today.
7. When a visitor opens a public address, the host returns its prerendered HTML in that language;
   the words are readable before any script runs, then the page becomes interactive.
8. When a visitor opens an address no route has, the host returns `404.html`; an app screen's
   address returns that screen's website page, as today.
9. When an agent, from habit, writes `import Link from 'next/link'`, adds `app/…/page.tsx` or types
   `'use client'`, lint fails with the sentence under Copy. The agent is wrong and is told where
   the route table is.
10. When the measurement in criterion 1 does not beat Next, the move stops after slice 1 and its
    new files are deleted. The evidence was missing, so nothing else is built on it.

## Edge cases

- **Zero.** A language without its own changelog still gets the page, canonical to the default
  language's (`src/shared/lib/public-pages/page-metadata.ts:31-35`).
- **One.** A fork with one folder under `messages/` builds one language's pages; the list is
  derived, never written twice.
- **Largest measured count.** 160 HTML files before the removal, 52 of them the 13 guide pages in
  four languages. The count must equal Next's at the same commit (criterion 3); it comes from the
  route table and is not pinned.
- **First run.** No stored language: the system list decides (`src/i18n/detect-locale.ts:13-24`).
- **Hangul input.** `?p=` and `?slug=` values with Hangul survive a language switch and a reload
  byte for byte (`src/features/locale-switch/ui/LocaleSwitch.tsx:17`). React stays 19.3.1, so
  composition handling does not change.
- **Moved, renamed or unreadable folder.** Unchanged: the bridges own it, not the bundler.
- **Two at once.** Two worktrees build into their own folders; peak memory per build is the number
  that decides how many fit (criterion 1).
- **Offline.** After `pnpm install` a build needs no network. The app embeds every chunk.
- **Fork under a sub-path.** With `ATLAS_PUBLIC_BASE_PATH` set, the site bundle is built a second
  time with that base; the app folder is always built for `/`.
- **Updating from a Next-built app.** The origin does not change, so the stored language
  (`ontology-atlas:locale`), text size and remembered folder persist.
- **Windows.** The build writes both folders with `/`-separated paths on every platform, as
  `stage-desktop-frontend.mjs:49-51` did.
- **The updater feed.** `out/update/latest.json` (`package.json:60`) stays at its address.

## Out of scope

- A different address format in the app, a bundle without website-only code, and a stricter
  script policy: each is a slice under Later with its reason.
- Moving `app/styles/**` and `app/globals.css`: 118 files name those paths; after slice 4 `app/`
  holds only them and the move is its own rename.
- Any change to what the website shows or which routes exist: the removal spec owns that.
- The addresses MCP hands out (`traversal-analysis.mjs:536`): a public MCP contract.
- Server rendering at request time: forbidden (`forbidden.md:32-33`).

## Acceptance criteria

1. **The numbers, measured first.** Given Next at slice 1's base commit and Vite at its head on one
   machine in one session, when a cold build with the type check skipped on both sides runs under
   `/usr/bin/time -l` and `pnpm dev` is timed to a settled map by one headless probe used for both
   (the spike's `devprobe.mjs`: first response, then network idle), then Vite is lower
   on build time, peak memory and time to the map, and the map logs no `token drift` error.
   Check: the six raw outputs attached to the pull request. Any number not lower stops the move.
2. **The same specs pass.** Given the app folder built by Vite in slice 1, when `e2e.yml` runs the
   whole suite against it, then every spec that passes against Next's export at that commit
   passes, and no spec's navigation was edited. Check: the two runs' pass lists, compared.
3. **Page-by-page parity.** Given `out/` from Next and from Vite at one commit, when the slice-2
   diff runs, then both hold the same HTML paths; each page has the same `<html lang>`, title,
   description, canonical, hreflang set, robots, Open Graph and JSON-LD; the same visible text; no
