# Build the app and the website with Vite and remove Next.js

**In one minute.** Next.js builds every Atlas screen today, yet Atlas uses none of its server: the
build writes plain files. That costs a 31 s build peaking at 3.3 GB and 13 s from `pnpm dev` to the
map. On 2026-11-27 the owner decided to move the installed app's screens and the public website to
Vite, one toolchain, with Next.js removed. This spec decides how:

- **It is built the way a Vite app is built, not as a copy of Next.** Screens are routes of
  TanStack Router, each declaring the query values it reads as a typed schema instead of parsing
  strings by hand; words come from `use-intl`; public pages are written by a short Atlas script on
  React's own prerender. No file imitates a Next file (owner, 2026-11-27).
- **Addresses in the app stay exactly as they are** (`/<language>/<screen>/?…`). They are how
  screens keep a selection, how the install link lands and how 466 test navigations enter; changing
  them in the same move would make a red test run unreadable.
- **Every public page stays a real HTML file at the same address**, written at build time by a
  step Atlas owns. Its whole `<head>`, its words, the sitemap and `llms.txt` do not change.
- **Nothing a person reads on a screen changes.** No message catalogue is edited. The app's first
  frames keep today's loading picture in the person's language.
- **It is built in one branch with the removal of the browser workbench, after the removal's
  slices.** There Vite builds the app beside Next and runs the whole suite; Vite builds the
  website beside Next and must match it page by page and beat it on three measured numbers; the
  shipping build switches and Next is deleted. Every review and check runs on that branch's head
  before anything ships; then the branch reaches `main` in one merge, which switches the app and
  the website at once. There is no beta and no waiting period (owner, 2026-11-27).

Words used below: the *app folder* is the files the installed app embeds; the *site folder* is the
files the website host serves; to *prerender* is to write a page's HTML at build time; a *shim* is
a small stand-in file that answers an import of `next/…` while both builds exist; a *route module*
is a file under `src/app/routes/` that declares one address and renders its screen; a *search
schema* is a route's declaration of the query keys it reads and their types. "The removal
spec" is "Remove the browser workbench" (`docs/specs/2026-11-27-remove-browser-workbench.md`), whose terms this
spec uses: the *faked app runtime* (the test helper answering the app's native calls), the
*app-only page* (what a plain browser sees at an app address), and the two *faces* an app address's
HTML carries, chosen before paint by the boot script's `data-shell="desktop"` on `<html>`.

## Patterns that already worked

| Pattern and source | Why it worked | How it fails | What Atlas borrows | What is new here |
|---|---|---|---|---|
| Replace a system beside the running one, behind an unchanged interface, then delete the old ([Strangler Fig](https://martinfowler.com/bliki/StranglerFigApplication.html)) | The old system stays the reference, so every difference is visible before anyone depends on the new one | Both run forever and cost double | Old and new builds judged by the same specs and a page-by-page diff, with a named moment for deletion | The diff compares two bundlers' HTML: whole heads, links, visible text, bytes |
| A desktop shell fed a static folder by Vite ([Tauri's Vite guide](https://v2.tauri.app/start/frontend/vite/); fallback read in Tauri's source, above) | The shell needs files and a fixed dev port, which is Vite's native output | A one-document app breaks on reload where the host has no fallback | The pairing, and history addresses instead of hash addresses | The same bundle also feeds a prerendered website |
| The query as typed, validated state, one schema per route ([TanStack Router's search-params guide](https://tanstack.com/router/latest/docs/framework/react/guide/search-params), summary read) | One declaration parses, types and checks what a screen reads, so no reader hand-parses strings and a bad link falls back instead of throwing | A schema that defaults or drops a key rewrites the address on arrival (Today, `Transitioner.js:27-42`); JSON-typed values turn `?p=1` into a number | The schema per route as the one parser of its query | The schema sits over Atlas's own string-only serializer, so every address keeps its bytes |
| Build-time prerender with the framework's static renderer ([Vite's SSR guide](https://vite.dev/guide/ssr), React's `prerender`; summaries only) | One client bundle plus a script that renders each route to a file needs no framework | The page and its hydrating script disagree; the page list drifts from the router | A script over the router's own route tree | Per-language pages with a message subset each |

## Problem and alternatives

The slow build is the symptom. The cause: Atlas pays for a server framework to get static files,
then maintains six corrections to its output (Today, third bullet), and agents arrive with Next
habits the repository must talk them out of (`AGENTS.md:173-177`).

**Ranked.** 1. The app on Vite: the daily wait and the peak memory of every parallel session come
back, and it proves the swap under the whole suite. 2. The website on Vite: no visible gain, but
Next cannot go without it, and it carries the search risk. 3. A different address format in the
app: no person can see it; it costs 466 test navigations, two Rust scripts and the scripts that
verify the installed app. First is 1, next is 2, and 3 waits under Later.

| Way | Value | Usability | Feasibility | Local-first fit | Verdict |
|---|---|---|---|---|---|
| Keep Next (status quo) | None gained | Familiar; agents' habits fit | Free | `next/font/google` fetches a font at build (Next's documented behaviour, not re-observed); telemetry must be switched off (`next.config.ts:16`) | Lost: the cost recurs on every build |
| Vite for the app, Next for the website | Most of the dev gain | Two toolchains, two translation set-ups | Smaller move | Same | Lost: every correction script stays, and the owner asked for one toolchain |
| Keep the Next API on Vite through a compatibility layer (vinext; not evaluated beyond a search summary) | Build gain | `app/` and Next habits stay | Young; depends on a re-implemented framework | Unknown | Lost: keeps a framework surface Atlas uses only to write files |
| Vite with an Atlas-owned router copying Next's API (this spec until 2026-11-27) | Build, dev loop, memory | Hand parsing of the query stays in 12 files | Atlas writes and maintains matching, scroll, code splitting and the address layer | Build needs no network | Lost: it rebuilds Next instead of using what Vite apps use (owner, 2026-11-27) |
| Vite with TanStack Start or Vike for the website | Prerender and head handling come with the framework | A second framework's conventions for 13 guide pages, download and changelog | Start brings server functions | Start's server functions break `forbidden.md:32-33` | Lost: React's own prerender plus one script covers it |
| **Vite, TanStack Router, `use-intl` and an Atlas prerender script** | Build, dev loop, memory; six correction scripts deleted; typed queries replace hand parsing | One command set; routes are files the router types | Seven slices | Build needs no network | Chosen |

**Address format in the app.**

| Option | What breaks | Verdict |
|---|---|---|
| Keep `/<language>/<screen>/?query#hash` on the router's browser history | Nothing: Tauri's fallback serves the one document for every path | **Chosen** |
| Drop the language from the path, read it from the stored setting | 466 navigations, both Rust scripts, `deploy-macos-app-local.mjs:17`; app and site would speak two grammars through one `Link` | Later 1 |
| Hash addresses | 39 files reading `location.search` and `pathname`; the hash is taken by heading anchors | Lost |
| No address (memory only) | Reload loses the screen; no test can open a screen; the install link and verifier scripts stop working | Lost |

**Decisions.** Decided by the lead on 2026-11-27 from the packages' registries and documentation,
under the owner's instruction to build it the Vite way (Person and moment), except where marked.

1. **Router: TanStack Router** (`@tanstack/react-router` 1.170.x), with routes generated from files
   by its Vite plugin (`@tanstack/router-plugin`).
   - *Route tree.* Route modules live in `src/app/routes/` in the router's own naming: `__root.tsx`;
     `index.tsx` for `/`, which chooses the language; `$locale/route.tsx`, which accepts the
     languages `src/i18n/routing.ts` lists (four today) and answers any other value as not found; two layouts that add no path segment,
     `$locale/_site/` for public pages and `$locale/_app/` for the shell; then one file per address
     (`$locale/_app/topology.tsx`, `$locale/_site/guide/$segment.tsx`). The plugin writes
     `src/app/route-tree.gen.ts`, which is committed, and gives each route its own chunk
     (`autoCodeSplitting`). A route module declares its address (params, search schema,
     redirects, a public page's loader) and renders its view from `src/views`; no file is named
     `page.tsx` or `layout.tsx`. The four redirect views (`src/views/*-redirect`) become redirects
     in `beforeLoad` that keep query and hash. Routes are written in code instead only if the
     generator fails beside the app's static `index.html`, judged in slice 1.
   - *The query as typed state.* Each route's `validateSearch` is a Zod 4 schema, which the router
     takes without an adapter: `z.looseObject`, so keys another screen owns survive; every field
     optional, with `.catch(undefined)` for a malformed value; never `.default()`, because a value
     the schema adds is written into the address on arrival (Today). Screens apply their defaults
     where they read. In slice 4b the 17 `useSearchParams` readers, the 50 `searchParams.get` calls
     and the hand parse in `use-home-route-state.ts` move onto `Route.useSearch()`; the rules in
     `url-state.ts` (realm, expanded parents, their cap) stay, as functions over the typed value.
   - *The address keeps its bytes.* `trailingSlash: 'always'`. `parseSearch` and `stringifySearch`
     are Atlas's own functions over `URLSearchParams`, not `parseSearchWith`, whose decoder has
     already made `"1"` a number (Today): each value is a string or a list of strings, repeated
     keys keep their order, and a query no one changed is written back as the bytes it was read
     from. The install link, the verifier, MCP's handoff and the 466 test navigations need no edit.
   - *Contract*, written first as `tests/e2e/app-shell/router-contract.spec.ts` green on Next, then
     proven on TanStack:
     - (a) No screen renders an address that is not its own. TanStack writes history before the
       new screen renders (Today), so this holds by what a screen reads, not by timing: it reads
       its address from its own route match (`Route.useSearch`, `Route.useParams`), never from
       `window.location` during render. The contract spec checks this from slice 1; a render-time
       read among the 39 files it catches moves in slice 1, and 4b moves the rest.
     - (b) The router is the one history writer. The six direct writers become router navigations
       (`navigate` with `search`, `hash` and `replace`), so history state keeps the router's keys
       and Back and Forward land where they should; the write budget (`history-write-guard.ts:7-8`)
       stays, in front of the router's writes; lint rejects `history.pushState` and `replaceState`
       outside the router's module, with the sentence under Copy.
     - (c) The language is the `$locale` param. The switch navigates to the same route with
       `params: { locale }`, `search: true` and `hash: true`, so `/en/x` becomes `/ko/x`, never
       `/ko/ko/x`, and query and hash keep their bytes.
     - (d) Inside the app a same-origin link is a router navigation. After each, `document.title`
       is the new screen's (the route renders React 19's `<title>`, as public pages do), a polite
       live region announces it, `#<heading>` on arrival scrolls that heading into view, and Back
       and Forward restore scroll as Next does at slice 1's base (the router's
       `scrollRestoration`). In a plain browser a link between public pages is a page load
       (`reloadDocument`; decided by lead 2026-11-27).
     - (e) Arrival never rewrites. After the router mounts on any address Atlas, its scripts or its
       tests write (every route, the install link, MCP's `?p=…&workbench=edit` with `%20`, Hangul
       values), the address and `history.length` are what was opened.
   - *`@/i18n/navigation` stays, decided by count.* As a thin layer over TanStack (`Link`;
     `useRouter` with `push`, `replace`, `back`; `usePathname` without the language) it leaves 119
     product files and 67 test mocks untouched and keeps the pane crossfade it owns
     (`src/i18n/navigation.tsx:19-44`); removing it would save one 44-line module. New code may
     import `@tanstack/react-router` directly for a typed `to`.
2. **One bundle, two folders.** `pnpm build` writes the app folder (`src-tauri/target/desktop-frontend`)
   and the site folder (`out/`). The app folder holds one `index.html` and what the bundle
   references, nothing else (criterion 7 replaces the exclusion list). That `index.html` carries
   the loading picture's `mapEntry.mapComing` and `mapEntry.loadingDetail` in all four languages;
   its inline boot script sets `lang` from the path, else the stored choice, else the system list
   (`src/i18n/detect-locale.ts:13-24`), and `data-shell`, before first paint; CSS shows the
   matching language (decided by lead 2026-11-27). A reload of a non-map screen therefore shows
   the map's loading picture, not that screen's neutral frame. The site folder holds the same
   bundle plus one prerendered file for every route and language Next exports after the removal,
   `404.html`, `sitemap.xml`, `robots.txt`, `llms.txt` and `llms-full.txt`.
3. **Prerender: Atlas's own script on React's prerender.** For each public route and language it
   creates the router over a memory history at that address, awaits `router.load()`, and renders
   it with React 19's `prerenderToNodeStream`, which waits for every suspended part, so a `lazy`
   part on a public page arrives whole. TanStack Start and Vike are not used (Problem and
   alternatives). A page's head is React's document metadata: the route renders `<title>`,
   `<meta>` and `<link>` from `buildPageMetadata`'s facts and React hoists them (Today's probe,
   which slice 2 keeps as a unit test so a React upgrade cannot stop it unseen). The root document

## Flow

1. When a contributor or agent runs `pnpm dev`, Atlas serves one document on `127.0.0.1:3000` for
   every path; a second server on the same port exits naming the port. A plain browser sees the
   public pages and the app-only page; the map opens under `pnpm desktop:dev` or the faked app
   runtime.
2. When they run `pnpm build`, Atlas writes the app folder and the site folder and prints first-load
   sizes for the app's map and the site's download page.
3. When a person launches the installed app, the window loads one document whose first frame is
   the loading picture in the stored or system language, then the map or first run.
4. When they press a destination or select a concept, the address changes, the title updates, and
   no document loads.
5. When they switch language, the first path segment changes in place; query and hash are kept
   byte for byte and the open folder stays open.
6. When an agent's install link arrives, the app opens `/<language>/mcp/?tab=connectors&install=…`
   and shows the pre-filled form, as today.
7. When a visitor opens a public address, the host returns its prerendered HTML in that language;
   the words are readable before any script runs. A link to another public page loads that page.
8. When a visitor opens an address no route has, the host returns `404.html`; an app address
   returns the app-only page the removal spec defines.
9. When an agent, from habit, writes `import Link from 'next/link'`, adds a `page.tsx`, types
   `'use client'` or calls `history.replaceState`, lint fails with a sentence under Copy. The
   agent is wrong and is told where routes live and how to write the address.
10. When the measurement in criterion 1 does not meet its margin, the move stops after slice 2:
    the merges of slices 1 and 2 are reverted inside the integration branch, and the combined gate
    runs on the removal alone. The evidence was missing, so nothing else is built on it.

## Edge cases

- **Zero.** A language without its own changelog still gets the page, canonical to the default
  language's (`src/shared/lib/public-pages/page-metadata.ts:31-35`).
- **One.** A fork with one folder under `messages/` builds one language's pages; the list is
  derived, never written twice.
- **Largest measured count.** 160 HTML files before the removal, 52 of them the 13 guide pages in
  four languages. The count must equal Next's at the same commit (criterion 3); it comes from the
  route tree and the language list and is not pinned.
- **First run.** No stored language: the boot script and the app agree on the system list.
- **Hangul input.** `?p=` and `?slug=` values with Hangul survive arrival, a language switch and a
  reload byte for byte (`LocaleSwitch.tsx:17`), because Atlas's serializer writes an unchanged
  query back as read. React stays 19.3.1, so composition handling does not change.
- **A query written another way.** MCP writes `%20` and `encodeURIComponent` forms
  (`traversal-analysis.mjs:536`) where `URLSearchParams` would write `+`; arrival keeps them
  (Decision 1 (e)). A value that looks like a number or `true` stays a string.
- **Moved, renamed or unreadable folder.** Unchanged: the bridges own it, not the bundler.
- **Two at once.** Two worktrees build into their own folders; peak memory per build is the number
  that decides how many fit (criterion 1).
- **Offline.** After `pnpm install` a build needs no network. The app embeds every chunk.
- **Fork under a sub-path.** With `ATLAS_PUBLIC_BASE_PATH` set, the site bundle is built a second
  time with that base; the app folder is always built for `/`.
- **Updating from a Next-built app.** The origin does not change, so the stored language
  (`ontology-atlas:locale`), text size and remembered folder persist.
- **Windows.** The build writes both folders with `/`-separated paths on every platform, as
  `stage-desktop-frontend.mjs:49-51` did.
- **The updater feed.** `out/update/latest.json` (`package.json:60`) stays at its address.

## Out of scope

- A different address format in the app, a bundle without website-only code, and a stricter
  website script policy: each is a slice under Later with its reason.
- Moving `app/styles/**` and `app/globals.css`: 118 files name those paths; after slice 4c `app/`
  holds only them and the move is its own rename.
- TanStack Query: Tauri's `invoke` cannot be cancelled, and 79 product files already keep their
  data in `useSyncExternalStore` stores; a trial for polling code is Later 8.
- Oxlint or Biome in place of ESLint: neither runs `eslint-plugin-boundaries` (Decision 6).
- The React Compiler, Vitest 5 and motion 14: each is its own measured change, so a regression is
  not mixed into this one's numbers.
- Search schemas for data the vault holds (concept kinds, slugs): a schema checks the address's
  shape, never whether a concept exists; the screens keep answering a missing one as today.
- Any change to what the website shows or which routes exist: the removal spec owns that.
- The addresses MCP hands out (`traversal-analysis.mjs:536`): a public MCP contract.
- Server rendering at request time: forbidden (`forbidden.md:32-33`).

## Risks

1. **The router changes addresses or history in ways no screen shows**: a schema default or a
   re-encoded `%20` rewrites the address on arrival, a direct write drops the router's history
   keys so Back skips, the outgoing screen paints the incoming query, or one of TanStack's frequent
   releases changes one of these. Answer: Atlas's own serializer and the no-default schema rule (Decision
   1); criterion 2's arrival, Back and in-flight checks run on every slice that touches routing;
   the router packages are pinned to an exact version, so an upgrade is its own change that runs
   the contract spec.
2. **Search visibility drops because a public page changed unseen**, including through rendering
   the router in Node, where a page could prerender one match and hydrate another. Answer: slice 2
   begins by prerendering one guide page through the router and hydrating it in Chromium with zero
   hydration errors; if that fails, the script renders the route's view inside the root document
   without the router, and the client builds the router before `hydrateRoot`. Criterion 3 compares
   whole heads, head order, links and text and is a condition of the one merge; the first Vite
   deploy stops unless IndexNow reports zero changed pages; `seo:check` and `verify-hosted` stay.
3. **The installed app fails where Chromium specs cannot see**: the nonce that disables inline
   styles, frozen prototypes meeting the router's or Zod's internals, module loading from the
   app's own origin, the router replacing `history.pushState` inside WKWebView, WebView2 on
   Windows. Answer: the style rule and its planted probe; criterion 2 freezes `Object.prototype`;
   criterion 5 runs a local installed app, with Back, Forward and the install link, before slice 2
   exists; the Windows job runs the verifier.

**Rollback.** Before the merge to `main`, nothing has shipped: a failing slice is reverted or fixed
inside the integration branch. After it, revert the one merge commit; this restores the Next
build, the website included, because `main` received the whole move, removal included, in exactly
one merge. That merge is the point of no return: from it the app and the website ship from Vite.
A Next-built patch release can still follow a Vite-built one because the app's origin and stored
keys do not change. If the first deploy's zero-change guard stops, the live site stays Next-built until the
difference is fixed or the merge is reverted. The MCP server's move to Rust merges on its own and
is reverted on its own.
