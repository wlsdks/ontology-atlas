# Why Atlas and not Obsidian or Notion

## Person and moment

The owner said on 2026-11-19, translated: "There are many services like Obsidian and Notion, but there has to be a reason someone must use mine. UI/UX matters, design and motion matter, readability matters, and above all the features must be very powerful."

**Who.** First, a developer who already runs Claude Code or Codex. Their agent changes code faster than they can keep a picture of it (`README.md:29-33`). Many such people keep an "LLM wiki": raw sources, plus Markdown pages an agent writes, viewed in Obsidian. The pattern's author puts it as "Obsidian is the IDE; the LLM is the programmer; the wiki is the codebase" ([Karpathy, llm-wiki gist, 2026-04-04](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)). All three of today's specs serve this person (`docs/specs/2026-11-19-search-by-meaning.md:14`, `…-source-progress.md:18`, `…-wiki-ontology-link.md:14`).

**The moment they would pick Atlas.** Their agent merged a change, and they ask two things Obsidian cannot answer. Which of the notes and pages about this code are now untrue? What else does this change touch? Obsidian draws links, but it knows nothing about the repository's history.

**The moments they leave.**
- In the first minute, their vault opens with links that lead nowhere and images that do not show (see Today).
- When they want to write or capture fast.
- When they reach for their phone.
- When the map is empty and the payoff of an agent run is invisible.

**Observed:** nothing. No capture exists of anyone opening an Obsidian vault in Atlas or comparing the two. Acceptance criterion 1 captures it first.

## Today

**Atlas: what no listed competitor offers (verified in code).**
- **Concepts are judged against Git.** A concept's `path:` and its elements' paths are judged `current`, `stale`, `missing` or `unknown` from Git. The screen and the MCP server import this one rule (`mcp/src/drift/evidence-verdict.mjs:1-5`, `mcp/src/drift/evidence-drift.mjs:1-3`). The map marks stale evidence with an amber pip and unknown evidence with a dashed hollow disc (`docs/FEATURES.md:68-69`).
- **Wiki claims are judged against source hashes.** A source counts as written up only while a page cites it with a matching SHA-256. Otherwise it is `stale`, `partial` or `checking` (`src/entities/docs-vault/lib/library/vault-library.ts:127-139`). `validate_wiki` checks every Facts bullet for a citation whose path exists (`mcp/src/server/tool-definitions/validate-vault.mjs:300-310`).
- **Impact queries.** `query_ontology` runs `impact` and `blast_radius` over typed relations (`mcp/src/ontology-engine.mjs:209-210`). On the map, pointing at a concept lights what it reaches (`docs/FEATURES.md:63-64`).
- **Stated uncertainty.** Every concept template carries a `## Uncertainty` section (`mcp/src/schema.mjs:315`). Missing evidence shows as unknown, never as safe (`README.md:38`).
- **The agent's write path.** There are 40 MCP tools (count of `name:` across `mcp/src/server/tool-definitions/*.mjs`). Snapshots are vault-scoped and dry-run first (`mcp/src/server/tool-definitions/git.mjs:35-37`). In-app ACP agents wait for allow or reject on each write (`README.md:93,105`). The ACP registry lists 46 agents (`src-tauri/src/acp-registry.json`).
- **The code map.** `analyze_repo_structure` surveys a repository (`mcp/src/server/tool-definitions/analyze-repo-structure.mjs:16-19`).
- **Search.** The app has an FTS5 index of every `.md` file (`docs/ARCHITECTURE.md:180-214`, record `183a2c12`).

**Atlas: what blocks a switch (verified in code).**
- **Wikilinks resolve by path, not by note name.** `[[x]]` resolves as a path from the folder root, or from `wiki/` for a page inside it (`src/shared/lib/vault-document/parse-frontmatter.ts:513-521`). Obsidian's `[[Note]]` names a note anywhere in the vault.
- **Embeds and aliases are not handled.** No code handles `![[…]]` embeds or `aliases:`; the rewrite regex ignores the `!` (`src/shared/lib/library/source-citation.ts:22-34`). Whether this renders a broken image was not observed.
- **Dot-folders are skipped.** The walk skips names starting with `.`, so `.obsidian/` is never read (`src/entities/docs-vault/lib/local-manifest/walk-vault.ts:87`).
- **Editing is plain text.** Editing uses plain textareas, and no editor library is installed (`package.json:285-287`; `src/views/planning/ui/PlanningEditor.tsx:39`; `src/features/project-edit/ui/MarkdownField.tsx:42`). The app can reveal a file in Finder but not open it in another editor (`src-tauri/src/library.rs:665`).
- **Notion arrives raw.** Notion pages arrive only through an agent turn with the Notion MCP. They land as raw sources under `sources/notion/` (`src/widgets/library-import/model/import-flow.ts:24-60`).
- **Scale.** Folders are read up to 100,000 entries (`docs/FEATURES.md:227`). Before the index, loading the app at 100,000 files took 22.4 s of CPU (record `183a2c12`). That record's budgets are a 50,000-file reopen within 3 s and search within 50 ms p95. Neither has been reported as measured since. Preparing 50,000 files for search by meaning through Ollama took 5–8 h (`search-by-meaning.md:91`).
- **Proof.** "Our benchmark has not yet shown better answers with Atlas, and Atlas was slower" (`README.md:112-113`).
- **Readability.** Authored text is 16 px with prose leading and a 66-step measure, 78 steps from 1536 px (`app/styles/tokens.css:389,617`).
- **Decision records.** `pnpm decisions:find` returns no record on Obsidian, Notion or competitive positioning. The standing first-contact records are the codebase category (2026-08-25) and the download headline, *AI changes the code. / See it on one map.* (`320d9a63`).

## Problem and alternatives

**What does not set Atlas apart** (each has a plugin or a competitor that matches it):
- a graph view;
- the number of MCP tools (Heptabase lists 65);
- local Markdown;
- search by meaning;
- Git versions;
- an agent chat.

Public copy that leads with any of these loses to Obsidian, which is free.

**The edge.** At most three claims. Each is true today or in the planned slices, provable in two minutes, and out of reach for a note app. A note app sees only its own window, while Atlas is in the coding agent's write path and reads the repository's history.

| # | Claim | True | Demo | Falsifier |
|---|---|---|---|---|
| E1 | **It shows which notes your last commit made untrue.** Concepts are judged against the code they cite; wiki claims against the hash of their source | Today (`evidence-verdict.mjs`, `vault-library.ts:127-139`). One list after a commit is Later 1 | Edit a cited file and commit. The concept turns stale on the map and in `validate_vault`. Edit a source, and its page needs review | A person shown five real commits agrees with fewer than 3 of 5 flagged concepts |
| E2 | **Ask what a change touches; you and your agent get the same answer.** Typed relations, impact, uncertainty | Today (`ontology-engine.mjs:209-210`, `FEATURES.md:63-64`) | Select a capability: the map lights its reach. The agent's `blast_radius` names the same nodes and their unknowns | The map and MCP disagree on one node, or a person misses an affected concept that they then find through code search alone |
| E3 | **From a document to the code, every step cited.** Source → hashed wiki fact → concept → `path:` → commit | Source → fact: today (`validate_wiki`). Fact → concept: `wiki-ontology-link` spec | From a concept, open the pages that say what it is, the files that implement it, and whether each is current | The link spec's criterion 1 error rate fails, or a page shows "current" while its source changed |

None of the three claims a better agent answer, since the benchmark has not shown one (`README.md:112`).

## Flow

1. When the person opens a folder whose top level lists a `.obsidian` entry (app picker, recent folder, or browser picker), Atlas reads the folder as it does today. It notes only that the name exists, and never opens or writes `.obsidian/`.
2. When the walk finishes, Atlas resolves every `[[target]]`, `[[target|label]]`, `[[target#heading]]` and `![[target]]`, in this order:
   - the exact folder-relative path;
   - the same folder as the linking note;
   - a unique file name, compared after NFC and case folding;
   - a unique `aliases:` entry.
3. When a target matches more than one note, Atlas does not guess. The link counts as having no target, with both paths listed.
4. When the folder opens on its first screen, a band at the top shows `firstRun.obsidianVault.title` and `.body`, plus `.showUnresolved` when any link has no target, and `.close`. The band appears once per folder; Close dismisses it for this folder.
5. When they press Show, a centred dialog (`.dialogTitle`, `.dialogBody`) lists each link: its note, its line, and a reason (`.reasonMissing` or `.reasonAmbiguous`), each with `.openNote`. When they fix a link in Obsidian, the watcher re-reads the file and the row leaves the list.
6. When a note is read, `![[image.png]]` shows the image if its type is one Atlas already shows inline. `![[Note]]` shows a link card (`.embedNote`), and a missing target shows `.embedMissing`.
7. When an agent or the person writes through Atlas, unrelated frontmatter and body bytes stay as they were (`FEATURES.md:211`). Atlas never rewrites `[[…]]` into another link form.
8. When an agent calls `find_backlinks` or `validate_wiki`, the same resolver answers, so the agent and the screen name the same links.

## Edge cases

- **Zero notes:** no band.
- **One note with one link:** the counts read singular.
- **Largest measured:** none exists for an Obsidian vault. The 100,000-file synthetic vault has no wikilinks, so AC7 extends `scripts/perf/gen-scale-vault.mjs`.
- **First run:** the band shows after whichever stage the folder opens on today; AC1 records which one.
- **Hangul:** macOS writes NFD names; links compare after NFC (`walk-vault.ts:88`). A link to a note with a Hangul name finds that note whichever form its file name is stored in.
- **Moved, renamed or unreadable folder:** the existing recovery applies. An unreadable note counts toward `{notes}`, and its links are not counted.
- **Two edits at once:** Obsidian and Atlas both open. Atlas's save keeps its conflict guard, and an outside save re-reads the note.
- **Offline:** all local; nothing is sent.

## Out of scope

- **Transcluding note bodies.** A link card shows the note; full transclusion needs its own reading design.
- **Rewriting `[[links]]` when Atlas renames a concept.** The MCP rename covers frontmatter today; Obsidian links in bodies are Later 6.
- **Reading `.obsidian/` settings** (attachment folder, link format). That breaks the dot-folder rule, so Atlas uses the defaults above.
- **Canvas and `.base` files.** They are not Markdown, so they are listed by name only.
- **Notion import:** see gap 10.

## Acceptance criteria

1. **Baseline capture.** Given today's main, built fresh, and two real vaults (the owner's Obsidian vault and `obsidianmd/obsidian-help` `en/` at a pinned commit), when each is opened in the installed app, then the PR records the screen it opens on, its links with no target, and its broken embeds. *Installed-app walk; screenshots attached to the PR.*
2. **Same links as Obsidian.** Given `obsidian-help` `en/`, when Atlas resolves links, then it finds a target for at least 99% of the links Obsidian resolves, and never a different target. The oracle is `obsidian eval code="JSON.stringify(app.metadataCache.resolvedLinks)"` (CLI `eval`, per the 1.15 changelog; its exact output is unverified). *A new resolver unit test against the exported oracle.*
3. **Nothing written.** Given a vault under Git, when it is opened, browsed and closed, then `git status` is clean and no `.obsidian/` file's mtime changed. *e2e spec on the fixture.*
4. **Embeds.** Given `![[diagram.png]]` and `![[Other note]]`, when the note is read, then the image draws and the card opens `Other note`. A missing target shows `embedMissing`. *e2e spec.*
5. **Agent and screen agree.** Given the fixture, when the agent calls MCP `find_backlinks` for a note and the person reads the backlinks strip, then both list the same notes. *Contract test.*
6. **Hangul.** Given a note with a Hangul file name stored as NFD and linked as NFC, when resolved, then the link finds it. *Unit test.*
7. **Scale.** Given a 50,000-note generated vault with 200,000 links, when it is opened on the M2 Max, then resolving adds at most 1 s to open and the band appears within 2 s of the first screen. *Perf script output in the PR.*
8. **Switching walk (recovery proof).** Given three people who run a coding agent and keep a vault in Obsidian, when each opens their vault in Atlas with no help, then within 10 minutes each finds a note by search, follows a link, and names one thing Atlas showed that Obsidian did not. Each also names what would make them leave, recorded word for word. *Recorded walks; side by side with Obsidian on the same three tasks.*

## Risks

1. **The people who keep Obsidian vaults are not the people who run coding agents.** Then the slice serves nobody. Probe: recruit AC8 only from agent users, and count how many of them have a vault before building Later 2–4.
2. **Opening whole still shows nothing Atlas-unique, so they go back.** The design answer is that Later 1 comes next. If AC8 finds no participant who names an Atlas-only thing, swap Later 1 ahead of any other polish.
3. **Resolution disagrees with Obsidian and erodes trust in every count.** The answer is AC2's oracle from Obsidian itself. An ambiguous link is listed, never guessed, so a wrong target is impossible by construction.
