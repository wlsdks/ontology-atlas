## Principles

- Atlas is a compact graph workbench, not a documentation portal with a graph attached: dark neutral surfaces, one indigo accent as the resting protagonist, dense readable controls. Dark only: no light switch, no `data-theme`.
- Every mark, colour, motion or effect carries a typed fact or a state. Gradients, glass, glow, scale hover, overshoot and further hues are allowed ("The expression bans are lifted", `docs/DECISIONS.md`) only through a ramp token that names the fact carried, with contrast floors and a reduced-motion equivalent held; as gloss they are a regression.
- A control names the ontology handle it acts on (kind, slug, relation type, proof target, path) and what happens next. A screen that changes the graph exposes a copyable MCP/CLI packet or direct handoff so an agent can verify the change; query-like surfaces show result contracts, limits and partial evidence.
- The selected concept survives navigation: one canonical graph handle across map focus, detail, Workshop deep link and source-document handoff.
- A design change names the rule it serves or argues why it diverges. Lineage: [`docs/FOUNDATIONS.md` section 4](./FOUNDATIONS.md#4-design-lineage--restraint-as-craft-cited).

## Workbench composition and motion

Tokens keep screens related; they cannot decide what a screen is about. Name the **one fact or action** that must be understood at first glance, draw its real object or relationship at the largest useful scale, then place controls and evidence around it. If three equal panels can be swapped without changing the meaning, the composition is unfinished. A structure view draws its causal links; a table with decorative connectors is still a table.

An empty state shows the real zero state and the next action in one scene. A preview may show column names or a labelled vacant slot, never something resembling an existing result or agent run, and stays quieter than the action. An example of a result a destination gives is allowed only when it says "example" in words (on screen and in its accessible description), names which parts come from the person's data, loops a bounded number of times and rests on its finished frame.

Motion is a change of *a named object*: selection reveals its evidence, a path highlights its real edges, unrelated panels stay still. Idle animation represents a live fact or bounded atmosphere, never an invented run or pending task. A screen recording, not a CSS value, proves continuity.

External design references are principles, not assets: no third-party screenshots, logos, fonts, code or recognizable compositions enter the repository.

## Surfaces and hierarchy

- **Order.** Primary task, then graph evidence (counts, relations, warnings, health, query readiness), then the next graph action. A large explanatory panel is never the first read; prefer compact handoff strips naming a destination and why. Retired structures (Browse/Write/Query cards, tree/ego hub, ERD Builder rails, query cockpit) are not revived.
- **Topology** (`/topology`) is the browse and decision surface: INDEX may project project, domain, capability, element, while canvas and datasheet keep typed relations, evidence and impact visible. `/ontology` and `/ontology/edit` are compatibility redirects, never second hubs. **Insights** is a maintenance board of measured questions, not an analytics dashboard: `?tab=` restores the question, one `tabpanel` is visible, the first viewport answers with real graph data, and the handoff row copies the matching MCP/CLI action.
- **Page rollout.** Pages inherit the map's language, not its canvas: chrome density (`--topology-chrome-*`), engraved mono numerals for counts that point to data, machined cards (`--color-panel`, 1px `--color-border-soft`, compact radius), hairline dividers (solid for contains, dashed for depends and stale), kind miniatures as legend markers, a powered dot for a real fresh or active state. Canvas-only: node shapes, comet pulse, diffraction spike, star dust, blueprint grid, vignette, altitude crossfade, breathe, hub ring, domain hull. Imitating them in DOM is an AI demo background. Tables use hairline dividers and right-aligned mono numbers, never zebra tint or a per-status badge palette.
- **Transient surfaces.** One surface owns the current action; support surfaces stay visibly weaker; blocking surfaces dim or suppress the rest. A new transient surface closes the previous unrelated one; a composer or modal demotes transient surfaces and blocks parent-map interaction, and a destructive confirm separates itself with a dim, scrim or blocked interaction. Elevation names layer order and nothing else. Chrome over a dark canvas uses dark panel tokens, never a light slab.
- **Colour is data, not atmosphere.** Kind colour (`--color-kind-*`) is allowed only where colour is the sole identity channel (kind-census strip, map dots, tree chips); elsewhere a label, icon, size, position or legend carries kind (WCAG 1.4.1). Panels and cards stay neutral with compact swatches and low-alpha borders.
- **No left-edge selection stripe.** Never attach a coloured vertical line or full-height rail to a selected card, row or diagram part: it is a generic callout cue that says nothing about the part. Selection is the whole control's surface and boundary, its label, and the evidence or relation. Dense Git rows and the document outline have separately reviewed position markers.

## Topology node focus & scale

Overview first, zoom and filter, details on demand (`docs/design/topology-focus-and-scale.md`).

- **Click is ego focus plus a compact popover, never a fullscreen modal.** The node and its direct neighbours stay at full opacity and the rest dims through the world's focus-state derivation (the source graph is not mutated). A content-sized `OntologyMapDetailPanel` anchors near the node and lists connected nodes as ego-walk targets; `FullDetailA1` is an explicit action inside it.
- **The default view is an overview**: project, domain and hub nodes at level 0, members on demand (semantic zoom). Never drop a 2-3k-node hairball on the person. A node-count capacity claim needs canvas-2D measurements at the stated viewport and interaction.
- **The canvas has no DOM.** Agents see it through `window.__atlasMap` (`?e2e=1` gate: typed node coordinates, camera, selection, cluster-chip claims; `map-testability`). Canvas 2D cannot read CSS variables: `src/widgets/ontology-map/tokens/read-map-tokens.ts` parses and caches them once.

## Node Spec

- **Kind is shape, not colour.** Hue cannot express order (Bertin) and is already spent on hierarchy (the brightness/depth ladder) and state (signal tones). Project is a hex plate, domain a square chip with pin ticks, capability a circle, element a square with a centre via-hole. A kind the map never draws (document, vault README, unknown) borrows no silhouette: the DOM facade draws the page mark (lucide `FileText`, quaternary ink).
- **One mapping, two gateways.** Canvas `render/node-shapes.ts` and DOM `src/shared/ui/map-kind-glyph.tsx` render the same mapping (`node-kind-shape-parity`). Node icon sets (geometric, line) change render style only, never silhouettes. Thresholds live in the constant block at the top of `node-shapes.ts`: cite code by symbol, never by line, and never copy a threshold here.
- **Radius is a fixed ladder** (`--map-radius-{project,domain,capability,element}` via `radiusForKind()`), a design decision lint cannot judge. Changing it, `DOMAIN_HALF_EXTENT_RATIO` or adding a bridge-node visual reopens map research through a `reviewer` with the `map-marks` lens; a bridge visual must state what fact its light or border carries (red overlaps the error tone). 3D views size in screen pixels (`DOME_NODE_PX`), perspective only, never camera zoom.
- **Size** (`computeMagnitudeScale`): only domain and capability scale, as `1 + k(sqrt(childCount) - 1) / sqrt(maxChildCount)` clamped to 1..1.4, `k = --map-radius-magnitude-k`. Never below base: that would signal "small", and leaves have no countable children. Size encodes direct children, numbers encode descendants: an intentional dual channel.
- **Engraved numerals** (`drawEngraved`): project and domain only, above `ENGRAVED_COUNT_MIN_RADIUS`, faded in the overview; the value is `descendantCount`.

## Map marks and ink

- **Machined surface**: a 1px stroke over a neutral fill tier; canvas nodes allow one monochrome vertical sheen (`--map-node-sheen-tint`), DOM cards do not simulate it. **Engraved mono numerals** only for counts that point to real data (node, relation, census); decorative numbers are forbidden.
- **Signal means state.** Indigo is "powered" (fresh stroke, powered dot, active highlight); the comet pulse is live traversal of `depends`; stale is a dashed border on a low-chroma surface. Signal colour with no stated state is forbidden. Indigo is the resting protagonist and amber marks one hub ring; a further hue must name a typed fact or decision (tier, state, lens) through a `--color-*` token.
- **Calm chrome, fluid canvas.** The canvas moves (spring camera, altitude crossfade, breathe); chrome is static precision instrumentation (`--topology-chrome-*`) and fluid motion does not leak into it.
- **Token scope.** `--map-*` is consumed only by the topology renderer and its panels; a page outside topology promotes the value to a global token first. Each map view spends only its own family through its own reader (Territories `render/territories.ts`, Hex board `board/`, Flat dial `dial/tokens.ts`, light `light/`), borrows existing inks and mints no hue; a hex face ladder is luminance, never hue.
- **Ink ladder, one depth axis.** Node strokes and containment edges draw the same tree depth, so they alias one value: `--map-ink-depth-{leaf,mid,top}`. The project stroke is a further step with no edge counterpart; the `depends` edge sits off the axis, distinguished by dashes and indigo tint, not lightness. Every stroke clears 3:1 over the canvas (WCAG 1.4.11) and no edge outshines the project stroke. Chrome at rest (cluster chip) is darker than any node yet clears 3:1, and wakes to indigo on hover and focus (`topology-ink-contrast`). An "edge at most 0.8 of node stroke" ceiling is not a rule: the ladders do not compete.
- **Labels** take their baseline from one function (`resolveLabelBaselineY` in `render/labels.ts`) shared by draw and bbox build, anchor to the drawn screen radius, keep `LABEL_NODE_CLEARANCE` from the outline, and reserve every drawn disc (selected and hovered win). A blocked label flips first and is suppressed last, so no shape goes nameless.
- **Side lanes** `--map-safe-inset-left/right` are the chrome standing on that side plus one equal air (`map-fit-side-air`). Cluster controls share one decision function for draw, hit-test and label scheduling (`clusterControlForm`) and never overlap (`expand-settings`). Canvas backgrounds are static, capped at `--canvas-bg-ink-max`, and lose to data.

## Design tokens

### Where values live

`app/globals.css` imports the parts in `app/styles/` in order (`@theme` ramps in `tokens.css`, `:root` alpha in `base-root-alpha.css`, `--map-*` in `base-map-tokens.css`); gates read the joined text through `readGlobalCss()` (`scripts/lib/global-css.mjs`).

- Every colour is a CSS variable; declare translucent values in `:root` too (Tailwind v4 may emit the utility without the root variable).
- A token needs a living consumer (`unused-token-ratchet`), and a token this document cites must exist (`design-doc-token-integrity`).
- A new topology token states its product reason, state or layer, responsive fallback and a WebView or test marker.
- Lint blocks raw hex and colour functions, `text-[Npx]`, `rounded-[Npx]`, hand-built shadows, numeric `duration-*` and z-index 20+ without `--z-*`. Spacing is deliberately unenforced.

### Scale fixed contract

Deviation is a defect.

- Chrome fields, tiles and chips are `--chrome-tile-size` tall; chrome labels use `text-label`; the rail icon is one step, `--app-nav-rail-icon-size`.
- No UI zoom below 2400px; `.topology-ui-scale` is 1.1 only from 2400px.
- Faces: self-hosted Pretendard Variable (`--font-sans`) and JetBrains Mono (`--font-mono`); weights 400, 510, 560, 650 only. No CJK font file ships (`app/styles/lang-cjk.css` names installed OS faces).
- A size step carries its own leading (the companion, for example `--text-body--line-height`); changing only the size breaks the pair. Text that inherits the 16px root has escaped the ramp.
- Every type, leading and radius step is registered in `cn()` (`TYPE_RAMP_STEPS`, `LEADING_RAMP_STEPS`, `RADIUS_RAMP_STEPS` in `src/shared/lib/cn.ts`); an unregistered step is read as a colour or size class and silently dropped or left unmerged.

### Colour

- **Surfaces** step `--color-canvas`, `--color-panel`, `--color-elevated`; hover and selection washes are `--color-overlay-1..3`; borders are `--color-border-soft` (default), `--color-divider`, `--color-border-strong`.
- **Text ink**: primary, secondary, tertiary, quaternary. Quaternary clears 4.5:1 only on the bare surfaces (canvas, panel, elevated) and panel plus overlay-1; hover or selection (panel plus overlay-2), elevated plus overlay-1 or more, and indigo or amber tint composites use tertiary, deeper composites secondary. A clickable row never rests on quaternary (`quaternary-ink-surface`). `--color-text-on-accent` is the only foreground on filled indigo (`controlClass({ tone: 'onAccent' })`).
- **Indigo is the only accent**; there is no accent setting. `--color-indigo-accent` is for bare dark surfaces and fails AA on tints, where text uses `--color-indigo-text-soft` (`accentOnTint`; `accent-ink-contrast`). Spell translucent indigo only with the existing alpha-step tokens (`pnpm design:tokens -- --prefix=--color-indigo`): a hand-copied `rgba()` of a token passes the raw-colour gate and is still a defect.
- **Signal tones**: warning amber, error red, success emerald, each a solid dot plus a symmetric surface, border and text alpha ladder on one hue. They explain state, never decoration; success marks a real positive state only. No fourth tone without a charter update.
- **Three ambers, three rules** (a grep for "amber" finds unrelated families). *Hub amber* `--map-amber-hub`: one hub ring, one Layer-0 container, two written exceptions (agent focus ring, `?recent=` spotlight); a third on screen is a defect. *Kind tone* `--color-kind-<kind>-rgb`: a data mark; `kind-tone-mirror` keeps the canvas paint copy equal. *Footprint trail* `--color-footprint-trail`: deliberately not the hub value, so "centre" and "walked" never merge (`footprint-trail-ink`).
- **Bars are neutral plus one indigo**: indigo marks the primary series only, and segments separate by a 1px seam, not by hue (indigo against neutral is 1.12:1, under the 3:1 graphic threshold). **Evidence-only concepts** (`isEvidenceOnlyConcept`) wear an achromatic badge, never amber, because dozens share a screen; demoted rows are never deleted. **Texture is not fact**: an ambient surface is monochrome in a neutral ramp, carries no count, title or link, and never wears signal inks.

### Type ramp

Steps: caption, label, body, body-lg, title, reading, display, hero, hero-lg, monument (`pnpm design:tokens -- --prefix=--text-`).

- Declared in `rem`, so a browser's text-only zoom reaches type; pixels at the default root are the ramp's numbers. Chrome geometry (tile, rail and dock widths, hit floors, dialog tiers) stays `px`: type follows the reader, boxes do not. A chrome box that stays absolute while its padding, icon and label follow the root declares a clip or collapse rule.
- `reading` is authored-document body on `--leading-prose`. It equals `title` in size and differs in kind: `--measure-doc-column` derives from it, so swapping them moves the reading column.
- Snap an off-ramp size to the nearest step; exactly between goes up. A step that does not exist (`text-large`) emits no CSS and renders at the 16px root (`type-ramp-step-defined`). A new step needs the ramp in `tokens.css` and registration in `cn.ts`.
- JavaScript that resolves a size token (canvas `ctx.font` cannot take `var()`) uses `rootFontPx()` and `cssLengthToPx()` from `src/shared/ui/root-font-size.ts`: `parseFloat("0.6875rem")` is 0.6875, 16 times too small.
- `rem` in a media query resolves against the browser's default font size, not `html { font-size }`: test text zoom of type by setting the root in script, but of layout only in a browser launched with `defaultFontSize` (`text-zoom-layout.spec.ts`; gate `type-ramp-root-relative`).

### Line-height ramp

Line height is a pair of its size, on a 2px grid in `rem`, plus ratio steps (`--leading-display-tight`, `-prose`, `-monument`).

- UI text uses its size's pair (carried by `text-<step>`); authored text uses `prose`; names and numbers that read as one block use `display-tight`, at most two lines (three make Hangul final consonants touch the line below).
- Korean sets the upper limit and Latin follows; no locale branching, because one paragraph mixes both.
- `text-[length:var(--text-display)]` keeps the size and loses the pair (`arbitrarySizeSelectors`). A conditional size (`sm:text-...`) misaligns the pair: use ramp utilities for it or an explicit `leading-*` covering both (`type-ramp-leading-pair`).
- In `cn()` write size first, line height second: tailwind-merge lets a later `text-<step>` absorb a preceding `leading-*`.

### Icons, radius, shadow

- **Icons.** Content icons beside text use `ICON_SIZE` (`src/shared/ui/icon-size.ts`: sm, md, lg), mirrored by `--icon-*` in `rem` because lucide's `size` prop cannot read `var()`. Pair the step with its type: sm with label and body (default), md with body-lg, lg with title. `icon-size-ramp` is a ratchet: new files start at zero off-ramp sizes. Icons rendered through a runtime variable escape the source scan; check rendered svg sizes.
- **Radius**: micro (kbd, micro badge), chip (chips, fields, `Select` trigger, `Button` at every size), card (items nested in panels, repeated list items), panel (sections, popovers, modals), sheet. Sheet is only for large transient surfaces that float and obscure what is below (shortcut, search and agent-connection sheets); inflow content never wears it. Zones placed directly on a page, sheet or drawer are panel plus `--card-pad`; boxes nested in them are card. Hairline meter tracks keep 1-4px; other exceptions stay `eslint-disable` with a reason.
- **Shadow**: three float tiers (`--shadow-elevation-1` toolbars, card hover, toast; `-2` popovers and palettes; `-3` dialog), two docking tiers for surfaces attached to a screen edge (`-dock-bottom`, `-dock-side`: the downward tiers would cast off-screen) and `--shadow-control-press`. Lint checks which token a value uses, not the presence of `var(`. Never hand-write a drop shadow; a new role is a token PR first. An inset hairline is material, not a shadow.

### Measures and page frames

- **Prose measure** `--measure-prose` is a `ch` cap on one line of authored text, applied to prose elements inside a column, never to the column; `ch` is the advance of `0`, not a character, so calibrate by rendering (`prose-measure-calibration`). **Document column** `--measure-doc-column` is that measure spent at `--text-reading` plus two gutters, so box and line cannot disagree; it grows with the reader's text size. Consumers that cannot read CSS variables (popout stylesheet, image `sizes`, the outline rail's fit verdict) use `src/shared/ui/reading-measure.ts`.
- **Page frames** (`src/shared/ui/page-frame.ts`) follow the direction the eye travels. Text and settings (read a sentence, act on a row) use `PAGE_FRAME_FORM`; a canvas (map, graph, diagram) or a list of many short cards uses `PAGE_FRAME` (`--page-max`) or none. A destination's `h1` wears `PAGE_TITLE` and its lede `PAGE_LEDE`; call sites add placement only (`page-frame`). Changing a frame value is a specification change that owes a decision record. A page mixing an `mx-auto` column with left-fixed surfaces has two alignment origins that diverge with the viewport.
- **Gateway** has one alignment origin, `--gateway-origin`, the only gateway token registered through `@property <length>` because JavaScript reads it (and re-derives on resize). `--gateway-page-max` stays at least `--page-max` (`gateway-column-width`); `--gateway-stage-max` is a clamp whose floor is the approved stage (`gateway-stage-width`). Never centre with `mx-auto`: it creates a second origin.
- **Widths have no shared unit**: they derive from content or geometry (`min()`, `clamp()`), not scale steps. For a new surface width, reuse a same-nature token, else add a surface-specific token with a derivation comment in that surface's block; that needs no approval (the spec sensor watches only ramp tokens, `RAMP_TOKEN_PATTERN` in `scripts/lib/design-spec-census.mjs`). A one-off `max-w-*` is an optical correction. **Padding is not a ramp**: `--card-pad` is the card and panel inset, `--map-panel-pad` is map-local, and `gap-*` and `space-*` use the 4/8 steps.

### Touch & tablet responsive contract

Touch is its own axis, not a width. `--touch-target-min` promotes control heights, the chrome tile, rail tile and overlay close under the coarse-pointer queries in `app/styles/`; fine pointers keep density. Below `lg` the `BottomTabBar` exists: a surface anchored to the bottom or ending in a scroll area reserves `--topology-mobile-bottom-tab-reserve`, and "blocked by the tab bar" is a defect. Below `md` the expanded INDEX is a full-bleed sheet.

## Controls

### Components and layers

`/ui-build` holds the need-to-component table. The **value layer** (`controlClass()`, `fieldClass()`, `fieldLabel()`, `badgeClass()` in `src/shared/ui/`) owns appearance, size, colour and disabled state; the **action layer** (`Chip`, `IconButton` with a required `label`, `RowButton`, `Input`, `Textarea`, `Checkbox`) owns what a string cannot carry: `type="button"` by default (a button in a form submits), accessible names, error wiring, keyboard semantics. `Button` is primary, outline, ghost or danger (the confirm step of an irreversible action), always at the chip radius; a page's one way forward is a `primary` Button, never a `controlClass` pill, which carries a state or count. `Dialog` is blocking (scrim, trap, Escape, return, scroll lock, `--z-dialog`); non-modal surfaces use `Surface`. `CloseButton` is the one close control. Raw `<select>`, `role="dialog"`, text fields, `<details>`, `type="checkbox"` and `role="tab"` outside their primitive are held by adoption ratchets that only fall.

### Control shapes and heights

`controlClass()` has eight shapes (chip, link, row, icon, pill, card, tile, segment), derived from a census of production buttons. Axes: `scope: 'app' | 'panel'` (the panel's achromatic ink lamp, `--map-panel-text-*`), `tone` (including `onAccent` and `accentOnTint`, paired with their background), `truncate`. A new axis, tone or shape needs the count of controls it leaves outside the system (`control-adoption-ratchet`); an exception axis is a symptom of a wrong value, so fix the value.

Heights come from one ladder, and a height outside it is a deviation: 24 (no token; the WCAG 2.5.8 floor), 28 `--control-h-sm`, 32 `--control-h-md` (default), 36 `--chrome-tile-size`, 40 `--control-h-lg`, 44 `--touch-target-min`.

- The ladder defines height and padding fits inside it, never the reverse.
- Single-line horizontal shapes (chip, pill, segment, row, card) and squares (icon) declare a ladder `min-h-*`, never a hard `h-*` (it clips wrapped controls). `xs` lowers inset, type and radius but keeps the 24 floor.
- Vertically stacked controls (tile, rail item) take the ladder on their inner tile, not the sum with label and gap. Inline prose links are exempt. A height not on the ladder means fixing the ladder, not adding an axis (`control-class`, `control-height-ladder-scope`).

### Links, touch floor, disabled

- The `link` floor is 24 (`min-h-6`). Coarse pointers reach 44 by actual height (`.atlas-touch-floor` on chip, row, pill) or hit expansion (`.touch-hit-expand`, a coarse-only pseudo-element for icon and hand-drawn controls, only with at least 12px clearance, or a later `::after` steals the earlier tap). The floor rule sits outside cascade layers, and its query is `any-pointer: coarse` (a touchscreen laptop reports `pointer: fine`).
- Links inside markdown flow are not controls: they wear `.prose-link` (underline geometry only; `prose-link`).
- `CONTROL_DISABLED_CLASS` (`control-class.ts`) is the one disabled treatment: opacity 55, `not-allowed`, no shadow, no hover; dimming alone leaves a control that looks disabled and still reacts. Elements that cannot take `disabled:` use `opacity-55` directly (`disabled-affordance`).

### Fields

`fieldClass({ frame, size, multiline })`. `boxed` is a record field (the value persists, so the input wins); `bare` is a query field (the result wins) and emits no dimensions, border, radius, inset or touch floor, because the parent provides the box. `size` maps 1:1 to the ladder (`xs` and `sm` 28, `md` 32, `lg` 40) and type pairs with it (`sm` `text-body`, `md` and `lg` `text-body-lg`): what a person types is the most readable thing in a form. A stage-size input (a 23px name on a creation card) is out of spec because its size carries information. `fieldLabel({ row })`: a name label is `text-label` in secondary ink, never smaller than its own footnote; a whole-row clickable label takes the touch floor and `min-h-6` (the label is the target); a layout-only wrapper gets no styling. Tests compare height unit-to-token and type by exact class (`text-body` is a substring of `text-body-lg`): `field-class`.

### Select, empty state, tabs, scrollers

- **Select** renders its list in a portal (an absolute list is clipped by ancestor `overflow: hidden`) and caps it at `LISTBOX_MAX_ROWS` or the remaining space, whichever is smaller, with a scroll affordance only when the cap clips (`select-growth.ts`).
- **EmptyState**: icon, skeleton, title, description, action; `tone` dashed (inside lists and cards) or solid; `align` left or centre. A centred card without a description demotes its title to the body step; with a left icon the action row sits in the text column. Empty charts and lists show a filling form (skeleton), not long whitespace.
- **TabBar** serves panel navigation (document sections, agent inbox categories); closable file tabs, preview and edit modes and search filters are other jobs. A flat row at least `--control-h-lg` tall with a 2px bottom indicator (`--tabbar-underline`) and a stronger primary label: no selected fill, raised frame, top cue or rounded silhouette. Tabs are `shrink-0 whitespace-nowrap` (a flex child in `overflow-x-auto` otherwise wraps), the active tab scrolls into view on mount and resize, and the overflow fade (`--tabbar-edge-fade`) draws only on the side with hidden tabs.
- **Scrollers** paint no bar: `scrollbar-width: none` and `::-webkit-scrollbar { display: none }` on `html`, `body` and every descendant (both spellings: Safari and the macOS WebView ignore the standard one). A hidden bar removes the only "there is more" mark, so a scroller with no other cue pairs with a `--tabbar-edge-fade` mask. `.atlas-scroll-quiet` marks scrollers designed without one (`chat-scroller-quiet`). `scroll-behavior: smooth` is on `html` only, under `prefers-reduced-motion: no-preference`; on inner boxes it changes what `scrollTop = n` means.

## Chrome

- Chrome is made only with `ChromeTile` (square icon button) and `ChromeChip` (label button), plus `CHROME_STATUS_CHIP_CLASS` for non-button status chips, which share the chip's height, radius, border, surface and padding so siblings never disagree. A panel (INDEX, datasheet) is one radius step above. Never rebuild a 36px square or label button inline.
- Geometry comes from `--chrome-tile-size`, `--chrome-radius`, `--chrome-radius-inner`, `--map-panel-radius`, `--chrome-border`, `--chrome-surface`, `--chrome-shadow`. Outer left and right margins of topology chrome are `--chrome-inset`: INDEX, toolbar, rail and readout share one rail and one top line from `md` up (the seam beside the agent dock is the one exception).

## Motion

### Ramp and defaults

- `--motion-fast` (verification: a state that already happened, such as hover, focus, colour, tab content), `--motion-base` (a surface changing position), `--motion-settle` (a finished change). The ramp ends at 240ms; longer values are named exception tokens with a reason (`--agent-panel-reflow-duration`, `--overlay-spring-response`).
- `--motion-ease` is for every entry. `--motion-ease-exit` is for exits only, on the clock `calc(var(--motion-base) * 0.67)`: an exit on the entry curve is the entrance played backwards. It never appears in a `transition:` (a transition runs both ways); JavaScript reaches it only through `EXIT_TRANSITION` (`motion-token-mirror`). `--motion-ease-place` is for arrivals that are set down: transform only, on a figure with no type inside, never on a surface or anything carrying a sentence.
- Tailwind's default transition duration and easing are `--motion-fast` and `--motion-ease` (set in `@theme`): write no duration class when the default is meant, and specify `--motion-base` (with the reason) where a surface appears or disappears. Duration and easing move as one family.
- Entrance distance is a name: `OVERLAY_RISE` and `SHEET_RISE` in `src/shared/motion/tokens.ts` (`framer-entrance-grammar`). Camera and drag timings are canvas physics (`src/widgets/ontology-map/model/motion-physics.ts`); a DOM surface never references them.

### Allocation and swaps

1. **The protagonist moves first.** When one input changes several surfaces, the transition belongs to the attention winner; a hard-cut winner (first-frame delta share above 70%) over an easing background is inverted allocation. Both instant is fine.
2. **One input is one event.** Stages start in the same frame; a gap above `--motion-fast` reads as two events. Stagger only to show causality.
3. **Verdicts are measured in frames**, not screenshots; a design verdict names the winner's transition token.
4. **Frequency eats budget.** Hover and focus surfaces end by `--motion-fast`; movement and settling belong to events a few times a day.
5. **An exit plays under its own animation name**: a `reverse` on the same element does not restart and shows the end state instantly (`exit-motion-restart`). Opacity-only classes use `--motion-ease`, never a movement curve.
6. **A swap keeps both frames** (`usePanelPresence`, `useSurfaceSwap`, `useSwapHeight` in `src/shared/lib/use-presence.ts`): the departing surface stays for one shared `EXIT_WINDOW_MS`, inert and `pointer-events-none`, and a crossfade wraps reflow by measuring height just before replacement.
7. **Inline expansion is one surface with two states**: the header band is constant and the detail grows; open, close and content swap share one transition (height `--motion-base`, content `--motion-fast`: space first on open, text clears first on close). The closing detail is `inert`.

### Reduced motion

The OS preference is the only switch. The global kill rule (`animation-duration: 0.01ms !important`, inside `@layer base`) is the safety net for un-audited, decorative or infinite motion. Motion that is evidence of causality gets an equivalent, not a kill: crossfades reclaim their duration token, and appearances with transforms switch to the opacity-only `panelCrossfadeIn` keyframe; no new keyframe, no literal milliseconds. The surfaces that owe an equivalent are an enforced list (`reduced-motion-equivalent`), and an equivalent sits in the same cascade layer as the kill rule and later in source order (between important declarations layer order inverts, so one outside the layer loses). Springs do not travel and the light layer is never created. User-initiated movement (scroll, pan, pinch, wheel zoom) keeps its duration (WCAG 2.2 section 2.3.3); only app-initiated movement (ego dive, fit, auto-align) snaps.

### Motion primitives

Thirteen primitives; durations and easings come from `--motion-*`, `MOTION` and `STAGGER` only, and each CSS lives in its own `app/styles/motion-*.css` part inside `@layer base` with its reduced equivalent. Every use names what it explains: causality, identity, origin, state progression or order established once.

- **Shared-element morph** (`runMorph`; `view-transition-engine`), **staggered entrance** (`useStaggerOnce`: once per session per vault and list), **count-up** (`useCountUp`, aria-hidden beside an sr-only final value), **relation reveal** (source to target), **continuous state** (`WorkStatus`), **expand and collapse** (`RowDisclosure`; `details-adoption-ratchet`), **progress to done** (`WorkProgress`: `scaleX`, never width).
- **Press**: detached shapes, `Button`, `ChromeTile`, `ChromeChip` and the `Select` trigger travel `active:translate-y-px`; flush shapes (row, link, segment, card) press with a surface or ink step and no travel. **Hover** changes ink, surface or border, never position (`hover-presence-ratchet`). **Toggle and checkbox draw** (`DrawnCheck`). **Selection indicator** (`useSlidingIndicator`: one per group on the `control` spring; `tab-adoption-ratchet`). **Success and failure** (`useCopyFeedback`, `FeedbackGlyph`): a successful `reject_once` answer reads as done, never danger; only icon-only controls shake; every result is also announced in a `role="status"` region. **Direction**: pages crossfade with no travel; popovers grow from their trigger; docks share one reflow grammar (`agentDockReflowStyle()`); drawers slide from their edge; modals rise; each leaves the way it came.

### Signature motion

One spring, one light. Meaning travels along real connections, lit only while it happens, with weight that depends on structure.

1. Motion caused by a relation runs along that relation's own line, in its direction; nothing crosses empty space. Everything arrives from its origin and leaves toward it.
2. Only what is happening now glows, for as long as the act lasts. Nothing at rest glows or moves; one line carries one light.
3. Weight follows structure: every spatial move uses one house damping ratio; speed depends on scale (control, surface, canvas) and, on the map, on mass (a concept's degree). Heavy concepts arrive later, never bounce more.

Spending by event tier. 0, constant (hover, focus ring, typing, scroll): ink only, no travel, no light. 1, frequent (press, tab, route change, popover, row select): house springs for travel, no light. 2, an answered question (focus a concept, find a path, open detail, camera flight): spring travel plus one light event, ending by `CAMERA_TWEEN_MAX_MS` plus bloom decay. 3, rare (first open, a change lands, agent proposes or writes, commit, compile): full choreography, 1.2s, once per event, any input settles it.

- **Springs**: `SPRING` in `src/shared/motion/spring.ts` (`control`, `surface`, `canvas`; one `HOUSE_DAMPING_RATIO`); `springState` is the closed form, retargetable from current position and velocity. DOM consumers get `springEasing(spring)`, a CSS `linear()` generated at runtime: no static CSS spring token and no hand-typed `linear()`. A new specialisation (`OVERLAY_SPRING`, the map's interactive, mass, press and home springs, `--motion-ease-place`) needs a decision record. A spring moves position, size, rotation or scale; opacity, colour, blur and light intensity never overshoot and stay on the ramp.
- **Budgets**: at synth 2k no frame interval above 50ms on first open (`map-flat-dial-motion.spec.ts`), measured headed on the static export (`docs/engineering/motion-recording.md`); DOM springs animate `translate`, `scale` and `transform` only; at rest the map sleeps (zero frames).
- **Light** marks only the thing a hand or an agent is acting on, for as long as the act lasts, on the map's WebGL2 light layer and never on a mark with identity. It composites `plus-lighter` only there; everything else is `source-over` (`canvas-composite-license`). It reads `--map-light-*`, borrows `--map-indigo-bright`, adds no hue, draws in Flat for an event, and rides the front of the relation's reveal.

## Absolute rules (Don'ts)

This list is the single canonical source. `.claude/rules/forbidden.md` carries a resident subset and `.claude/rules/design.md` points here. Each item ends with a `dont:` key matched by slug in `tests/contract/design-donts-parity.contract.test.ts`: rewrite the sentence freely, never the key.

- Clicking a topology node opens a fullscreen or full-bleed detail modal. The default is ego focus plus a compact popover anchored to the node; full detail is opt-in from inside that popover. <!--dont:node-click-fullscreen-modal-->
- Floating-box soup: unrelated panels, popovers, HUD, minimap and cards at equal visual weight. <!--dont:floating-box-soup-->
- Stacked popovers, or a popover over a modal, without closing or dimming the previous surface. <!--dont:stacked-popover-->
- A blocking composer or modal without a dim, scrim or suppressed parent interaction. <!--dont:modal-without-dim-->
- A one-off topology `clamp(...)`, shadow, radius, z-order, easing or duration without a `--topology-*` token and verifier marker. <!--dont:oneoff-topology-value-->
- Overlap tolerated because the surface "mostly still works": the overlap count is zero for fixed and card surfaces in the tested state. <!--dont:overlap-tolerated-->
- Decorative arrows trailing a label (`Open →`, `Details →`, a trailing `ArrowRight` or `ArrowUpRight`). <!--dont:decorative-trailing-arrow-->
- Cards in one grid whose height is decided by how much text each contains. <!--dont:content-decided-card-height-->

Also held, with no resident key: tokenless visual values in JSX; touch-density chrome (48px and up) on desktop; a light panel slab on a dark canvas; `--map-*` referenced from a page outside topology; reviving the app-embedded terminal dock (`--terminal-*`, `docs/AGENT-GRAPH-WORKFLOW.md`); rarity glow, gems, loot and particles on decision surfaces. Every Don't holds app-wide.

### Arrows carry information or they don't ship

A trailing arrow after a link label adds nothing: the label already says where you go. Test: remove the arrow and read the label aloud; if nothing was lost, it was decoration. An arrow is allowed when it is the data: a path `{source} → {target}`, an ordering, a menu path `Settings → Developer`, cause and effect, a leading `↗` on a link that leaves the app, a chevron as disclosure state. `label-decoration` scans `messages/*.json` for a trailing arrow, a bare `↗` in JSX without `data-external-link-marker`, and a lone arrow element at the end of a label, matched by position (its next non-whitespace sibling is the parent's closing tag), never by glyph.

### Dimensional regularity

A container's dimensions are a design decision, not a byproduct of its contents. In a repeating set: fix the anatomy (the same named slots in the same order; an absent slot is worse than an empty one); reserve the space of an optional clause; truncate list slots to a fixed count with a remainder caption, never "however many fit"; equalize rows as well as columns when the set reads as one field; clamp long titles with the full value on hover, focus or in the detail. A one-off card sizes to its content.

### One text edge per column

Bare text, labels, headings, table labels and row text in one column start on one x. Backgrounds, borders and hover fills may extend past that edge (`-mx-*` paired with the matching `px-*`); text never steps in. A boxed control keeps its inner padding, so its box sits on the edge; cards in a list sit exactly on the column's box edge. A full-width `shape: "row"` emits `w-full`, so a bare `-mx-*` bleeds left only: split the column's inset between the list and the row.

**Control groups fill their column.** A row of controls that would wrap becomes a grid that fills the width: `grid grid-cols-2`, `w-full` on every control, `col-span-2` on the odd child, and a control whose label is a sentence takes the whole row. Inline rows that never wrap at their design width are left alone.

## System growth rules

How to extend the system, in order.

0. **Look for the existing value first**: the role's token (`pnpm design:tokens -- --prefix=<role>`), the ramp rules here, and `git log --oneline -S'<token>' -- app/globals.css app/styles` for why it is what it is. A value created without looking is a second system.
1. **Look at slots before adding axes.** Axes multiply (three axes, eight combinations); components add. If only the shell changes, an axis; if text, icon or badge changes, a part.
2. **Do not make two tags with the same appearance** (a byte-identical `<button>` and `<Link>`). One component replaces its underlying element; `asChild` is an escape hatch only where a duplicate would otherwise appear, and its child must spread all props, accept a ref and stay accessible, pinned by contract tests, or one side is removed.
3. **To change the specification, invoke the system.** Declare `design-contract` to `pnpm design:route` for the files `.claude/rules/design.md` lists; `pnpm decisions:check` requires a `docs/DECISIONS.md` record for a change that moves the spec, judged by census (`scripts/lib/design-spec-census.mjs`, `design-spec-ledger`), not by file name.
4. **Count how many are blocked.** A new shape, tone or axis comes with the number of controls it would leave outside the system; uncounted, it is a preference.
5. **A rule and its gate land in the same pull request.** Count violations before enabling a gate (`/gate-probe`) and plant a flaw that turns it red.
6. **Changing a library is a last resort**: a new dependency needs its reason in the pull request, and replacing `cva` needs evidence that slots cannot be done with it.
