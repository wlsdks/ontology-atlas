# 가이드

Ontology Atlas 를 처음 여는 사람을 위한 안내입니다. 읽는 순서대로 따라오면
폴더 하나가 지도가 되고, 그 지도를 AI 에이전트가 읽게 됩니다.

> 이 문서 자체가 Atlas 볼트 안의 마크다운 한 장입니다. 지금 보고 계신 화면은
> 그 파일을 그린 것이고, 같은 파일을 앱에서 열 수도 에이전트가 MCP 로 읽을
> 수도 있습니다. 제품이 자기 형식으로 자기를 설명하는 셈입니다.

## 1. 이게 무엇인가

**코드는 남고 맥락은 사라집니다.** 왜 이렇게 만들었는지, 여길 건드리면 어디가
흔들리는지 — 그 지식은 보통 사람 머릿속과 흘러간 대화 속에 있습니다. grep 은
코드를 찾아주지만 *왜* 는 찾아주지 못합니다.

Atlas 는 그 **의미 층**을 마크다운 폴더 하나에 붙잡아 둡니다. 파일의
frontmatter 가 곧 노드이고 관계입니다. 별도 데이터베이스도, 로그인도, 서버도
없습니다.

읽는 사람이 둘입니다.

- **사람** — 지도를 보고 판단합니다. 기획자·마케터·의사결정자·개발자가 같은
  그림을 봅니다.
- **AI 에이전트** — 같은 파일을 MCP 로 읽고 씁니다. 작업 시작점, 도메인 맥락,
  구현 증거, 영향 범위, 검증 경로를 여기서 가져갑니다.

한쪽만 읽는 문서는 썩습니다. 위키는 사람만 읽어서 낡고, 에이전트 전용 메모리는
사람이 심판할 수 없어서 믿을 수 없게 됩니다. Atlas 는 **둘이 같이 기르는 한 층**
입니다.

## 2. 첫 5분

### 설치 없이 먼저 보기

브라우저에서 바로 열 수 있습니다. 마크다운 폴더를 고르면 그 자리에서 지도가
됩니다. 폴더는 브라우저 밖으로 나가지 않습니다.

파일 시스템 접근이 필요해서 **Chrome · Edge · Safari 18.2+ · Opera** 에서
동작합니다. Firefox 는 아직 이 API 가 없어 폴더를 열지 못합니다.

### 앱으로 쓰기

macOS 앱이 볼트의 본거지입니다. 브라우저가 원리적으로 할 수 없는 일들이 앱에만
있습니다.

- 볼트의 **절대 경로** — 에이전트 설정 파일에 실제 경로를 써 줄 수 있습니다
- **git** 기록 읽기와 스냅샷
- **키체인** — API 키를 브라우저 저장소가 아닌 OS 금고에 둡니다
- **폴더 감시** — OS 파일워처로 0.5초 안팎에 반영됩니다 (웹은 폴링이라 1.5~5초)
- **MCP 서버 동봉** — 앱을 설치하면 에이전트 표면도 같이 설치됩니다

앱이 처음 묻는 것은 폴더 하나입니다.

## 3. 볼트의 구조

볼트는 그냥 마크다운 폴더입니다. 특별한 것은 각 파일 맨 위의 frontmatter 뿐입니다.

```markdown
---
kind: capability
slug: token-issue
title: 토큰 발급
domain: auth
---

# 토큰 발급

로그인에 성공한 사용자에게 세션 토큰을 내준다.
```

`kind` 가 그 파일이 무엇인지 정합니다.

| kind | 뜻 | 예 |
|---|---|---|
| `project` | 최상위 산출물 | `auth-platform` |
| `domain` | 기능 묶음 | `auth`, `billing` |
| `capability` | 하나의 일관된 행동 | `token-issue` |
| `element` | 구체적인 조각 (파일·라이브러리·스키마) | `jwt-signer.ts` |
| `document` | 그래프에 매인 설명 문서 | 이 가이드 |

관계는 `contains` · `depends_on` · `broader` 같은 키로 씁니다. **프로젝트 소속은
따로 적지 않습니다** — `contains` 사슬을 타고 자동으로 정해집니다. `domain: auth`
라고만 써 두면 그 위의 프로젝트까지 알아서 이어집니다.

frontmatter 가 진실원입니다. 별도 승인 절차도, 동기화 버튼도 없습니다. 파일을
고치면 그게 곧 그래프입니다.

## 4. AI 에이전트 연결하기

앱의 **「에이전트 연결」** 버튼 한 번이면 됩니다. 지금 쓰는 도구를 고르면 그
도구의 설정 파일에 **볼트의 실제 절대 경로**가 박힌 한 줄을 써 줍니다.

지원 도구: **Claude Code · Codex · Cursor · Antigravity**

연결되면 에이전트가 이런 일을 합니다.

- **작업 시작 전** — `get_concept` 으로 건드릴 개념과 이웃을 먼저 읽습니다.
  `find_backlinks` 로 이름을 바꾸기 전에 누가 기대고 있는지 봅니다.
- **작업 후** — 새로 생긴 capability 나 element 를 `add_concept` 으로 남깁니다.
  이름이 바뀌었으면 `rename_concept` 이 백링크를 전부 다시 씁니다.

읽기 19개 · 쓰기 13개, 도구 32개가 있습니다. 사람이 쓰는 CLI 는 52개 명령을
가집니다 — 볼트 만들기부터 그래프 컴파일, 경로 열거, 영향 반경, 순환 탐지까지.

**중요한 것은 에이전트가 쓴 것도 그냥 마크다운이라는 점입니다.** `git diff` 로
보이고, 마음에 안 들면 손으로 고치면 됩니다. 사람이 의미의 심판입니다.

## 5. 어디에 두는가

볼트는 여러분 디스크의 폴더 하나입니다. 보통은 다루는 저장소 안에 둡니다 —
그러면 코드와 의미가 같은 커밋에 실려 같이 리뷰됩니다.

```
your-repo/
├── src/
└── docs/ontology/     ← 볼트
    ├── project.md
    ├── domains/
    ├── capabilities/
    └── elements/
```

이 저장소도 그렇게 합니다. `docs/ontology/` 에 자기 자신을 98개 노드로
적어 두고 있고, 그 파일들로 이 제품을 만듭니다.

## 6. 신뢰에 관하여

- **로컬이 전부입니다.** 볼트는 여러분 디스크에만 있습니다. 조용히 전송되는
  것은 없습니다.
- **평문 마크다운입니다.** 앱을 지워도 폴더는 그대로 남습니다. 잠기는 것이
  없습니다.
- **로그인이 없습니다.** 계정도, 서버도, 요금제 뒤에 갇힌 기능도 없습니다.
- **LLM 연결은 선택입니다.** 켜지 않으면 어떤 모델도 호출되지 않고, 켜면 무엇이
  나갔는지 볼트 안 감사 로그에 남습니다.
