# MCP differential harness

Sends two MCP servers the same corpus of JSON-RPC requests over stdio and compares everything an agent
or a vault could notice. It exists so the Rust port of `mcp/src` can be proven equal to the JavaScript
server one slice at a time (`docs/specs/2026-11-27-mcp-server-in-rust.md`). The corpus is
`tests/differential/corpus/<family>/<case>.jsonl`; it is generated by `write-corpus.mjs` from
`corpus-definitions.mjs`, so edit the definition and run `pnpm mcp:differential:check` after.

## What is compared

For each case, in a folder the harness makes for that run:

- every answer, as the raw line the server wrote: key order, number text (`1.0` is not `1`), string
  escapes, whitespace and the envelope (`jsonrpc`, `id` as written, `result` xor `error`). If the lines
  differ, the answers are also compared as trees to name the first differing path;
- every other line the server wrote on stdout, a last line with no newline, and bytes that are not UTF-8;
- stderr, the exit code or signal, and a missing answer (the step waits `timeoutMs`);
- the case folder, the home folder and the worker folder: kind, permission bits, bytes, symlink target,
  and for a file the harness planted whether it still has its planted time. A write outside the case
  folder fails the run;
- the repository state (`HEAD` and `git status`) when the vault is inside a repository;
- the file times an answer reports (`mtime`, `mtimeMs`, `newMtime`, `intoMtime`, `mtimes`) must equal
  the named file's real time. The times of files the server itself wrote are masked in both runs and
  never compared across runs; they are checked against the file instead.

## Pinned inputs

A program under test must receive the same two inputs from the harness:

| Input | Variable | Value |
|---|---|---|
| Clock | `ATLAS_DIFF_CLOCK_MS` | epoch milliseconds returned by every "now" (`Date.now()`, `new Date()`). Default `1_790_000_000_000` (2026-09-21T14:13:20Z); the `-late-clock` twin of a `vault-read` or `writes` case sets `4_102_444_800_000` (year 2100) so the document cache sees files older than its two-second window |
| UUIDs | `ATLAS_DIFF_UID_SEED` | `differential` |

Both are honoured only when set. A UUID is not random: draw number `i` of stream `name` is the SHA-256 of
`<seed>\0<name>\0<i>` (decimal `i`), the first 16 bytes with the version nibble set to 4 and the variant
bits to `10`, written as 8-4-4-4-12 lowercase hexadecimal. Streams are separate counters so a draw for a
temporary file name cannot shift the UIDs minted for concepts:

| Stream | Used by |
|---|---|
| `schema` | node UIDs (the module `schema.mjs`) |
| `map-analysis-log` | session ids (the module `map-analysis-log.mjs`) |
| `other` | every other draw |

The JavaScript server gets both through `tests/differential/support/deterministic-preload.mjs`
(`node --import`); the Bun twin compiles them in; the Rust program reads the same two variables behind a
cargo feature the release build lacks.

The rest of a server's environment is explicit: `PATH`, `HOME` and `TMPDIR` (and on Windows
`USERPROFILE`, `TEMP`, `TMP`, `SystemRoot`, `COMSPEC`, `PATHEXT`) point into a per-run folder, `TZ=UTC`,
`LANG` is `en_US.UTF-8` (`ko_KR.UTF-8` for the first side of `--ko-vs-en`), git is configured to run no
user hooks, and `OATLAS_VAULT` names the vault.

## Modes

```text
pnpm mcp:differential -- [--family=<name>] [--case=<name>] [--concurrency=<n>] [--base-ref=<ref>]
  --a=node --b=node               control run: must be equal
  --a=node --b=bun                Node against the pinned Bun's build of the same source
  --a=bun  --b=bun-shipped        the twin against the shipped binary (see below)
  --a=node --b=rust               the port (ATLAS_MCP_RUST names the program)
  --a=node --b=cmd:<command>      any program that speaks the protocol
  --ko-vs-en                      one server under two locales
  --coverage [--write-manifest] [--enforce] [--report=<file>]
  --drift --days=14               the tree as it was 14 days ago against this one
  --goldens[=write] [--goldens-dir=<folder>]
  --record-expected=<file>        write every difference found as known-difference entries
  --corpus-dir=<folder>           replay another corpus
```

- The Bun twin refuses to build with a Bun that is not the version in `.bun-version`; point
  `ATLAS_DIFF_BUN` at a pinned executable.
- `bun-shipped` cannot take the two pinned inputs. Each case runs twice on it; a case whose two runs
  differ (its answers show the clock or a UID) is skipped and named in the output, and the rest are
  compared. Build the binary first with `pnpm mcp:build-binary`.
- `--coverage` runs the whole corpus on Node under V8 coverage and reports, per family, how much of the
  family's own files ran, and per tool which functions its calls executed. A file no case loaded counts
  as one unrun function. `--write-manifest` rewrites `tests/differential/tool-functions.json` and
  `unrun-functions.json` (existing reasons are kept; new entries say `unreviewed`).
- `--goldens` freezes the answers of the chosen server to `tests/differential/goldens/` (35 MB for the
  current corpus, so it is not committed yet; writing it takes about a minute) so they can be checked after the JavaScript server
  is gone. A golden holds no path, time or hash that depends on where it was made.

## What may differ

Nothing, except what a committed list names:

- `tests/differential/manifest.json` `equalExcept`: per family, rules `{ tool, path }` for a field the
  family's tools may differ in while something they call is not ported. A rule names one tool and a path
  inside `result` of at least three segments; a whole result, the envelope and an error are never
  excepted. The list may only shrink: `equal-except-ceiling.json` bounds it, and `checkManifest`
  compares both with `--base-ref` (default `origin/main`; an empty value skips that comparison).
- `expect-locale-diff.json` and `node-vs-bun-differences.json`: one entry `{ case, where, id?, path }`
  per request or path, with the reason. A run fails when an entry no longer differs, and neither list
  may grow against the base ref.
- `declared-changes.json`, read by `--a=node --b=rust`: the same entries, each also naming the row of
  the specification's table of declared changes (`change`) and a reason. A run fails when an entry no
  longer differs, and an entry without a row and a reason is refused. An entry with `platform`
  (`process.platform`, such as `win32`) is looked for on that platform only. It grows with the table, so the
  base-ref check skips it. A difference is reported once per request (the first differing path), so an
  entry hides the rest of that request's answer; the Rust program's own tests state each declared
  answer in full.

## Corpus steps

A case file starts with a header line (`case`, `vault` fixture name, optional `env`, `clockMs`,
`snapshot`, `mustNotExist`, `folder: "invariants"`), then one step per line: a JSON-RPC request (with
optional `timeoutMs`, `settleMs`, `noWait`), a `{"raw": "..."}` line, a notification (`notify`), or a
directive `{"$": ...}`: `await`, `wait`, `touch`, `write-file`, `mkdir`, `remove`, `symlink`, `chmod`,
`git` (`args`: one `git` run in the folder that holds the vault, hardened as the harness reads the
repository), `close-stdin`, `close-stdout`, `kill`, `kill-after-first-write`.

Strings in a request may hold `$VAULT`, `$PARENT`; a whole value may be `$MTIME(<path>)` (the planted
time of a file the server has not written) or `$ANSWER(<request id>, <path>)` (a value out of an
earlier answer, path from the response root, so a client sends back what the server reported).

## The planted-difference test

`pnpm test:mcp:differential` runs the harness against the JavaScript server behind a proxy
(`tests/differential/support/planted-difference-server.mjs`) that plants one difference of each kind in
turn and fails unless the harness exits 1 naming it. A harness that cannot see a difference proves
nothing.
