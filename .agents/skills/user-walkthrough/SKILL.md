# /user-walkthrough — 과업 하나를 처음부터 끝까지 걷는다

화면 단위 심사는 이미 여럿이 한다. 아무도 **여정 전체**를 걷지 않는다. 이 제품이
스스로 세운 북극성 — *링크 → 설치 → 에이전트가 내 vault 노드를 인용, 5분 이내* —
은 연속된 경험인데, 그걸 연속으로 검증하는 장치가 없었다.

## 이 스킬의 사거리 — 어디까지 판정하고 어디서 멈추는가

판별 기준은 하나다: **답이 만든 물건 안에 있는가, 사람 안에 있는가.**

**물건 안에 있다 → 사람급으로 판정한다. 봐주지 않는다.**
이 라벨이 이 사람의 어휘인가 · 이 단계에서 다음에 뭘 할지 알 수 있는가 · 누를 수
있다는 게 보이는가 · 눌렀다는 게 보이는가 · 무엇이 무섭게 생겼는가(되돌릴 수 없어
보이는 버튼) · 어디가 싸구려로 읽히는가 · 무엇이 빠졌는가 · 어디서 기다리는지
모른 채 기다리는가. **이건 전부 물건을 가리켜 증명할 수 있다** — "이 라벨이
자기가 하는 일을 말하지 않는다"는 라벨을 인용하면 끝난다.

**사람 안에 있다 → 주장하지 않는다.**
이 사람이 이걸 *원할지* · 다시 올지 · 추천할지 · 돈을 낼지. 그건 물건의 속성이
아니라 사람의 사실이고, **관측된 적 없는 것을 관측된 것처럼 쓰는 순간 이 출력은
근거가 아니라 창작이 된다.** 시뮬레이션 사용자는 보정 불가능한 방향으로 어긋난다는
실증이 있다(어려운 과제 과소평가 · 중간 과제 과대평가 · 사람과 *다른* 실패 패턴
지목). 마찰 0 은 **"걸리지 않았다"** 이지 **"좋아한다"** 가 아니다.

욕망의 증거는 여전히 실제 사람에게서만 온다 — 설치 수 · 재방문 · 처음 보는 3인의
실물 반응. 이 스킬은 그 자리를 대신하지 않고, 그 사람들이 **걸려 넘어질 지점을
미리 치운다.**

## 이 스킬의 진짜 능력 — 패턴 인식이다

사용자가 **될** 필요는 없다. 패턴을 **알아보면** 된다. 그게 이 판정의 근거이고,
동시에 규율이다.

- **"이 사람은 답답함을 느낄 것"** → 창작이다. 반박할 수 없고 확인할 수도 없다.
- **"이건 막다른 CTA 다 — 누르면 빈 페이지로 간다"** → 패턴이다. 이름이 있고,
  물건을 가리켜 증명되고, 틀렸으면 틀렸다고 말할 수 있다.

**그래서 모든 지적은 패턴 이름을 단다.** 이름을 못 대면 그건 직감이고, 직감은
이 출력에 들어가지 않는다. 자주 나오는 것들:

| 패턴 | 무엇인가 |
|---|---|
| 막다른 CTA | 가장 강한 컨트롤이 아무것도 없는 곳으로 보낸다 |
| 기제 라벨 | 라벨이 결과가 아니라 내부 동작을 말한다("vault 인덱싱" vs "내 문서 읽기") |
| 가치 앞의 관문 | 무엇이 좋은지 보여주기 전에 무언가를 요구한다 |
| 조용한 기다림 | 진행 중인데 진행 표시가 없다 |
| 되돌리기 불명 | 파괴적으로 보이는 행동에 취소가 안 보인다 |
| 내부 언어 누출 | 만든 쪽의 어휘가 사용자 화면에 그대로 있다 |
| 유령 다음 단계 | 방금 한 일 다음에 무엇을 할지 화면이 말하지 않는다 |

이 표는 닫힌 목록이 아니다 — 새 패턴을 봤으면 **이름을 붙이고 무엇이 그 패턴인지
한 줄로 정의해서** 보고한다. 이름 붙은 패턴은 다음 워크스루가 재사용하고,
`docs/DECISIONS.md` 에서 반복되면 헌장 조항 후보가 된다.

## 걷는 이를 만드는 법

**지식 상태 + 맥락 + 무엇을 신경 쓰는가.** 이 셋이 페르소나다. 인구통계와 감정
서사("민지, 32세, 좌절감을 느낀다")는 만들지 않는다 — 판정을 바꾸지 않으면서
지어낸 것처럼 읽힌다.

기본 프로필 (`docs/PRODUCT-PLAN-2026-07.md` 의 대상):

```
아는 것: Claude Code 를 매일 쓴다. CLAUDE.md 를 직접 관리한다. 마크다운과 git 은
        편하다. 그래프 DB 는 안 써봤다.
모르는 것: Atlas 를 본 적 없다. "온톨로지"를 제품 용어로 들어본 적 없다.
맥락: 2~10인 팀 테크리드. 지금 다른 일을 하다 링크를 받았다. 10분 뒤 회의가 있다.
신경 쓰는 것: 에이전트가 매 세션 맥락을 잃는 것. 설치한 것이 자기 디스크를
        건드리는 것. 나중에 빠져나올 수 있는가.
```

**무지는 연기가 아니라 구조로 만든다.** 걷는 이는 **저장소 컨텍스트가 없는 새
에이전트**로 띄운다. 브리프는 위 프로필 + 과업 한 문장 + 시작 URL 뿐이다 —
코드도, 문서도, 이 스킬의 내용도 주지 않는다. 아는 상태로 모르는 척하면 아는
사람의 경로를 걷게 된다.

**걷는 이는 판정하지 않는다.** 각 단계에서 *무엇이 보였고 · 무엇을 눌렀고 · 왜
그랬고 · 무엇을 기대했고 · 실제로 뭐가 일어났는지*만 기록한다. 판정은 소집한
쪽이 그 로그에 아래 네 질문을 적용해서 한다.

## 네 질문 (각 단계마다)

1. **목표** — 이 단계에서 무엇을 하려는지 알 수 있었는가?
2. **발견** — 그걸 하는 컨트롤이 보였는가?
3. **연결** — 그 컨트롤이 자기가 할 일을 이 사람 어휘로 말했는가?
4. **확인** — 누른 뒤 진전이 보였는가?

실패는 **단계에 위치시킨다**: `[단계 N · 화면 · 실패한 질문 · 걸린 시간 · 증거]`.

## 두 여정

**A. 에이전트 여정 — 이건 시뮬레이션이 아니라 실측이다.**
이 제품 사용자의 절반은 코딩 에이전트다. Atlas MCP 만 연결한 plain Claude Code
세션에 북극성 과업을 시킨다: *"이 저장소의 구조를 vault 노드를 인용해 설명해라."*
링크 도달부터 첫 정확 인용까지 시간을 잰다. **대상 인구가 실제 사용자이므로 이건
진짜 사용자 검증이다** — 이 스킬에서 유일하게 그렇다.

**B. 사람 여정 — 검사법.** 위 프로필로 걷는 이를 띄우고, 실제 빌드에서 과업을
끝까지 걷게 한다. 빌드는 실행 중이어야 한다(정적 export 를 띄우거나 설치 앱).

## 결과가 가는 곳

- 마찰 목록 → `/po-pass` · `po-evidence` 에 **dogfood 실패 관측**으로 전달한다.
  이건 Discovery Lead 증거 목록의 1급 항목이다.
- 위계/상호작용에 강등·라벨·상태 재료로 전달한다.
- **이 출력만으로 `Build and verify` 를 정당화하지 않는다.** 마찰이 0이어도 그건
  "걸리지 않았다"까지다.

## 출력 형식

```md
## 사용자 워크스루 — <과업>

**걷는 이**: [지식 상태 · 맥락 · 신경 쓰는 것] · **컨텍스트 격리**: [확인]
**여정**: A 에이전트 실측 / B 사람 워크스루 / 둘 다
**빌드**: [URL 또는 설치 앱 · 커밋]

**북극성 시간**: [링크 → 첫 정확 인용까지 N분 — 목표 5분] (여정 A 일 때)

| 단계 | 화면 | 실패 질문 | 걸린 시간 | 증거 |
|---|---|---|---|---|
| … | … | 목표/발견/연결/확인 | … | 스크린샷·로그 |

**막힌 지점** (심각도 순): […]
**빠져나간 지점**: [걷는 이가 과업을 포기했다면 어디서, 무엇 때문에]
**물건이 말하지 않은 것**: [사람 어휘가 아닌 라벨 · 없는 다음 단계 · 안 보이는 상태]

**주장하지 않은 것**: 이 사람이 이걸 원할지 · 다시 올지 — 그건 실제 사람에게서만
온다. 이 워크스루는 그 사람들이 걸려 넘어질 지점을 치웠을 뿐이다.
```
